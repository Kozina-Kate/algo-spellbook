## Строка в JavaScript

**Строка неизменяема (immutable).** Любая операция «изменения» создаёт новую строку, а старая остаётся нетронутой.

```js
let s = 'hello';
s[0] = 'H';     // молча не сработает, ошибки не будет
console.log(s); // 'hello'
```

Отсюда следует главное практическое правило:

:::caution
**Конкатенация в цикле — это O(n²).**

```js
// ПЛОХО: каждая итерация создаёт новую строку и копирует всё накопленное
let result = '';
for (const ch of chars) {
  result += ch;
}

// ХОРОШО: собираем в массив, склеиваем один раз — O(n)
const parts = [];
for (const ch of chars) {
  parts.push(ch);
}
const result = parts.join('');
```

На современных движках есть оптимизация конкатенации (rope-структуры), но на собеседовании правильный ответ — «собираю в массив и делаю join».

:::
## Кодировка: что нужно знать

Строки в JS хранятся в UTF-16. Символ индексируется как **кодовая единица** (16 бит), а не как «буква».

Для латиницы, кириллицы и цифр это одно и то же — каждый символ занимает одну единицу. Но эмодзи и редкие иероглифы занимают **две** единицы (суррогатную пару):

```js
'привет'.length;   // 6 — всё ожидаемо
'😀'.length;        // 2 — не 1!
'😀'[0];            // половинка суррогатной пары, нечитаемый символ
[...'😀'].length;   // 1 — спред идёт по кодовым ТОЧКАМ, а не единицам
```

**Практический вывод для собеседования:** если в условии не оговорено иное, считайте, что строки состоят из ASCII или кириллицы, и работайте по индексам. Но упомянуть вслух «если возможны эмодзи, я бы перебирал через `for...of` или спред» — большой плюс, это показывает знание реальных граблей.

`for (const ch of s)` и `[...s]` итерируют по кодовым точкам и корректно обрабатывают суррогатные пары. Обычный `for` по индексам — нет.

## Работа с кодами символов

```js
'a'.charCodeAt(0);         // 97
'z'.charCodeAt(0);         // 122
'A'.charCodeAt(0);         // 65
'0'.charCodeAt(0);         // 48
String.fromCharCode(98);   // 'b'
```

**`charCodeAt(i)`** — числовой код символа в позиции `i`. **`String.fromCharCode(code)`** — обратное преобразование.

Главная идиома — превратить букву в индекс массива:

```js
const idx = ch.charCodeAt(0) - 'a'.charCodeAt(0);   // 'a' → 0, 'b' → 1, ... 'z' → 25
```

Так делают частотный массив из 26 ячеек. Он быстрее `Map` по константе и позволяет сказать «память O(1), потому что алфавит фиксирован».

## Задача 1. Валидная анаграмма

**Условие.** Являются ли две строки анаграммами (перестановками друг друга)?

Пример: `'anagram'` и `'nagaram'` → `true`. `'rat'` и `'car'` → `false`.

### Решение через сортировку

```js
function isAnagramSort(s, t) {
  if (s.length !== t.length) return false;   // быстрая отсечка
  // split('') → массив символов, sort() → лексикографический порядок,
  // join('') → обратно в строку. Анаграммы дают одинаковый результат
  return s.split('').sort().join('') === t.split('').sort().join('');
}
// Время O(n log n), память O(n)
```

### Решение через счётчик — O(n)

```js
/**
 * Являются ли строки анаграммами. Только строчные латинские буквы.
 * @param {string} s
 * @param {string} t
 * @returns {boolean}
 */
function isAnagram(s, t) {
  // Разная длина — точно не анаграммы. Проверяем первым делом
  if (s.length !== t.length) return false;

  const A_CODE = 'a'.charCodeAt(0);
  const counts = new Array(26).fill(0);

  // Один проход по обеим строкам: для s прибавляем, для t вычитаем.
  // Длины равны, поэтому один цикл покрывает обе строки
  for (let i = 0; i < s.length; i++) {
    counts[s.charCodeAt(i) - A_CODE]++;
    counts[t.charCodeAt(i) - A_CODE]--;
  }

  // Если строки — анаграммы, все счётчики обнулятся
  return counts.every(c => c === 0);
}
```

### Разбор функций

- **`Array.prototype.every(fn)`** — возвращает `true`, если `fn` вернула истину для **всех** элементов. Останавливается на первом `false`. Парная ей `some(fn)` — истина, если хотя бы для одного.
- **Приём «прибавляем за одну строку, вычитаем за другую»** — избавляет от второго массива и второго прохода сравнения. Стоит запомнить.

**Универсальная версия через `Map`** — если алфавит не ограничен:

```js
function isAnagramMap(s, t) {
  if (s.length !== t.length) return false;

  const counts = new Map();

  for (const ch of s) {
    counts.set(ch, (counts.get(ch) || 0) + 1);
  }

  for (const ch of t) {
    const c = counts.get(ch);
    // Символа нет вообще или его запас исчерпан — не анаграмма
    if (c === undefined || c === 0) return false;
    counts.set(ch, c - 1);
  }

  return true;
}
```

Здесь проверка `c === undefined || c === 0` — важная деталь: `if (!c)` сработала бы так же, но при отрицательных значениях повела бы себя иначе; явная проверка надёжнее.

**Сложность:** время **O(n)**, память **O(1)** для версии с 26 ячейками, **O(k)** для `Map`.

## Задача 2. Палиндромы

**Палиндром** — строка, читающаяся одинаково в обе стороны.

Проверка палиндрома двумя указателями разобрана на странице [Два указателя](../dva-ukazatelja/). Здесь — более интересная задача.

### Самая длинная палиндромная подстрока

**Условие.** Найти самую длинную подстроку, являющуюся палиндромом.

Пример: `'babad'` → `'bab'` (или `'aba'`).

#### Ход мысли

Наивно — перебрать все подстроки и проверить каждую: O(n³). Слишком медленно.

Приём — **расширение от центра**. Любой палиндром симметричен относительно своего центра. Центров всего `2n - 1`: n «символьных» (для палиндромов нечётной длины, вроде `aba`) и n−1 «межсимвольных» (для чётной длины, вроде `abba`).

Для каждого центра расходимся в обе стороны, пока символы совпадают. Это O(n) на центр, итого O(n²) — приемлемо.

#### Решение

```js
/**
 * Самая длинная палиндромная подстрока.
 * @param {string} s
 * @returns {string}
 */
function longestPalindrome(s) {
  if (s.length < 2) return s;   // пустая строка и один символ — палиндромы

  let bestStart = 0;
  let bestLength = 1;

  /**
   * Расширяется от центра (left, right) наружу, пока символы совпадают,
   * и обновляет глобальный рекорд.
   * @param {number} left — левая граница центра
   * @param {number} right — правая граница центра
   */
  function expandFromCenter(left, right) {
    // Расходимся, пока не вышли за границы и символы равны
    while (left >= 0 && right < s.length && s[left] === s[right]) {
      left--;
      right++;
    }

    // Цикл вышел, когда условие НАРУШИЛОСЬ, значит последний
    // валидный палиндром — это (left + 1 .. right - 1).
    // Его длина: (right - 1) - (left + 1) + 1 = right - left - 1
    const length = right - left - 1;

    if (length > bestLength) {
      bestLength = length;
      bestStart = left + 1;
    }
  }

  for (let i = 0; i < s.length; i++) {
    expandFromCenter(i, i);       // нечётный палиндром: центр — символ i
    expandFromCenter(i, i + 1);   // чётный: центр между i и i+1
  }

  // slice(start, end) — подстрока, end не включается
  return s.slice(bestStart, bestStart + bestLength);
}
```

#### Разбор

- **Вложенная функция `expandFromCenter`** — объявлена внутри и через **замыкание** видит `s`, `bestStart`, `bestLength`. Замыкание — способность функции обращаться к переменным окружающей области видимости; благодаря ему не нужно передавать состояние параметрами.
- **`right - left - 1`** — длина палиндрома после выхода из цикла. Это место, где легко ошибиться. Проверьте руками на `'aba'` с центром `i = 1`: цикл закончится при `left = -1`, `right = 3`, длина `3 - (-1) - 1 = 3`. Верно.
- **`expandFromCenter(i, i + 1)`** — если `s[i] !== s[i+1]`, цикл не выполнится ни разу, длина получится `0`, рекорд не обновится. Корректно и без дополнительных проверок.
- **`s.slice(start, end)`** — подстрока от `start` до `end` не включая.

#### Сложность

Время **O(n²)**, память **O(1)**. Существует алгоритм Манакера за O(n), но на собеседовании достаточно упомянуть его существование.

## Задача 3. Сжатие строки

**Условие.** Сжать строку, заменяя серии одинаковых символов на «символ + количество». Если сжатая версия не короче исходной — вернуть исходную.

Пример: `'aabcccccaaa'` → `'a2b1c5a3'`. `'abc'` → `'abc'` (сжатие длиннее).

### Решение

```js
/**
 * Простое сжатие серий одинаковых символов.
 * @param {string} s
 * @returns {string} сжатая строка или исходная, если сжатие не выгодно
 */
function compressString(s) {
  if (s.length === 0) return s;

  const parts = [];   // собираем в массив, а не через += — см. правило выше
  let count = 1;

  for (let i = 1; i <= s.length; i++) {
    // i === s.length — искусственный «конец строки»:
    // он заставляет записать последнюю серию.
    // Без него хвост потерялся бы — классическая ошибка
    if (i < s.length && s[i] === s[i - 1]) {
      count++;
    } else {
      parts.push(s[i - 1]);        // символ серии
      parts.push(String(count));   // его количество
      count = 1;                   // начинаем новую серию
    }
  }

  const compressed = parts.join('');

  // Возвращаем то, что короче
  return compressed.length < s.length ? compressed : s;
}
```

### Разбор

- **`i <= s.length`** — цикл намеренно делает один «лишний» шаг, чтобы закрыть последнюю серию. Приём «виртуальный элемент за концом» часто выручает в задачах на группировку подряд идущих элементов.
- **`String(count)`** — явное преобразование числа в строку. Можно и `count.toString()`; `String()` безопаснее, потому что работает с `null` и `undefined`.
- **Тернарный оператор в `return`** — компактная проверка выгодности сжатия.

**Сложность:** время **O(n)**, память **O(n)**.

## Задача 4. Поиск подстроки

**Условие.** Найти индекс первого вхождения `needle` в `haystack`, или −1.

### Наивное решение

```js
/**
 * Индекс первого вхождения needle в haystack.
 * @param {string} haystack — где ищем
 * @param {string} needle — что ищем
 * @returns {number} индекс или -1
 */
function strStr(haystack, needle) {
  if (needle.length === 0) return 0;   // пустая строка есть в начале любой
  if (needle.length > haystack.length) return -1;

  // Идём до последней позиции, где needle ещё помещается целиком
  for (let i = 0; i <= haystack.length - needle.length; i++) {
    let j = 0;
    // Сравниваем посимвольно, пока совпадает
    while (j < needle.length && haystack[i + j] === needle[j]) {
      j++;
    }
    // Дошли до конца needle — значит совпало целиком
    if (j === needle.length) return i;
  }

  return -1;
}
```

**Сложность:** время **O(n · m)** в худшем случае, память **O(1)**.

**Что сказать про оптимизацию.** Существует алгоритм Кнута — Морриса — Пратта (KMP) за O(n + m). Он строит префикс-функцию, которая при несовпадении позволяет сдвинуть шаблон не на один символ, а сразу на столько, сколько допускает уже совпавшая часть. Писать KMP на собеседовании обычно не требуют, но знать про его существование и идею — ожидаемо.

В реальном коде, конечно, `haystack.indexOf(needle)`.

## Задача 5. Разбор строки на слова

Задачи вроде «перевернуть слова в строке» проверяют аккуратность с разделителями.

```js
/**
 * Переворачивает порядок слов, схлопывая лишние пробелы.
 * @param {string} s
 * @returns {string}
 */
function reverseWords(s) {
  return s
    .trim()            // убрать пробелы по краям
    .split(/\s+/)      // разбить по одному или нескольким пробельным символам
    .reverse()         // развернуть массив слов НА МЕСТЕ
    .join(' ');        // склеить через один пробел
}

reverseWords('  the   sky  is blue  ');   // 'blue is sky the'
```

### Разбор функций

- **`trim()`** — новая строка без пробельных символов в начале и конце.
- **`split(/\s+/)`** — разбиение по регулярному выражению. `\s` — любой пробельный символ (пробел, таб, перевод строки), `+` — один или более. Обычный `split(' ')` дал бы пустые строки между подряд идущими пробелами.
- **`reverse()`** — разворот массива **на месте**, возвращает тот же массив.
- **`join(' ')`** — склейка через пробел.

Время **O(n)**, память **O(n)**.

Версию «за O(1) памяти» на JS написать нельзя из-за неизменяемости строк — это стоит сказать вслух: «в языке с изменяемыми строками я бы развернула всю строку, а потом каждое слово по отдельности».

## Задача 6. Изоморфные строки

**Условие.** Строки изоморфны, если существует взаимно однозначное соответствие символов, переводящее одну в другую.

Пример: `'egg'` и `'add'` → `true` (e→a, g→d). `'foo'` и `'bar'` → `false` (o должно быть и a, и r).

### Решение

```js
/**
 * Изоморфны ли строки.
 * @param {string} s
 * @param {string} t
 * @returns {boolean}
 */
function isIsomorphic(s, t) {
  if (s.length !== t.length) return false;

  // Нужны ДВЕ карты: соответствие должно быть взаимно однозначным.
  // С одной картой 'ab' и 'aa' ошибочно прошли бы проверку
  const forward = new Map();   // символ s → символ t
  const backward = new Map();  // символ t → символ s

  for (let i = 0; i < s.length; i++) {
    const a = s[i];
    const b = t[i];

    // Если соответствие для a уже задано — оно должно совпадать
    if (forward.has(a) && forward.get(a) !== b) return false;
    // И симметрично в обратную сторону
    if (backward.has(b) && backward.get(b) !== a) return false;

    forward.set(a, b);
    backward.set(b, a);
  }

  return true;
}
```

**Почему две карты.** Возьмём `s = 'ab'`, `t = 'aa'`. Прямая карта даст `a→a`, `b→a` — противоречия нет. Но обратное отображение невозможно: `a` должно переходить и в `a`, и в `b`. Вторая карта ловит именно это.

Время **O(n)**, память **O(k)**.

## Типичные ошибки

1. **`+=` в цикле** вместо сборки в массив.
2. **Попытка изменить символ по индексу** — молча не работает.
3. **Забытая проверка длин** в задачах на анаграммы и изоморфизм.
4. **`split(' ')` вместо `split(/\s+/)`** — ломается на подряд идущих пробелах.
5. **Off-by-one в границах подстроки.** `slice(start, end)` — `end` не включается, а в двух указателях длина отрезка `right - left + 1`.
6. **Одна карта вместо двух** в задачах на соответствие символов.
7. **Игнорирование регистра и не-буквенных символов**, когда условие этого требует. Всегда уточняйте.
8. **Работа по индексам при возможных эмодзи.**

## Чеклист

- Состав символов важен, порядок нет → частотный словарь (26 ячеек или `Map`)
- Симметрия → два указателя навстречу
- Все палиндромные подстроки → расширение от центра
- Серии одинаковых символов подряд → проход с «виртуальным элементом» за концом
- Соответствие символ↔символ → две карты
- Собираете результат посимвольно → массив + `join`
