## Диагностика по ключевым словам

Первое, что нужно сделать с условием, — вычленить формулировки-маркеры. Почти каждая тема имеет свой набор.

| **Формулировка в условии** | **Скорее всего нужно** |
| --- | --- |

## Диагностика по ограничениям

Ограничение на размер входа — это подсказка о требуемой сложности, которую интервьюеры дают намеренно.

| **Ограничение** | **Допустимая сложность** | **Что это обычно значит** |
| --- | --- | --- |
| n ≤ 10–12 | O(n!) | перестановки, полный перебор |
| n ≤ 20–25 | O(2ⁿ) | подмножества, перебор с масками |
| n ≤ 100–500 | O(n³) | двумерное ДП с третьим циклом, Флойд |
| n ≤ 5000 | O(n²) | двумерное ДП, НВП, перебор пар |
| n ≤ 10⁵–10⁶ | O(n log n) | сортировка, бинарный поиск, куча |
| n ≤ 10⁷ и выше | O(n) или O(log n) | один проход, два указателя, математика |
Читается это в обе стороны. Если n ≤ 20 — не ищите полиномиальное решение, его, скорее всего, нет. Если n = 10⁶ — не предлагайте O(n²), даже как отправную точку: лучше сразу сказать «квадрат здесь не пройдёт, поэтому думаю в сторону одного прохода».

## Диагностика по требуемой сложности

Когда в условии прямо указана целевая сложность, это почти готовый ответ.

- **Требуют O(log n)** → бинарный поиск, почти без вариантов.
- **Требуют O(n) вместо очевидного O(n²)** → хеш-таблица, два указателя, скользящее окно или префиксные суммы. Четыре кандидата, выбирайте по ключевым словам.
- **Требуют O(n log n)** → сортировка как первый шаг, либо куча.
- **Требуют O(1) дополнительной памяти** → два указателя, пометка прямо во входных данных, математические трюки (XOR, циклическая замена). Хеш-таблица отпадает.
- **Требуют O(n log k)** → куча размера k.

## Дерево решений

Если ключевые слова не помогли, идите по вопросам сверху вниз.

**1. Что на входе?**

- Связный список → [приёмы для списков](../svjaznye-spiski/): фиктивный узел, быстрый и медленный указатели
- Дерево → [обход](../derevja/); нужны ответы детей → postorder, нужны уровни → BFS
- Сетка или матрица → чаще всего [граф](../grafy/), иногда [двумерное ДП](../dinamicheskoe-programmirovanie/)
- Граф, зависимости, связи → BFS, DFS, топологическая сортировка
- Строка → [строковые приёмы](../stroki/), но часто под ними тот же массив
- Массив → идём дальше

**2. Массив отсортирован?**

- Да → [бинарный поиск](../binarnyj-poisk/) или [два указателя](../dva-ukazatelja/)
- Нет, но сортировка не испортит задачу → отсортируйте и вернитесь к предыдущему пункту
- Нет, и порядок важен → идём дальше

**3. Что требуется вернуть?**

- Все варианты → [перебор с возвратом](../rekursija-i-backtracking/)
- Количество способов → [ДП](../dinamicheskoe-programmirovanie/)
- Максимум или минимум → ДП либо жадность, проверьте жадность контрпримером
- Да или нет → часто хеш-таблица или ДП
- Конкретный элемент или позиция → хеш-таблица, два указателя, бинарный поиск

**4. Речь про непрерывный отрезок?**

- Да, и он меняется постепенно → [скользящее окно](../skolzjashhee-okno/)
- Да, и нужны суммы на произвольных отрезках → [префиксные суммы](../prefiksnye-summy/)
- Нет, элементы могут идти не подряд → подпоследовательность, скорее всего ДП

**5. Ничего не подошло?**

Напишите честный перебор. Он почти всегда есть, и он — законный первый ответ. Затем спросите себя: что пересчитывается лишний раз? Ответ на этот вопрос и есть путь к оптимизации.

## Приёмы оптимизации: от наивного к хорошему

Практически любое ускорение на собеседовании — это один из шести переходов.

| **Наивное решение** | **Приём** | **Результат** |
| --- | --- | --- |
| Два вложенных цикла по парам | хеш-таблица: храним увиденное | O(n²) → O(n) |
| Пересчёт суммы отрезка каждый раз | префиксные суммы или скользящее окно | O(n²) → O(n) |
| Линейный поиск в отсортированном массиве | бинарный поиск | O(n) → O(log n) |
| Перебор всех значений ответа | бинарный поиск по ответу | O(n) → O(log n) |
| Сортировка ради k элементов | куча размера k | O(n log n) → O(n log k) |
| Повторный пересчёт одних подзадач | мемоизация или таблица | O(2ⁿ) → O(n²) |
Если вы застряли, пройдитесь по этому списку. В девяти случаях из десяти нужный переход здесь есть.

## Протокол ответа на собеседовании

Повторяю с [корневой страницы](../), потому что это важнее любого конкретного алгоритма. Семь шагов, в этом порядке.

**1. Повторите задачу своими словами.** «Правильно ли я понимаю: дан массив, нужно вернуть индексы двух элементов, дающих в сумме target?» Это ловит недопонимание до того, как вы потратили двадцать минут.

**2. Уточните вход и краевые случаи.** Обязательный минимум вопросов:

- Может ли массив быть пустым? Состоять из одного элемента?
- Отрицательные числа? Нули? Дубликаты?
- Отсортирован ли вход?
- Гарантируется ли существование ответа? Что вернуть, если ответа нет?
- Если ответов несколько — вернуть любой или все?
- Каков диапазон значений и размер входа?
- Можно ли изменять входные данные?

**3. Разберите пример руками.** Возьмите маленький вход и проговорите, как получается ответ. Часто решение становится видно именно здесь. Рисуйте.

**4. Назовите наивное решение и его сложность.** «Можно перебрать все пары — это O(n²)». Так вы фиксируете, что задача решена хотя бы как-то, и создаёте точку отсчёта. Молчать и думать о красивом решении — худшая стратегия.

**5. Найдите узкое место и приём.** «Проблема в том, что для каждого элемента я заново ищу дополнение. Если запоминать увиденное в хеш-таблице, поиск станет O(1)».

**6. Пишите код, проговаривая, что делаете.** Не молча. Интервьюер оценивает ход мысли, а не скорость печати.

**7. Прогоните код руками и назовите сложность.** Возьмите пример из условия и пройдите по строкам. Отдельно проверьте краевые случаи. Затем назовите время и память — по собственной инициативе, не дожидаясь вопроса.

:::tip
**Что делать, если решение не приходит.**

Скажите об этом вслух и продолжайте думать в диалоге. Молчаливая пауза на пять минут — худший из возможных вариантов: интервьюер не знает, думаете вы или сдались, и не может помочь.

Рабочие фразы:

- «Давайте я начну с перебора, а потом посмотрим, что можно ускорить»
- «Мне кажется, здесь поможет хеш-таблица, попробую развить эту мысль»
- «Я вижу два подхода, оба неидеальны. Первый — …, второй — …. Какой развивать?»
- «Можно небольшую подсказку, в правильном ли направлении я думаю?»

Просить подсказку — нормально. Это часть формата, и почти всегда её дают. Кандидат, который дошёл до решения с одной подсказкой, оценивается выше, чем тот, кто не сдвинулся вообще.

:::
## Что оценивают на самом деле

Алгоритмическая секция проверяет не знание алгоритмов наизусть. Оценивают примерно это:

- **Умение задавать вопросы.** Кандидат, который сразу бросился кодить, не уточнив краевые случаи, теряет баллы, даже если код верный.
- **Структурированность мышления.** Виден ли ход от задачи к решению, или ответ «телепортировался» из памяти.
- **Честность про сложность.** Назвать сложность самостоятельно и корректно, включая память.
- **Знание своего языка.** Для JS это: `sort()` без компаратора сортирует как строки, `shift()` это O(n), `+=` для строк в цикле это O(n²), лимит глубины рекурсии, отсутствие встроенной кучи.
- **Реакция на подсказку.** Умеете ли услышать и встроить чужую мысль.
- **Проверка своего кода.** Прогон руками до того, как сказать «готово».

Идеальный код, написанный молча, оценивается ниже, чем хорошее решение с проговоренным ходом мысли.

## JavaScript: что сказать вслух

Короткий список моментов, которые интервьюеры ждут именно от JS-кандидата. Упомянуть их к месту — заметный плюс.

- **`arr.sort()` без компаратора** сортирует лексикографически: `[10, 9, 2].sort()` даёт `[10, 2, 9]`. Всегда `sort((a, b) => a - b)`.
- **`shift()` и `unshift()` — O(n)**. В очереди используйте указатель головы.
- **`includes`, `indexOf`, `find` внутри цикла** превращают O(n) в O(n²). Замена — `Set` или `Map`.
- **Конкатенация строк в цикле — O(n²)**. Собирайте в массив, склеивайте `join`.
- **`new Array(n).fill(new Array(m))`** создаёт n ссылок на один массив. Нужен `Array.from({length: n}, () => new Array(m).fill(0))`.
- **Глубина рекурсии** ограничена примерно 10 000 кадрами. При n = 10⁵ нужна итеративная версия.
- **`Number.MAX_SAFE_INTEGER` = 2⁵³ − 1**. Выше точность теряется; для больших чисел есть `BigInt`.
- **`Math.trunc` против `Math.floor`** различаются на отрицательных числах.
- **Кучи в стандартной библиотеке нет** — нужно писать самой.
- **`Map` против объекта:** `Map` сохраняет порядок вставки, допускает любые ключи, имеет `.size` и быстрее на частых вставках и удалениях.
- **`for...of` против `for`** по индексам — на строках с эмодзи это разные вещи.

## Частые ловушки в условиях

- **«Подмассив» против «подпоследовательности».** Подмассив непрерывен, подпоследовательность — нет. Путаница здесь меняет задачу целиком: скользящее окно против ДП.
- **«Не более» против «ровно».** «Окно длины не более k» и «ровно k» — разные алгоритмы.
- **Строгие и нестрогие неравенства.** «Возрастающая» против «неубывающая», касание интервалов концами — считать ли пересечением.
- **Что вернуть: значение или индекс.** Читайте примеры, а не только текст.
- **Индексация с нуля или с единицы.**
- **Можно ли менять вход.** Влияет на оценку памяти.
- **Дубликаты.** Почти всегда меняют решение — в перестановках, подмножествах, двух указателях.
- **Гарантии существования ответа.** Если ответа может не быть, нужна ветка возврата.

## Мини-справочник по сложностям

| **Алгоритм / операция** | **Время** | **Память** |
| --- | --- | --- |
| Доступ к элементу массива | O(1) | — |
| `Map`/`Set`: get, set, has | O(1) в среднем | — |
| Бинарный поиск | O(log n) | O(1) |
| Один проход, два указателя, скользящее окно | O(n) | O(1) или O(k) |
| Построение префиксных сумм | O(n) | O(n) |
| Сортировка | O(n log n) | O(n) в JS |
| Куча: push, pop | O(log n) | — |
| k наибольших через кучу | O(n log k) | O(k) |
| Обход дерева | O(n) | O(h) |
| BFS/DFS по графу | O(V + E) | O(V) |
| Топологическая сортировка | O(V + E) | O(V + E) |
| Одномерное ДП | O(n·k) | O(n) или O(1) |
| Двумерное ДП | O(m·n) | O(m·n) или O(n) |
| Подмножества | O(2ⁿ) | O(n) |
| Перестановки | O(n!) | O(n) |
## Финальный чеклист перед собеседованием

Проверьте, что можете написать **не задумываясь**:

- Шаблон бинарного поиска с корректными границами
- Разворот связного списка тремя указателями
- Обход дерева: три DFS и BFS по уровням
- BFS по графу с `visited` и указателем головы очереди
- Шаблон скользящего окна переменной длины
- Шаблон перебора с возвратом с копией и откатом
- `MinHeap` с компаратором
- Частотный словарь через `Map`
- Пять шагов постановки задачи ДП

И что помните:

- Таблицу «размер входа → допустимая сложность»
- Семь шагов протокола ответа
- Список JS-специфики из раздела выше
- Обязательные вопросы про краевые случаи

Если все пункты закрыты — вы готовы к секции. Остальное придёт с практикой: решайте по две-три задачи в день, обязательно проговаривая решение вслух, как на настоящем собеседовании.
