Алгоритмические главы не нужно читать как справочник и пытаться запомнить весь код. Их задача — научить вас постепенно улучшать решение, которое вы уже понимаете.

## Один маршрут для всех разборов

В каждой алгоритмической главе двигайтесь по одной цепочке:

1. **Простое решение.** Сначала сформулируйте способ, который точно даёт правильный ответ, даже если он медленный.
2. **Почему оно работает.** Проверьте идею руками на маленьком примере и сформулируйте, почему ни один нужный случай не потерян.
3. **Узкое место.** Найдите повторную работу: повторный поиск, пересчёт суммы, перебор одной и той же пары или подзадачи.
4. **Паттерн.** Выберите структуру данных или технику, которая убирает именно эту повторную работу.
5. **Улучшенное решение.** Напишите код, сохранив понятные имена и отдельные шаги.
6. **Сравнение.** Оцените время и дополнительную память обоих вариантов.

Короткая версия, которую вы увидите в начале каждой главы:

> простое решение → почему работает → узкое место → паттерн → улучшенный код → сравнение сложности

## Не начинайте с готового быстрого кода

Если сразу переписать оптимальное решение, легко запомнить строки и не понять выбор алгоритма. На новой задаче такой шаблон уже не поможет.

Вместо этого перед открытием решения ответьте словами:

- что нужно вернуть;
- какие данные придётся помнить;
- какой самый прямой способ приходит в голову;
- какая операция в нём повторяется;
- можно ли сохранить результат этой операции или исключить часть перебора.

Если ответа пока нет, вернитесь к [маршруту от условия к коду](../ot-usloviya-k-kodu/) и разберите задачу руками.

## Что делать с незнакомым JavaScript

Каждая глава содержит блок «Перед началом» со ссылками на нужные уроки. Не обязательно перечитывать весь базовый курс: откройте только конструкцию, которая мешает понять текущий пример.

| Если непонятно | Куда вернуться |
| --- | --- |
| `const`, `let`, типы и сравнения | [Переменные и типы](../js-02-peremennye-i-tipy/) |
| `if`, `else`, логические условия | [Условия и логика](../js-03-usloviya-i-operatory/) |
| `for`, `while`, индекс | [Циклы](../js-04-cikly/) |
| параметры, `return`, вызов функции | [Функции](../js-05-funkcii/) |
| индекс массива, `push`, `pop`, строка | [Массивы и строки](../js-06-massivy-i-stroki/) |
| объект, `Map`, `Set` | [Объекты, Map и Set](../js-07-obekty-map-set/) |
| ошибка, `console.log`, тестовый пример | [Ошибки и отладка](../js-08-oshibki-i-otladka/) |

:::tip[Локальное напоминание — не новая тема]
В сложных главах встретятся ссылки между объектами, рекурсия, классы и функции-компараторы. Их короткое объяснение будет дано прямо перед первым использованием. Понимать эти конструкции нужно; запоминать синтаксис с первого раза — нет.
:::

## Как читать два варианта решения

Для уже разобранной задачи [Missing Number](../most-04-proverka-i-uluchshenie/) простой вариант проверяет каждого возможного кандидата отдельным поиском. Он понятен, но повторяет работу. Улучшенный вариант хранит встреченные числа в `Set` и заменяет повторный линейный поиск быстрой проверкой наличия.

Обращайте внимание не только на финальный код, а на **одну конкретную замену**:

```text
повторно ищем значение в массиве
                 ↓
один раз запоминаем значения в Set
                 ↓
проверяем наличие без нового прохода
```

Именно такая замена — от узкого места к подходящему инструменту — является переносимым навыком.

## Рабочий цикл ученика

Для каждой первой задачи нового типа:

1. Закройте готовое решение.
2. Решите пример вручную.
3. Запишите простую идею обычными словами.
4. Напишите простой код и проверьте его.
5. Назовите повторную работу.
6. Прочитайте объяснение паттерна.
7. Напишите улучшенный вариант самостоятельно.
8. Сравните результаты на тех же примерах.
9. На следующий день воспроизведите идею без подсказки.

## Когда можно идти дальше

- [ ] Я могу объяснить простое решение без кода.
- [ ] Я вижу его узкое место и могу назвать повторную работу.
- [ ] Я понимаю, какую проблему устраняет новый паттерн.
- [ ] Я могу проследить улучшенный код на маленьком примере.
- [ ] Я могу объяснить разницу во времени и памяти простыми словами.
- [ ] Я решила хотя бы одну задачу этого типа без копирования ответа.
