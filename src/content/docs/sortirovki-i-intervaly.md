Сортировку в задачах почти всегда делают встроенным `sort`. Но устройство алгоритмов спрашивают, а сортировка как **подготовительный шаг** открывает целый класс задач — в первую очередь задачи на интервалы.

← [К оглавлению](../)

## Сортировка в JavaScript

```js
const arr = [10, 9, 100, 1];

arr.sort();                    // [1, 10, 100, 9] — СТРОКОВОЕ сравнение!
arr.sort((a, b) => a - b);     // [1, 9, 10, 100] — по возрастанию
arr.sort((a, b) => b - a);     // [100, 10, 9, 1] — по убыванию
```

**Компаратор** — функция от двух элементов, определяющая порядок. Контракт:

- вернуть **отрицательное** число → `a` идёт раньше `b`
- вернуть **положительное** → `a` идёт позже `b`
- вернуть **ноль** → порядок между ними не важен

Для чисел `a - b` идеально подходит: если `a < b`, разность отрицательна.

:::caution
`sort` **изменяет исходный массив** и возвращает ссылку на него же. Если исходный массив портить нельзя — копируйте: `[...arr].sort(...)`.

Без компаратора элементы приводятся к строкам и сравниваются посимвольно. Поэтому `100` оказывается раньше `9` — символ `'1'` меньше `'9'`. Это самая частая ошибка с числами в JS.

:::
### Сортировка объектов и многоуровневая сортировка

```js
const people = [
  { name: 'Аня', age: 30 },
  { name: 'Борис', age: 25 },
  { name: 'Вера', age: 30 },
];

// По возрасту возрастанию
people.sort((a, b) => a.age - b.age);

// По строке: localeCompare корректно сравнивает с учётом языка
people.sort((a, b) => a.name.localeCompare(b.name));

// Два уровня: сначала по возрасту, при равенстве — по имени
people.sort((a, b) => {
  if (a.age !== b.age) return a.age - b.age;   // основной ключ
  return a.name.localeCompare(b.name);          // разрешение ничьей
});
```

**`String.prototype.localeCompare(other)`** возвращает отрицательное число, ноль или положительное — ровно то, что нужно компаратору. Для кириллицы работает правильно, в отличие от `a < b` по кодам символов.

### Стабильность

**Стабильная сортировка** сохраняет исходный относительный порядок элементов с равными ключами. `Array.prototype.sort` в современных движках (V8 использует TimSort) **стабильна** — это гарантировано спецификацией с ES2019.

Зачем это важно: можно сортировать в несколько проходов. Отсортировали по имени, потом стабильно по возрасту — получили сортировку «по возрасту, при равенстве по имени».

Сложность встроенной сортировки — **O(n log n)** по времени.

## Как устроены сортировки

Реализовывать их в задаче обычно не требуется, но устройство спрашивают. Разберём три, которые нужно знать.

### Сортировка слиянием (merge sort)

**Идея — «разделяй и властвуй»:** делим массив пополам, рекурсивно сортируем каждую половину, затем сливаем две отсортированные половины в одну.

Слияние — это ровно та функция из [двух указателей](../dva-ukazatelja/).

```js
/**
 * Сортировка слиянием. Возвращает НОВЫЙ отсортированный массив.
 * @param {number[]} arr
 * @returns {number[]}
 */
function mergeSort(arr) {
  // База рекурсии: массив из 0 или 1 элемента уже отсортирован
  if (arr.length <= 1) return arr;

  const mid = Math.floor(arr.length / 2);

  // slice(0, mid) — копия первой половины, slice(mid) — копия второй
  const left = mergeSort(arr.slice(0, mid));
  const right = mergeSort(arr.slice(mid));

  return merge(left, right);
}

/**
 * Сливает два отсортированных массива в один отсортированный.
 * @param {number[]} a
 * @param {number[]} b
 * @returns {number[]}
 */
function merge(a, b) {
  const result = [];
  let i = 0, j = 0;

  // Берём меньший из двух текущих элементов
  while (i < a.length && j < b.length) {
    // <= делает сортировку СТАБИЛЬНОЙ:
    // при равенстве первым идёт элемент из левой половины
    if (a[i] <= b[j]) {
      result.push(a[i++]);
    } else {
      result.push(b[j++]);
    }
  }

  // Дописываем остаток того массива, который не кончился
  while (i < a.length) result.push(a[i++]);
  while (j < b.length) result.push(b[j++]);

  return result;
}
```

**Разбор.** `a[i++]` — постфиксный инкремент: используется текущее значение `i`, затем `i` увеличивается. Компактная запись для «взять элемент и сдвинуть указатель».

**Сложность.** Время **O(n log n)** — всегда, в любом случае: log n уровней рекурсии, на каждом уровне суммарно O(n) работы на слияние. Память **O(n)** — под промежуточные массивы.

**Свойства:** стабильна, гарантированное O(n log n), но требует дополнительной памяти.

### Быстрая сортировка (quicksort)

**Идея:** выбираем **опорный элемент (pivot)**, разбиваем массив на «меньше опорного» и «больше опорного», рекурсивно сортируем обе части.

```js
/**
 * Быстрая сортировка (упрощённая, не на месте — ради читаемости).
 * @param {number[]} arr
 * @returns {number[]}
 */
function quickSort(arr) {
  if (arr.length <= 1) return arr;

  // Опорный — средний элемент. Выбор середины лучше, чем первый элемент:
  // на уже отсортированных данных первый элемент даёт худший случай O(n²)
  const pivotIndex = Math.floor(arr.length / 2);
  const pivot = arr[pivotIndex];

  const less = [];    // строго меньше опорного
  const equal = [];   // равные (важно для массивов с дубликатами)
  const greater = []; // строго больше

  for (const x of arr) {
    if (x < pivot) less.push(x);
    else if (x > pivot) greater.push(x);
    else equal.push(x);
  }

  // Рекурсивно сортируем края, середина уже на месте.
  // Спред раскладывает массивы в аргументы concat
  return [...quickSort(less), ...equal, ...quickSort(greater)];
}
```

**Сложность.** Время **O(n log n)** в среднем, **O(n²)** в худшем случае (когда опорный элемент каждый раз оказывается минимальным или максимальным). Память: эта версия O(n); классическая реализация на месте — O(log n) на стек.

**Свойства:** на практике быстрее merge sort по константе, но нестабильна и имеет плохой худший случай.

:::note
**Зачем нужна отдельная группа `equal`.** Без неё массив из одинаковых элементов разбивался бы на пустую и полную части, и рекурсия деградировала бы до O(n²). Разделение на три части (three-way partition) — стандартная защита.

:::
### Сортировка подсчётом (counting sort)

Работает **за O(n)**, но только когда элементы — целые числа в небольшом известном диапазоне.

```js
/**
 * Сортировка подсчётом для целых чисел из диапазона [min, max].
 * @param {number[]} arr
 * @returns {number[]}
 */
function countingSort(arr) {
  if (arr.length === 0) return [];

  const min = Math.min(...arr);
  const max = Math.max(...arr);

  // Одна ячейка на каждое возможное значение
  const counts = new Array(max - min + 1).fill(0);

  // Считаем, сколько раз встретилось каждое значение
  for (const x of arr) {
    counts[x - min]++;   // сдвиг на min, чтобы индексы начинались с нуля
  }

  // Разворачиваем счётчики обратно в массив
  const result = [];
  for (let i = 0; i < counts.length; i++) {
    for (let j = 0; j < counts[i]; j++) {
      result.push(i + min);
    }
  }

  return result;
}
```

**Сложность.** Время **O(n + k)**, память **O(k)**, где k — размер диапазона значений. Если k сопоставим с n — это линейная сортировка. Если значения от 0 до миллиарда — метод бесполезен.

Упоминание counting sort на собеседовании в подходящей задаче («оценки от 1 до 5», «цвета: 0, 1, 2») производит хорошее впечатление.

### Сравнение

| **Алгоритм** | **Среднее** | **Худшее** | **Память** | **Стабильна** |
| --- | --- | --- | --- | --- |
| Merge sort | O(n log n) | O(n log n) | O(n) | да |
| Quicksort | O(n log n) | O(n²) | O(log n) | нет |
| Heapsort | O(n log n) | O(n log n) | O(1) | нет |
| Counting sort | O(n + k) | O(n + k) | O(k) | да |
| Bubble sort | O(n²) | O(n²) | O(1) | да |
:::note
**Почему нельзя быстрее O(n log n).** Любая сортировка, основанная на **сравнениях**, не может работать быстрее O(n log n). Доказательство: существует n! возможных перестановок; каждое сравнение даёт один бит информации; чтобы различить n! вариантов, нужно не меньше log₂(n!) ≈ n log n сравнений. Counting sort обходит эту границу, потому что не сравнивает элементы, а использует их значения как индексы.

Этот аргумент — хороший ответ на вопрос «а можно быстрее?».

:::
## Интервалы

**Интервал (отрезок)** — пара `[start, end]`. Задачи на интервалы почти всегда начинаются с сортировки — обычно по началу, иногда по концу.

### Задача 1. Объединить пересекающиеся интервалы

**Условие.** Дан массив интервалов. Объединить все пересекающиеся и вернуть результат.

Пример: `[[1,3], [2,6], [8,10], [15,18]]` → `[[1,6], [8,10], [15,18]]`.

#### Ход мысли

Отсортируем по началу. Тогда достаточно одного прохода: держим «текущий накопленный» интервал и сравниваем со следующим.

Два интервала пересекаются, если начало следующего не превышает конец текущего: `next[0] <= current[1]`. При пересечении расширяем текущий: новый конец — максимум из двух концов (следующий интервал может целиком лежать внутри текущего).

#### Решение

```js
/**
 * Объединяет пересекающиеся интервалы.
 * @param {number[][]} intervals — массив пар [start, end]
 * @returns {number[][]} непересекающиеся интервалы, отсортированные по началу
 */
function mergeIntervals(intervals) {
  if (intervals.length === 0) return [];

  // Сортируем по началу. Без этого одного прохода не хватит
  intervals.sort((a, b) => a[0] - b[0]);

  // Первый интервал кладём как заготовку. slice() делает копию,
  // чтобы не испортить входные данные при последующем изменении
  const result = [intervals[0].slice()];

  for (let i = 1; i < intervals.length; i++) {
    // Последний добавленный интервал — тот, который сейчас растёт
    const last = result[result.length - 1];
    const current = intervals[i];

    if (current[0] <= last[1]) {
      // Пересекаются — расширяем конец.
      // Math.max обязателен: current может лежать ВНУТРИ last,
      // тогда last[1] уже больше, и перезапись его бы сократила
      last[1] = Math.max(last[1], current[1]);
    } else {
      // Разрыв — начинаем новый интервал
      result.push(current.slice());
    }
  }

  return result;
}
```

#### Разбор

- **`intervals.sort((a, b) => a[0] - b[0])`** — компаратор по первому элементу пары.
- **`result[result.length - 1]`** — последний элемент результата; он же объект, который мы мутируем.
- **`.slice()`** без аргументов — полная копия массива. Без неё мы бы изменили входные данные, что считается побочным эффектом и вызывает вопросы на ревью.
- **`Math.max(last[1], current[1])`** — ключевая деталь. Случай «вложенный интервал» (`[[1,10], [2,3]]`) ломает наивную версию `last[1] = current[1]`.

#### Сложность

Время **O(n log n)** — доминирует сортировка. Память **O(n)** на результат.

### Задача 2. Вставить интервал

**Условие.** Дан список непересекающихся интервалов, отсортированных по началу, и новый интервал. Вставить его, объединив при необходимости.

#### Решение

```js
/**
 * Вставляет новый интервал в отсортированный список непересекающихся.
 * @param {number[][]} intervals — отсортированные непересекающиеся интервалы
 * @param {number[]} newInterval — вставляемый интервал [start, end]
 * @returns {number[][]}
 */
function insertInterval(intervals, newInterval) {
  const result = [];
  let i = 0;
  const n = intervals.length;

  // Фаза 1: всё, что целиком левее нового интервала — копируем как есть.
  // Условие «конец текущего строго меньше начала нового» = нет пересечения
  while (i < n && intervals[i][1] < newInterval[0]) {
    result.push(intervals[i]);
    i++;
  }

  // Фаза 2: всё пересекающееся поглощаем в newInterval.
  // Пересечение есть, пока начало текущего не превышает конец нового
  let start = newInterval[0];
  let end = newInterval[1];
  while (i < n && intervals[i][0] <= end) {
    start = Math.min(start, intervals[i][0]);
    end = Math.max(end, intervals[i][1]);
    i++;
  }
  result.push([start, end]);

  // Фаза 3: остаток — целиком правее, копируем
  while (i < n) {
    result.push(intervals[i]);
    i++;
  }

  return result;
}
```

Время **O(n)** — сортировка не нужна, вход уже отсортирован. Память **O(n)**.

Трёхфазная структура — типовой шаблон для задач «до / пересечение / после». Проговаривание фаз вслух сильно упрощает объяснение.

### Задача 3. Минимум переговорок

**Условие.** Дан массив встреч `[start, end]`. Сколько переговорок нужно минимум, чтобы провести все встречи?

Пример: `[[0,30], [5,10], [15,20]]` → `2`.

#### Ход мысли

Переформулируем: нужно найти **максимальное число одновременно идущих встреч**.

Приём — **событийная развёртка (sweep line)**. Каждая встреча даёт два события: «начало» (+1 к счётчику занятых комнат) и «конец» (−1). Сортируем все события по времени и идём слева направо, ведя счётчик. Максимум счётчика — ответ.

Тонкость: если встреча заканчивается ровно тогда, когда другая начинается, комната освобождается вовремя. Значит, при равном времени событие «конец» обрабатывается **раньше** события «начало».

#### Решение

```js
/**
 * Минимальное число переговорок для всех встреч.
 * @param {number[][]} intervals — массив [start, end]
 * @returns {number}
 */
function minMeetingRooms(intervals) {
  if (intervals.length === 0) return 0;

  // Раскладываем интервалы на два отсортированных массива времён.
  // map извлекает нужную координату, sort упорядочивает
  const starts = intervals.map(iv => iv[0]).sort((a, b) => a - b);
  const ends = intervals.map(iv => iv[1]).sort((a, b) => a - b);

  let rooms = 0;      // сколько комнат занято сейчас
  let maxRooms = 0;   // рекорд
  let endPtr = 0;     // указатель по массиву окончаний

  for (let i = 0; i < starts.length; i++) {
    // Пока есть встречи, закончившиеся НЕ ПОЗЖЕ начала текущей —
    // освобождаем их комнаты.
    // <= а не <: встреча, кончающаяся в 10:00, освобождает комнату
    // для встречи, начинающейся в 10:00
    while (endPtr < ends.length && ends[endPtr] <= starts[i]) {
      rooms--;
      endPtr++;
    }

    rooms++;                                // текущая встреча занимает комнату
    maxRooms = Math.max(maxRooms, rooms);
  }

  return maxRooms;
}
```

#### Разбор

- **`intervals.map(iv => iv[0])`** — новый массив из первых элементов каждой пары.
- **Два независимо отсортированных массива** — приём, позволяющий обойтись двумя указателями вместо явного списка событий.
- **`ends[endPtr] <= starts[i]`** — знак равенства здесь меняет ответ. Обязательно уточните у интервьюера: считается ли встреча, заканчивающаяся в момент начала другой, конфликтующей.

#### Сложность

Время **O(n log n)**, память **O(n)**.

Альтернативное решение — через мин-кучу времён окончания, см. [Жадные алгоритмы и куча](../zhadnye-algoritmy-i-kucha/). Хорошо назвать оба подхода.

### Задача 4. Максимум непересекающихся интервалов

**Условие.** Сколько интервалов нужно удалить минимум, чтобы оставшиеся не пересекались?

#### Ход мысли

Это [жадная](../zhadnye-algoritmy-i-kucha/) задача, и здесь важна **сортировка по концу**, а не по началу.

Интуиция: чтобы оставить как можно больше интервалов, каждый раз выбираем тот, который заканчивается раньше всех — он освобождает максимум места для остальных.

#### Решение

```js
/**
 * Минимальное число интервалов, которые надо удалить,
 * чтобы оставшиеся не пересекались.
 * @param {number[][]} intervals
 * @returns {number}
 */
function eraseOverlapIntervals(intervals) {
  if (intervals.length === 0) return 0;

  // Сортировка ПО КОНЦУ — ключевое решение задачи
  intervals.sort((a, b) => a[1] - b[1]);

  let kept = 1;                  // первый интервал всегда оставляем
  let lastEnd = intervals[0][1]; // конец последнего оставленного

  for (let i = 1; i < intervals.length; i++) {
    // Начинается не раньше конца предыдущего — не пересекается, оставляем
    if (intervals[i][0] >= lastEnd) {
      kept++;
      lastEnd = intervals[i][1];
    }
    // Иначе пропускаем этот интервал (то есть «удаляем» его)
  }

  return intervals.length - kept;
}
```

**Почему сортировка по концу, а не по началу.** Возьмём `[[1,100], [2,3], [3,4]]`. По началу первым окажется `[1,100]`, он съест всё, и ответ будет 1 вместо 2. По концу порядок будет `[2,3], [3,4], [1,100]` — оставим два. Формально это доказывается аргументом обмена: любое оптимальное решение можно перестроить так, чтобы первым шёл интервал с наименьшим концом, не ухудшив результат.

Время **O(n log n)**, память **O(1)** дополнительно.

## Типичные ошибки

1. **`sort()` без компаратора для чисел** — главная ошибка JS в этой теме.
2. **Мутация входного массива.** `sort` меняет вход. Если это нежелательно — копируйте.
3. **Сортировка не по тому ключу.** Объединение интервалов — по началу; максимум непересекающихся — по концу. Перепутать легко, и решение станет неверным без единой синтаксической ошибки.
4. **Забыт `Math.max` при объединении** — вложенные интервалы обрабатываются неправильно.
5. **Неоговорённые границы.** Считаются ли `[1,2]` и `[2,3]` пересекающимися? Это уточняющий вопрос, который нужно задать.
6. **Пустой вход** — проверяйте `intervals.length === 0`.

## Чеклист

- Нужен порядок → `sort` с явным компаратором
- Задача на интервалы → почти всегда начать с сортировки
- «Объединить / вставить / пересечение» → сортировка по началу
- «Максимум непересекающихся / минимум удалений» → сортировка по концу, жадность
- «Сколько одновременно» → событийная развёртка или куча
- Небольшой диапазон целых значений → упомянуть counting sort за O(n)

## Задачи для тренировки

1. **Сортировка цветов** — массив из 0, 1, 2 отсортировать за один проход и O(1) памяти (голландский флаг).
2. **Может ли человек посетить все встречи** — проверка отсутствия пересечений.
3. **Пересечение двух списков интервалов.**
4. **Найти k ближайших элементов к заданному числу.**
5. **Перестроить очередь по росту** — сортировка с нетривиальным компаратором и вставками.
