Жадность — самый простой по коду подход и самый коварный по доказательству. Куча — структура, которой в JavaScript нет из коробки, поэтому её приходится писать руками.

## Жадный алгоритм

**Жадный алгоритм (greedy)** — алгоритм, который на каждом шаге делает локально оптимальный выбор, никогда не пересматривая уже принятые решения.

Пример из жизни: выдать сдачу минимальным числом монет. Берём самый крупный подходящий номинал, потом следующий и так далее. Для российских и европейских номиналов это даёт оптимум.

Но не для любых. Для номиналов `[1, 3, 4]` и суммы `6` жадность даст `4 + 1 + 1` — три монеты, а оптимум `3 + 3` — две. Ровно на этом жадность и ломается.

:::caution
**Главная опасность темы.** Жадное решение почти всегда выглядит правдоподобно и проходит первые два примера. Прежде чем писать код, нужно либо обосновать корректность, либо найти контрпример.

Формальный критерий — **свойство жадного выбора**: существует оптимальное решение, содержащее локально оптимальный выбор первого шага. Практически это проверяется двумя способами:

1. Попробовать построить контрпример из 3–4 элементов. Если за пару минут не получилось — жадность, скорее всего, работает.
2. Провести рассуждение **обменом (exchange argument)**: взять произвольное оптимальное решение и показать, что жадный выбор можно в него подставить, не ухудшив результат.

Если жадность не работает — задача решается [динамическим программированием](../dinamicheskoe-programmirovanie/).

:::
### Жадность против динамического программирования

| **Признак** | **Жадный алгоритм** | **Динамическое программирование** |
| --- | --- | --- |
| Решения | принимаются раз и навсегда | перебираются все варианты |
| Память | обычно O(1) | O(n) и больше |
| Время | обычно O(n log n) на сортировку | O(n·k) и больше |
| Корректность | нужно доказывать | следует из полного перебора |
| Когда применим | есть свойство жадного выбора | всегда, но дороже |
Практическое правило для собеседования: предложите жадное решение, **сразу скажите, что его нужно обосновать**, и приведите либо аргумент, либо контрпример. Такой ход ценится выше, чем молча написанный код.

## Задача 1. Максимум непересекающихся интервалов

**Условие.** Дан набор интервалов. Выбрать максимальное количество попарно непересекающихся.

### Ход мысли

Кандидаты на жадный критерий: брать самый короткий интервал, брать начинающийся раньше всех, брать **заканчивающийся раньше всех**.

Правильный — последний. Интуиция: выбрав интервал, который заканчивается раньше всех, мы оставляем максимум свободного места для остальных.

**Обоснование обменом.** Пусть в оптимальном решении первый интервал заканчивается позже, чем наш жадный выбор. Заменим его на жадный: он заканчивается не позже, значит не конфликтует ни с чем из остатка, и количество интервалов не изменилось. Значит, существует оптимум, начинающийся с жадного выбора. Повторяя рассуждение, получаем корректность всего алгоритма.

### Решение

```js
/**
 * Максимальное количество непересекающихся интервалов.
 * @param {number[][]} intervals — массив пар [start, end]
 * @returns {number}
 */
function maxNonOverlapping(intervals) {
  if (intervals.length === 0) return 0;

  // Сортируем по ВРЕМЕНИ ОКОНЧАНИЯ — в этом вся суть решения.
  // Компаратор возвращает отрицательное число, если a должно идти раньше
  const sorted = [...intervals].sort((a, b) => a[1] - b[1]);

  let count = 1;              // первый интервал берём всегда
  let lastEnd = sorted[0][1]; // момент, когда освободимся

  for (let i = 1; i < sorted.length; i++) {
    const [start, end] = sorted[i];

    // Интервал начинается не раньше, чем закончился предыдущий выбранный —
    // значит не пересекается, берём его.
    // Нестрогое >= означает, что касание концами пересечением не считается.
    // Обязательно уточните это у интервьюера
    if (start >= lastEnd) {
      count++;
      lastEnd = end;
    }
    // Иначе просто пропускаем — пересекается с уже выбранным
  }

  return count;
}
```

### Разбор

- **`[...intervals].sort(...)`** — копия перед сортировкой: `sort` мутирует массив, а портить вход не стоит.
- **`(a, b) => a[1] - b[1]`** — числовой компаратор по второму элементу пары. Без компаратора `sort()` сравнил бы элементы как строки.
- **`const [start, end] = sorted[i]`** — деструктуризация пары в две именованные переменные. Читается лучше, чем `sorted[i][0]`.

Время **O(n log n)** — доминирует сортировка. Память **O(n)** на копию.

## Куча

**Куча (heap)** — структура данных, дающая доступ к минимальному (или максимальному) элементу за O(1), а вставку и удаление — за O(log n).

**Приоритетная очередь (priority queue)** — очередь, где элементы выдаются не в порядке поступления, а по приоритету. Куча — её стандартная реализация. В задачах эти два термина обычно употребляют как синонимы.

**Мин-куча** отдаёт минимум, **макс-куча** — максимум.

### Как устроена

Куча — это **полное бинарное дерево**, хранящееся в массиве. «Полное» означает, что все уровни заполнены слева направо без пропусков, — именно это позволяет обойтись без ссылок.

Индексы вычисляются арифметикой:

```js
parent(i) = Math.floor((i - 1) / 2)
left(i)   = 2 * i + 1
right(i)  = 2 * i + 2
```

**Свойство кучи (heap property):** значение любого узла не больше значений его детей (для мин-кучи). Обратите внимание: это **слабее**, чем в BST — порядок между братьями не определён, отсортированного обхода из кучи не получить.

Две ключевые операции восстанавливают свойство кучи:

- **Всплытие (sift up / bubble up)** — новый элемент кладётся в конец массива и поднимается, меняясь местами с родителем, пока он меньше родителя.
- **Погружение (sift down / heapify down)** — при удалении корня на его место ставится последний элемент, который опускается вниз, меняясь с меньшим из детей.

Обе операции проходят путь от листа до корня, то есть **O(log n)** — высота полного дерева.

:::note
**В JavaScript кучи нет в стандартной библиотеке.** Нет `PriorityQueue`, нет `Heap` — в отличие от Python (`heapq`), Java (`PriorityQueue`) и C++ (`priority_queue`).

Это значит, что на собеседовании кучу придётся написать самой. Реализация ниже — примерно 50 строк, её стоит выучить: она отпирает целый класс задач.

Если реализация не требуется по существу задачи, спросите: «могу ли я считать, что приоритетная очередь у меня есть?» Часто разрешают — и вы сэкономите десять минут.

:::
### Реализация мин-кучи

```js
/**
 * Мин-куча (приоритетная очередь).
 * По умолчанию сравнивает числа по возрастанию,
 * но принимает произвольный компаратор.
 */
class MinHeap {
  /**
   * @param {(a: *, b: *) => number} compare — компаратор:
   *        отрицательное число, если a имеет более высокий приоритет
   */
  constructor(compare = (a, b) => a - b) {
    this.items = [];
    this.compare = compare;
  }

  get size() {
    return this.items.length;
  }

  isEmpty() {
    return this.items.length === 0;
  }

  /** Посмотреть минимум, не удаляя. O(1). */
  peek() {
    return this.items[0];
  }

  /**
   * Добавить элемент. O(log n).
   * @param {*} value
   */
  push(value) {
    this.items.push(value);          // кладём в конец — свойство кучи нарушено
    this.siftUp(this.items.length - 1);   // и восстанавливаем всплытием
  }

  /**
   * Извлечь минимум. O(log n).
   * @returns {*} минимальный элемент или undefined
   */
  pop() {
    if (this.items.length === 0) return undefined;

    const top = this.items[0];
    const last = this.items.pop();   // снимаем последний элемент

    // Если после снятия что-то осталось, ставим последний элемент
    // в корень и погружаем его на своё место
    if (this.items.length > 0) {
      this.items[0] = last;
      this.siftDown(0);
    }

    return top;
  }

  /**
   * Поднимает элемент вверх, пока он «легче» родителя.
   * @param {number} index — стартовая позиция
   */
  siftUp(index) {
    let i = index;

    while (i > 0) {
      const parent = Math.floor((i - 1) / 2);

      // Родитель уже не больше — свойство кучи выполнено, останавливаемся
      if (this.compare(this.items[i], this.items[parent]) >= 0) break;

      this.swap(i, parent);
      i = parent;   // продолжаем с позиции родителя
    }
  }

  /**
   * Опускает элемент вниз, пока он «тяжелее» кого-то из детей.
   * @param {number} index — стартовая позиция
   */
  siftDown(index) {
    let i = index;
    const n = this.items.length;

    while (true) {
      const left = 2 * i + 1;
      const right = 2 * i + 2;
      let smallest = i;

      // Проверяем левого ребёнка: существует ли и меньше ли текущего минимума
      if (left < n && this.compare(this.items[left], this.items[smallest]) < 0) {
        smallest = left;
      }
      // То же для правого
      if (right < n && this.compare(this.items[right], this.items[smallest]) < 0) {
        smallest = right;
      }

      // Текущий элемент меньше обоих детей — он на своём месте
      if (smallest === i) break;

      this.swap(i, smallest);
      i = smallest;   // продолжаем с позиции, куда опустились
    }
  }

  /** Меняет местами два элемента массива. */
  swap(i, j) {
    [this.items[i], this.items[j]] = [this.items[j], this.items[i]];
  }
}
```

### Разбор реализации

- **Компаратор в конструкторе** — одна и та же реализация работает как мин-куча, макс-куча и куча объектов. Макс-куча получается инверсией: `new MinHeap((a, b) => b - a)`. Кучу пар по второму полю: `new MinHeap((a, b) => a[1] - b[1])`.
- **`siftUp` останавливается по `>= 0`** — как только элемент не меньше родителя. Строгое `> 0` тоже работает, но `>=` избавляет от лишних перестановок равных элементов.
- **`siftDown` сравнивает с *меньшим* из детей.** Меняться местами с большим ребёнком — типичная ошибка: свойство кучи не восстановится.
- **`smallest === i` как условие выхода** — элемент на своём месте.
- **`[a[i], a[j]] = [a[j], a[i]]`** — обмен через деструктуризацию массива, без временной переменной. Правая часть вычисляется целиком до присваивания, поэтому обмен корректен.
- **`this.items.pop()` до проверки длины** — обратите внимание на порядок в `pop()`: когда в куче один элемент, `pop()` снимет именно его, и он же вернётся как `top`. Проверка `length > 0` после снятия обрабатывает этот случай.

### Сложности операций

| **Операция** | **Сложность** |
| --- | --- |
| `peek` | O(1) |
| `push` | O(log n) |
| `pop` | O(log n) |
| Построение кучи из массива поэлементно | O(n log n) |
| Построение кучи из массива через heapify | O(n) |
## Задача 2. k-й наибольший элемент

**Условие.** Найти k-й по величине элемент несортированного массива.

### Ход мысли

Отсортировать и взять `nums[n - k]` — O(n log n). Работает, но задача проверяет знание кучи.

Приём: держать **мин**-кучу размера ровно `k`. Звучит парадоксально — мин-куча для поиска максимума, — но логика такая: в куче лежат k наибольших элементов, виденных до сих пор, а её корень — наименьший из них, то есть ровно k-й наибольший.

Когда размер превышает k, выбрасываем минимум — он точно не входит в k наибольших.

### Решение

```js
/**
 * k-й наибольший элемент массива.
 * @param {number[]} nums
 * @param {number} k
 * @returns {number}
 */
function findKthLargest(nums, k) {
  // МИН-куча: её корень — самый маленький из k наибольших
  const heap = new MinHeap((a, b) => a - b);

  for (const num of nums) {
    heap.push(num);

    // Куча выросла больше k — выбрасываем минимум.
    // Он гарантированно не входит в k наибольших элементов
    if (heap.size > k) {
      heap.pop();
    }
  }

  // В куче ровно k наибольших, её корень — k-й наибольший
  return heap.peek();
}
```

### Сложность

Время **O(n log k)** — n вставок в кучу размера k. Память **O(k)**.

Это заметно лучше сортировки при малом k: для n = 10⁶ и k = 10 разница между `log k ≈ 3` и `log n ≈ 20` почти семикратная.

:::tip
**Шаблон «куча размера k» универсален.** k наибольших → мин-куча. k наименьших → макс-куча. Инверсия всегда кажется контринтуитивной; запомните правило: **куча хранит то, что мы оставляем, а её корень — кандидат на вылет**.

Существует и решение за O(n) в среднем — QuickSelect, модификация быстрой сортировки. Упомянуть его стоит, писать обычно не требуют.

:::
## Задача 3. k ближайших точек к началу координат

**Условие.** Из массива точек `[x, y]` выбрать k ближайших к точке (0, 0).

### Решение

```js
/**
 * k ближайших к началу координат точек.
 * @param {number[][]} points — массив пар [x, y]
 * @param {number} k
 * @returns {number[][]}
 */
function kClosest(points, k) {
  // k БЛИЖАЙШИХ → МАКС-куча по расстоянию:
  // корень — самая далёкая из отобранных, её и выбрасываем
  const heap = new MinHeap((a, b) => distance(b) - distance(a));

  /**
   * Квадрат расстояния от точки до начала координат.
   * Корень не извлекаем: он монотонен, порядок сравнения не изменит,
   * а извлечение корня медленнее и даёт погрешность округления
   */
  function distance(point) {
    return point[0] * point[0] + point[1] * point[1];
  }

  for (const point of points) {
    heap.push(point);
    if (heap.size > k) {
      heap.pop();   // выбрасываем самую далёкую
    }
  }

  return heap.items;   // порядок внутри кучи произвольный — по условию это ок
}
```

### Разбор

- **`distance(b) - distance(a)`** — инверсия аргументов превращает мин-кучу в макс-кучу.
- **Отказ от `Math.sqrt`** — важная деталь, которую стоит проговорить: сравнение квадратов эквивалентно сравнению расстояний, потому что квадратный корень монотонно возрастает на неотрицательных числах.
- **`heap.items`** возвращает внутренний массив — элементы там не отсортированы, но по условию порядок не важен. Если бы был важен — извлекали бы через `pop` в цикле.

Время **O(n log k)**, память **O(k)**.

## Задача 4. Слияние k отсортированных списков

**Условие.** Даны k отсортированных массивов. Слить их в один отсортированный.

### Ход мысли

Наивно — склеить всё и отсортировать: O(N log N), где N — суммарная длина.

Лучше: в куче держим по одному текущему элементу из каждого массива. Извлекаем минимум, добавляем его в результат и сразу кладём в кучу следующий элемент из того же массива.

Куча всегда размера не больше k, поэтому каждая операция O(log k).

### Решение

```js
/**
 * Слияние k отсортированных массивов.
 * @param {number[][]} lists — массив отсортированных массивов
 * @returns {number[]} общий отсортированный массив
 */
function mergeKSorted(lists) {
  // В куче — тройки [значение, номер массива, индекс внутри массива].
  // Сравниваем по первому элементу тройки
  const heap = new MinHeap((a, b) => a[0] - b[0]);

  // Кладём первый элемент каждого непустого массива
  for (let i = 0; i < lists.length; i++) {
    if (lists[i].length > 0) {
      heap.push([lists[i][0], i, 0]);
    }
  }

  const result = [];

  while (!heap.isEmpty()) {
    // Минимум среди всех «голов» — следующий элемент результата
    const [value, listIndex, itemIndex] = heap.pop();
    result.push(value);

    // Подтягиваем следующий элемент из того же массива, если он есть.
    // Номер массива хранится в тройке именно для этого
    const nextIndex = itemIndex + 1;
    if (nextIndex < lists[listIndex].length) {
      heap.push([lists[listIndex][nextIndex], listIndex, nextIndex]);
    }
  }

  return result;
}
```

### Разбор

- **Тройка вместо значения.** Одного значения мало: извлекая минимум, нужно знать, из какого массива его подтягивать дальше.
- **Размер кучи не превышает k** — по одному элементу на массив.
- **`while (!heap.isEmpty())`** — цикл заканчивается, когда все массивы исчерпаны.

Время **O(N log k)**, память **O(k)** на кучу плюс O(N) на результат.

Та же схема работает для связных списков — меняется только способ получить следующий элемент (`node.next` вместо индекса).

## Задача 5. Планировщик задач с кучей

**Условие.** Даны интервалы встреч. Сколько переговорок нужно минимум?

Задача уже разбиралась через [сортировку и метод заметающей прямой](../sortirovki-i-intervaly/). Вариант с кучей нагляднее.

```js
/**
 * Минимальное число переговорок для набора встреч.
 * @param {number[][]} intervals — пары [start, end]
 * @returns {number}
 */
function minMeetingRooms(intervals) {
  if (intervals.length === 0) return 0;

  // Обрабатываем встречи в порядке НАЧАЛА
  const sorted = [...intervals].sort((a, b) => a[0] - b[0]);

  // В куче — времена окончания занятых переговорок.
  // Корень — комната, которая освободится раньше всех
  const rooms = new MinHeap((a, b) => a - b);

  for (const [start, end] of sorted) {
    // Самая рано освобождающаяся комната уже свободна к моменту start —
    // переиспользуем её: снимаем старое время окончания
    if (!rooms.isEmpty() && rooms.peek() <= start) {
      rooms.pop();
    }

    // Занимаем комнату (либо освободившуюся, либо новую)
    rooms.push(end);
  }

  // Размер кучи — максимальное число одновременно занятых комнат
  return rooms.size;
}
```

### Разбор

- **Достаточно снять одну комнату за итерацию.** Даже если освободилось несколько, для текущей встречи нужна ровно одна; остальные освободятся на следующих итерациях. Это неочевидно и стоит проговорить.
- **`rooms.peek() <= start`** — нестрогое сравнение: встреча, заканчивающаяся ровно в момент начала следующей, не конфликтует. Уточните у интервьюера.
- **Размер кучи как ответ** — куча никогда не уменьшается ниже максимума занятости.

Время **O(n log n)**, память **O(n)**.

## Задача 6. Медиана потока данных

**Условие.** Числа приходят по одному. После каждого нужно уметь выдать медиану всех полученных.

**Медиана** — средний элемент отсортированной последовательности; при чётном количестве — среднее двух средних.

### Ход мысли

Хранить отсортированный массив — вставка O(n).

Приём — **две кучи**. Делим числа пополам:

- **макс**-куча `low` хранит меньшую половину, её корень — наибольший из маленьких
- **мин**-куча `high` хранит бо́льшую половину, её корень — наименьший из больших

Медиана всегда находится на стыке — в корне одной из куч. Нужно лишь поддерживать баланс размеров.

### Решение

```js
/**
 * Медиана потока чисел.
 */
class MedianFinder {
  constructor() {
    // Меньшая половина, макс-куча: корень — самое большое из маленьких
    this.low = new MinHeap((a, b) => b - a);
    // Бо́льшая половина, мин-куча: корень — самое маленькое из больших
    this.high = new MinHeap((a, b) => a - b);
  }

  /**
   * Добавить число. O(log n).
   * @param {number} num
   */
  addNum(num) {
    // Шаг 1: кладём всегда в low
    this.low.push(num);

    // Шаг 2: перекладываем максимум из low в high.
    // Это гарантирует порядок: всё в low не больше всего в high
    this.high.push(this.low.pop());

    // Шаг 3: восстанавливаем баланс размеров.
    // Договорённость: low может быть на один элемент больше high
    if (this.high.size > this.low.size) {
      this.low.push(this.high.pop());
    }
  }

  /**
   * Текущая медиана. O(1).
   * @returns {number}
   */
  findMedian() {
    // Нечётное количество — медиана в корне большей кучи
    if (this.low.size > this.high.size) {
      return this.low.peek();
    }
    // Чётное — среднее двух корней
    return (this.low.peek() + this.high.peek()) / 2;
  }
}
```

### Разбор

- **Трёхшаговая схема добавления** — то, что делает решение простым. Прямая проверка «в какую кучу класть» требует разбора случаев и легко ломается; перекладывание через `low → high → low` работает всегда.
- **Инверсия компаратора** `(a, b) => b - a` — вот зачем компаратор вынесен в конструктор.
- **Договорённость о размерах** («low может быть больше на один») должна соблюдаться и в `addNum`, и в `findMedian`. Рассогласование здесь — источник ошибок.

Время: `addNum` — **O(log n)**, `findMedian` — **O(1)**. Память **O(n)**.

Это одна из самых красивых задач на кучи. Если разберёте её до состояния «могу объяснить, почему трёх шагов достаточно» — тема освоена.

## Ещё жадные задачи

### Прыжки по массиву

**Условие.** `nums[i]` — максимальная длина прыжка из позиции `i`. Можно ли добраться до конца?

```js
/**
 * Достижим ли последний индекс массива.
 * @param {number[]} nums — максимальная длина прыжка из каждой позиции
 * @returns {boolean}
 */
function canJump(nums) {
  // Самый дальний индекс, до которого можем добраться
  let maxReach = 0;

  for (let i = 0; i < nums.length; i++) {
    // Досюда дойти не можем — дальше идти бессмысленно
    if (i > maxReach) return false;

    // Обновляем рекорд достижимости
    maxReach = Math.max(maxReach, i + nums[i]);

    // Уже достаём до конца — можно не досматривать
    if (maxReach >= nums.length - 1) return true;
  }

  return true;
}
```

**Почему жадность корректна.** Если позиция достижима, то достижимы и все позиции до неё — прыжок можно укоротить. Поэтому достаточно отслеживать одну величину, максимальную достижимость, не перебирая маршруты.

Время **O(n)**, память **O(1)**.

### Заправки на маршруте

**Условие.** Круговой маршрут из n заправок. `gas[i]` — топливо на i-й, `cost[i]` — расход до следующей. С какой заправки начать, чтобы объехать круг? Гарантируется, что решение единственно или его нет.

```js
/**
 * Индекс стартовой заправки, или -1.
 * @param {number[]} gas
 * @param {number[]} cost
 * @returns {number}
 */
function canCompleteCircuit(gas, cost) {
  let totalTank = 0;    // суммарный баланс по всему кругу
  let currentTank = 0;  // баланс от текущего кандидата на старт
  let start = 0;

  for (let i = 0; i < gas.length; i++) {
    const diff = gas[i] - cost[i];
    totalTank += diff;
    currentTank += diff;

    // Бак ушёл в минус — ни одна заправка от start до i не годится
    // как стартовая, потому что каждая из них дала бы ещё меньший запас.
    // Пробуем следующую за i
    if (currentTank < 0) {
      start = i + 1;
      currentTank = 0;
    }
  }

  // Если суммарного топлива не хватает на круг — решения нет вовсе
  return totalTank >= 0 ? start : -1;
}
```

**Ключевое наблюдение**, ради которого задача и существует: если от `start` не удалось дойти до `i`, то не удастся и ни от одной промежуточной точки. Поэтому одного прохода достаточно вместо O(n²).

Время **O(n)**, память **O(1)**.

## Типичные ошибки

1. **Жадность применена без обоснования** там, где нужно ДП.
2. **Неверный критерий сортировки.** «По началу» вместо «по концу» в задачах на интервалы.
3. **Мин-куча вместо макс-кучи** и наоборот. Проверьте на примере из 3 элементов.
4. **Обмен с бо́льшим ребёнком** в `siftDown`.
5. **Забыта проверка границ** `left < n` в `siftDown` — обращение к `undefined`.
6. **Сортировка вместо кучи** при большом n и малом k — рабочее, но не оптимальное решение.
7. **`Math.sqrt` там, где хватает квадрата расстояния.**
8. **Мутация входного массива** сортировкой без копии.

## Чеклист

- «Максимальное/минимальное количество, выбирая по одному» → попробуйте жадность, но обоснуйте
- Задача на интервалы → почти всегда сортировка по концу (выбор) или по началу (слияние)
- «k наибольших / наименьших / ближайших» → куча размера k с инвертированным компаратором
- «Слить k последовательностей» → куча из k голов
- «Медиана потока», «динамический максимум» → две кучи
- Жадность даёт неверный ответ на маленьком примере → переходите к ДП
- Нужна куча → напишите `MinHeap` с компаратором, одна реализация покроет все случаи

## Задачи для тренировки

1. **Раздача конфет детям по рейтингу** — два прохода жадности.
2. **Минимальное число прыжков до конца** — усложнение `canJump`.
3. **Реорганизация строки** так, чтобы одинаковые символы не стояли рядом — куча по частоте.
4. **Топ-k частых элементов** — частотный словарь плюс куча.
5. **Последний вес камня** — макс-куча, простая.
6. **Планировщик задач с охлаждением** — жадность плюс подсчёт частот, трудная.
7. **Максимальная прибыль от акций II** — жадность в одну строку.
