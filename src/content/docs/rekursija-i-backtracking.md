Рекурсия — не приём для отдельного класса задач, а способ мышления, на котором держатся деревья, графы, сортировки и динамическое программирование. Перебор с возвратом — её самое мощное применение.

## Рекурсия

**Рекурсия** — приём, при котором функция вызывает сама себя для решения уменьшенной версии той же задачи.

У любой корректной рекурсии есть две части:

- **База (base case)** — случай, который решается напрямую, без рекурсивного вызова. Без базы рекурсия не остановится.
- **Шаг (recursive case)** — сведение задачи к меньшей и вызов себя. Задача обязана **уменьшаться**, иначе база никогда не будет достигнута.

```js
/**
 * Факториал числа n.
 * @param {number} n — неотрицательное целое
 * @returns {number}
 */
function factorial(n) {
  if (n <= 1) return 1;          // база: 0! = 1! = 1
  return n * factorial(n - 1);   // шаг: задача уменьшается на единицу
}
```

### Как это выполняется

**Стек вызовов (call stack)** — структура, в которой движок хранит незавершённые вызовы. Каждый вызов кладёт на стек **кадр (frame)** со своими локальными переменными и точкой возврата.

Для `factorial(3)`:

```
factorial(3) → ждёт factorial(2)
  factorial(2) → ждёт factorial(1)
    factorial(1) → возвращает 1          ← база достигнута
  factorial(2) → возвращает 2 * 1 = 2
factorial(3) → возвращает 3 * 2 = 6
```

:::caution
**Лимит глубины рекурсии в JavaScript — примерно 10 000 вызовов** (точное число зависит от движка и размера кадра). При превышении бросается `RangeError: Maximum call stack size exceeded`.

Практический вывод: если в условии `n` может достигать 10⁵ (а это типичное ограничение), **рекурсия по элементам массива или по длине списка небезопасна**. Скажите это вслух и предложите итеративную версию или явный стек.

Оптимизации хвостовой рекурсии в V8 нет, несмотря на то что она описана в стандарте ES2015. Рассчитывать на неё нельзя.

:::
### Как думать рекурсивно

Главная ошибка новичка — пытаться мысленно «раскрутить» всю цепочку вызовов. Так рекурсию не написать: в голове не помещается.

Правильный способ — **доверие рекурсии**:

1. Сформулируйте, **что именно** возвращает функция. Одним предложением. Точно.
2. Считайте, что для меньших входов она уже работает правильно. Не проверяйте это мысленно — просто примите.
3. Напишите, как из ответов для меньших входов получить ответ для текущего.
4. Отдельно обработайте базу.

Например, «`maxDepth(node)` возвращает высоту поддерева с корнем `node`». Тогда шаг очевиден: `1 + max(maxDepth(left), maxDepth(right))`, база — пустое дерево даёт 0. Раскручивать вручную ничего не нужно.

Именно этот навык проверяется задачами на деревья и перебор.

### Стоимость рекурсии

Время считается так: **количество вызовов × работа в одном вызове**.

Память — **глубина рекурсии** (максимальная высота стека), а не число вызовов.

```js
// Наивные числа Фибоначчи
function fib(n) {
  if (n <= 1) return n;
  return fib(n - 1) + fib(n - 2);
}
```

Здесь **O(2ⁿ)** времени: каждый вызов порождает два, дерево вызовов удваивается на каждом уровне. `fib(40)` считается секунды, `fib(50)` — часы.

Причина — **перекрывающиеся подзадачи**: `fib(35)` вычисляется многократно. Лечится мемоизацией, см. [Динамическое программирование](../dinamicheskoe-programmirovanie/).

### Мемоизация

**Мемоизация** — кеширование результатов функции по её аргументам.

```js
/**
 * Числа Фибоначчи с кешем.
 * @param {number} n
 * @param {Map<number, number>} memo — кеш, создаётся один раз
 * @returns {number}
 */
function fibMemo(n, memo = new Map()) {
  if (n <= 1) return n;

  // Уже считали — отдаём готовое
  if (memo.has(n)) return memo.get(n);

  const result = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
  memo.set(n, result);   // запоминаем перед возвратом

  return result;
}
```

Сложность падает с O(2ⁿ) до **O(n)**: каждое значение вычисляется ровно один раз.

:::caution
**`memo = new Map()` в параметрах по умолчанию** создаёт новый кеш при **каждом** внешнем вызове. Внутри одного вычисления это работает (мы передаём `memo` дальше явно), но между вызовами кеш не переиспользуется.

Если нужен общий кеш — выносите его наружу через замыкание:

```js
const fib = (() => {
  const memo = new Map();
  return function f(n) {
    if (n <= 1) return n;
    if (memo.has(n)) return memo.get(n);
    const result = f(n - 1) + f(n - 2);
    memo.set(n, result);
    return result;
  };
})();
```

Здесь используется **IIFE** (immediately invoked function expression) — функция, объявленная и тут же вызванная. Она создаёт область видимости для `memo`, недоступную снаружи.

:::
## Перебор с возвратом

**Перебор с возвратом (backtracking)** — систематический перебор всех вариантов, при котором мы строим решение по шагам и **откатываем** шаг, когда он оказался неудачным или исчерпанным.

Метафора: лабиринт. Идём по коридору, упёрлись в тупик — возвращаемся к последней развилке и пробуем другой поворот.

Отличие от простой рекурсии — в **отмене выбора**: после рекурсивного вызова мы возвращаем состояние к тому, каким оно было до шага.

### Универсальный шаблон

Все задачи на перебор пишутся по одной схеме. Выучите её — дальше меняются только детали.

```js
function backtrackTemplate(input) {
  const results = [];
  const current = [];   // строящееся решение

  /**
   * @param {*} state — что осталось перебрать / где мы находимся
   */
  function backtrack(state) {
    // 1. УСЛОВИЕ ЗАВЕРШЕНИЯ: решение готово
    if (isComplete(state)) {
      results.push([...current]);   // КОПИЯ, не ссылка!
      return;
    }

    // 2. ПЕРЕБОР ВАРИАНТОВ на текущем шаге
    for (const choice of getChoices(state)) {
      // 3. ОТСЕЧЕНИЕ: вариант заведомо не приведёт к решению
      if (!isValid(choice, current)) continue;

      // 4. ВЫБОР
      current.push(choice);

      // 5. РЕКУРСИЯ — исследуем ветку с этим выбором
      backtrack(nextState(state, choice));

      // 6. ОТКАТ — снимаем выбор, чтобы попробовать следующий
      current.pop();
    }
  }

  backtrack(initialState);
  return results;
}
```

:::tip
**Три детали, на которых ломаются почти все:**

1. **`results.push([...current])`** — обязательно копия. `current` мутируется дальше по ходу перебора, и если положить ссылку, в результате окажутся одинаковые (и пустые) массивы. Это ошибка номер один в теме.
2. **`current.pop()` строго после рекурсии** — симметрично `push`. Забыли — состояние «протечёт» в соседние ветки.
3. **Отсечение (pruning)** — то, что превращает неподъёмный перебор в проходящий по времени. Чем раньше отсекаем, тем лучше.

:::
## Задача 1. Все подмножества

**Условие.** Вернуть все подмножества массива уникальных чисел.

Пример: `[1, 2, 3]` → `[[], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]]`.

### Ход мысли

Для каждого элемента есть ровно два варианта: взять или не взять. Значит, подмножеств всего 2ⁿ, и меньше быть не может — ответ сам по себе такого размера.

Реализуем перебор по позициям: на шаге `start` решаем, какой элемент добавить следующим.

### Решение

```js
/**
 * Все подмножества массива.
 * @param {number[]} nums — уникальные числа
 * @returns {number[][]}
 */
function subsets(nums) {
  const results = [];
  const current = [];

  /**
   * @param {number} start — индекс, с которого можно брать элементы.
   *        Он не даёт перебрать одно и то же подмножество
   *        в разном порядке ([1,2] и [2,1])
   */
  function backtrack(start) {
    // Каждое промежуточное состояние — само по себе валидное подмножество.
    // Поэтому записываем его сразу, без условия завершения
    results.push([...current]);

    for (let i = start; i < nums.length; i++) {
      current.push(nums[i]);      // выбираем элемент i
      backtrack(i + 1);           // дальше берём только из элементов ПОСЛЕ i
      current.pop();              // откатываем выбор
    }
  }

  backtrack(0);
  return results;
}
```

### Разбор

- **`results.push([...current])` в начале, а не в базе** — особенность именно этой задачи: подмножеством является любой префикс построения.
- **Параметр `start` и `backtrack(i + 1)`** — механизм борьбы с перестановками. Элементы берутся строго слева направо, поэтому `[2, 1]` не возникнет.
- **Базы как отдельного `if` нет** — цикл `for` сам не выполнится, когда `start === nums.length`. Рекурсия остановится естественным образом.
- **`[...current]`** — спред создаёт **поверхностную** копию. Для массива чисел этого достаточно.

### Сложность

Время **O(n · 2ⁿ)** — 2ⁿ подмножеств, копирование каждого до O(n). Память **O(n)** на рекурсию, не считая результата.

Экспонента здесь не признак плохого решения: размер ответа сам экспоненциален, быстрее не бывает.

## Задача 2. Все перестановки

**Условие.** Вернуть все перестановки массива уникальных чисел.

Пример: `[1,2,3]` → 6 перестановок.

### Ход мысли

В отличие от подмножеств, здесь порядок важен и используются **все** элементы. Значит, на каждом шаге доступны все ещё не использованные.

Нужно отслеживать использованные — массивом флагов.

### Решение

```js
/**
 * Все перестановки массива.
 * @param {number[]} nums — уникальные числа
 * @returns {number[][]}
 */
function permute(nums) {
  const results = [];
  const current = [];

  // used[i] === true, если nums[i] уже стоит в current
  const used = new Array(nums.length).fill(false);

  function backtrack() {
    // Условие завершения: набрали перестановку полной длины
    if (current.length === nums.length) {
      results.push([...current]);
      return;
    }

    for (let i = 0; i < nums.length; i++) {
      if (used[i]) continue;   // элемент уже в текущей перестановке

      // Выбор: помечаем и добавляем
      used[i] = true;
      current.push(nums[i]);

      backtrack();

      // Откат: снимаем ОБА изменения, в обратном порядке
      current.pop();
      used[i] = false;
    }
  }

  backtrack();
  return results;
}
```

### Разбор

- **Цикл с нуля, а не с `start`** — принципиальное отличие от подмножеств. Здесь `[1,2]` и `[2,1]` это разные ответы, поэтому ограничивать порядок нельзя.
- **Откат снимает оба изменения.** Забыть `used[i] = false` — частая ошибка; она не вызывает падения, просто часть перестановок потеряется.
- **`continue` вместо вложенного `if`** — плоский код читается легче, особенно когда условий отсечения несколько.

### Сложность

Время **O(n · n!)** — n! перестановок, копирование каждой O(n). Память **O(n)**.

:::note
**Если в массиве есть дубликаты**, схема меняется: массив сортируют и добавляют отсечение

```js
if (i > 0 && nums[i] === nums[i - 1] && !used[i - 1]) continue;
```

Условие означает: «не начинай новую ветку с дубликата, если его близнец в этой позиции ещё не использован». Так каждая уникальная перестановка строится ровно один раз. Приём общий для всех задач с дубликатами — и в подмножествах, и в комбинациях.

:::
## Задача 3. Комбинационная сумма

**Условие.** Дан массив различных положительных чисел и целевая сумма. Найти все комбинации, дающие в сумме target. Каждое число можно брать **неограниченно много раз**.

Пример: `candidates = [2, 3, 6, 7]`, `target = 7` → `[[2,2,3], [7]]`.

### Ход мысли

Отличие от подмножеств: элемент можно взять повторно. Значит, рекурсивный вызов идёт с `i`, а не с `i + 1`.

Отсечение: как только остаток стал отрицательным, ветку можно бросать. Сортировка кандидатов позволяет отсекать ещё раньше — через `break`.

### Решение

```js
/**
 * Все комбинации чисел, дающие в сумме target.
 * Числа можно использовать повторно.
 * @param {number[]} candidates — различные положительные числа
 * @param {number} target
 * @returns {number[][]}
 */
function combinationSum(candidates, target) {
  const results = [];
  const current = [];

  // Сортировка позволяет прервать цикл на первом слишком большом числе:
  // все следующие тоже не подойдут
  const sorted = [...candidates].sort((a, b) => a - b);

  /**
   * @param {number} start — с какого кандидата можно брать
   * @param {number} remaining — сколько осталось набрать
   */
  function backtrack(start, remaining) {
    // База: набрали ровно target
    if (remaining === 0) {
      results.push([...current]);
      return;
    }

    for (let i = start; i < sorted.length; i++) {
      // Отсечение: кандидат больше остатка. Массив отсортирован,
      // поэтому все следующие тоже больше — прерываем цикл целиком.
      // Именно break, не continue — в этом смысл сортировки
      if (sorted[i] > remaining) break;

      current.push(sorted[i]);

      // Передаём i, а НЕ i + 1: тот же элемент можно взять снова
      backtrack(i, remaining - sorted[i]);

      current.pop();
    }
  }

  backtrack(0, target);
  return results;
}
```

### Разбор

- **`backtrack(i, ...)` вместо `backtrack(i + 1, ...)`** — единственная строка, разрешающая повторы. Одновременно `start` не даёт получить `[2,3]` и `[3,2]` как разные ответы.
- **`break` вместо `continue`** — работает только благодаря сортировке. Это заметное ускорение, и о нём стоит сказать вслух.
- **Отрицательный остаток невозможен** — отсечение срабатывает раньше. Поэтому базы `remaining < 0` не нужно.

### Сложность

В худшем случае экспоненциальная — точная оценка зависит от данных. Формально верхняя граница `O(n^(target/min))`. На собеседовании достаточно сказать «экспоненциальная, с отсечениями по отсортированному массиву».

## Задача 4. Буквенные комбинации номера телефона

**Условие.** По цифрам на телефонной клавиатуре вернуть все возможные буквенные комбинации.

Пример: `'23'` → `['ad','ae','af','bd','be','bf','cd','ce','cf']`.

### Решение

```js
/**
 * Все буквенные комбинации для цифр телефонной клавиатуры.
 * @param {string} digits — строка из цифр 2-9
 * @returns {string[]}
 */
function letterCombinations(digits) {
  if (digits.length === 0) return [];   // особый случай: пустой вход → пустой ответ

  const KEYPAD = {
    '2': 'abc', '3': 'def', '4': 'ghi', '5': 'jkl',
    '6': 'mno', '7': 'pqrs', '8': 'tuv', '9': 'wxyz',
  };

  const results = [];
  const current = [];   // массив символов, а не строка — см. разбор

  /**
   * @param {number} index — какую цифру обрабатываем
   */
  function backtrack(index) {
    // База: обработали все цифры — комбинация готова
    if (index === digits.length) {
      results.push(current.join(''));
      return;
    }

    const letters = KEYPAD[digits[index]];

    for (const letter of letters) {
      current.push(letter);
      backtrack(index + 1);   // переходим к следующей цифре
      current.pop();
    }
  }

  backtrack(0);
  return results;
}
```

### Разбор

- **Проверка на пустой вход в начале** — без неё функция вернула бы `['']`, что неверно по условию. Такие краевые случаи нужно проговаривать до написания кода.
- **`current` как массив символов** — можно было бы передавать строку параметром (`backtrack(index, prefix + letter)`), и откат стал бы не нужен, потому что строки неизменяемы. Но это создаёт новую строку на каждом шаге. Массив плюс `join` в базе эффективнее.
- **Один уровень рекурсии на одну цифру** — глубина равна длине `digits`, а не числу букв.

### Сложность

Время **O(4ⁿ · n)**, где n — количество цифр: до 4 букв на цифру, и `join` стоит O(n). Память **O(n)** на рекурсию.

## Задача 5. Восемь ферзей

**Условие.** Расставить n ферзей на доске n×n так, чтобы они не били друг друга. Вернуть все расстановки.

Классическая задача на перебор с отсечениями — именно она обычно и иллюстрирует тему.

### Ход мысли

Ферзь бьёт по горизонтали, вертикали и обеим диагоналям. Значит, в каждой строке ровно один ферзь — можно перебирать построчно, и вертикаль отпадает автоматически.

Остаётся проверять столбец и две диагонали. Наивная проверка «пройтись по уже поставленным» — O(n) на проверку. Лучше — три множества:

- занятые **столбцы**
- занятые диагонали «↘», у которых `row - col` постоянна
- занятые диагонали «↙», у которых `row + col` постоянна

Проверка становится O(1).

### Решение

```js
/**
 * Все расстановки n ферзей на доске n×n.
 * @param {number} n
 * @returns {string[][]} каждая расстановка — массив строк доски
 */
function solveNQueens(n) {
  const results = [];

  // queens[row] = col — в какой колонке стоит ферзь строки row
  const queens = new Array(n).fill(-1);

  const cols = new Set();      // занятые столбцы
  const diag1 = new Set();     // занятые диагонали row - col
  const diag2 = new Set();     // занятые диагонали row + col

  /**
   * @param {number} row — строка, в которую ставим ферзя
   */
  function backtrack(row) {
    // База: расставили ферзей во всех строках
    if (row === n) {
      results.push(buildBoard(queens, n));
      return;
    }

    for (let col = 0; col < n; col++) {
      const d1 = row - col;
      const d2 = row + col;

      // Отсечение за O(1): клетка под боем
      if (cols.has(col) || diag1.has(d1) || diag2.has(d2)) continue;

      // Выбор: ставим ферзя и помечаем три линии
      queens[row] = col;
      cols.add(col);
      diag1.add(d1);
      diag2.add(d2);

      backtrack(row + 1);

      // Откат: снимаем ферзя и освобождаем линии.
      // Все четыре изменения должны быть отменены
      cols.delete(col);
      diag1.delete(d1);
      diag2.delete(d2);
      queens[row] = -1;
    }
  }

  backtrack(0);
  return results;
}

/**
 * Превращает массив позиций в текстовое представление доски.
 * @param {number[]} queens — queens[row] = col
 * @param {number} n
 * @returns {string[]}
 */
function buildBoard(queens, n) {
  return queens.map(col =>
    // repeat(k) повторяет строку k раз.
    // Слева от ферзя col точек, сам ферзь, справа остальные точки
    '.'.repeat(col) + 'Q' + '.'.repeat(n - col - 1)
  );
}
```

### Разбор

- **`row - col` и `row + col` как идентификаторы диагоналей** — главная находка решения. Для клеток одной диагонали «↘» разность постоянна, для «↙» — сумма. Проверьте на доске 3×3: клетки (0,0), (1,1), (2,2) дают разность 0.
- **`row - col` может быть отрицательным** — для `Set` это не проблема, ключом может быть любое число. В решении через массив пришлось бы добавлять смещение `n - 1`.
- **Откат снимает четыре изменения** — по одному на каждое `add`/присваивание. Пропуск любого ломает перебор.
- **Одна строка — один ферзь** — это структурное отсечение: вместо перебора всех C(n², n) расстановок мы перебираем только nⁿ, а с отсечениями ещё меньше.

### Сложность

Верхняя оценка **O(n!)** — в первой строке n вариантов, во второй не больше n−1 и так далее. Реально отсечения срезают дерево гораздо сильнее. Память **O(n)**.

## Задача 6. Генерация правильных скобочных последовательностей

**Условие.** Сгенерировать все корректные последовательности из n пар скобок.

Пример: `n = 2` → `['(())', '()()']`.

### Ход мысли

Можно сгенерировать все 2²ⁿ строк и отфильтровать валидные — но это расточительно. Лучше строить **только корректные**, отсекая на лету.

Два правила:

- открывающую скобку можно ставить, пока их меньше n
- закрывающую — только если открытых больше, чем закрытых (иначе последовательность станет некорректной и уже не исправится)

### Решение

```js
/**
 * Все корректные скобочные последовательности из n пар.
 * @param {number} n
 * @returns {string[]}
 */
function generateParenthesis(n) {
  const results = [];
  const current = [];

  /**
   * @param {number} open — сколько открывающих уже поставлено
   * @param {number} close — сколько закрывающих уже поставлено
   */
  function backtrack(open, close) {
    // База: использовали все 2n позиций
    if (current.length === 2 * n) {
      results.push(current.join(''));
      return;
    }

    // Вариант 1: поставить открывающую, если лимит не исчерпан
    if (open < n) {
      current.push('(');
      backtrack(open + 1, close);
      current.pop();
    }

    // Вариант 2: поставить закрывающую, только если есть что закрывать.
    // Это условие и есть отсечение — оно не даёт построить ')...'
    if (close < open) {
      current.push(')');
      backtrack(open, close + 1);
      current.pop();
    }
  }

  backtrack(0, 0);
  return results;
}
```

### Разбор

- **Два `if` вместо цикла** — вариантов на шаге ровно два, цикл не нужен. Шаблон перебора гибок: «перебор вариантов» не обязан быть циклом.
- **`close < open`** — самое важное условие. Оно гарантирует, что ни один префикс не становится некорректным, поэтому фильтрация в конце не требуется.
- **Каждая ветка со своим `push`/`pop`** — симметрия соблюдена в обоих блоках.

### Сложность

Количество ответов — n-е **число Каталана**, примерно `4ⁿ / (n^1.5 · √π)`. Время **O(4ⁿ / √n)**. Достаточно сказать «экспоненциальная, равна числу Каталана».

## Когда перебор — правильный ответ

Экспоненциальная сложность пугает, но иногда она неизбежна и ожидаема.

Ориентир по размеру входа (подробнее — на [корневой странице](../)):

| **n** | **Что допустимо** |
| --- | --- |
| до 10–12 | n! — перестановки |
| до 20–25 | 2ⁿ — подмножества, маски |
| до 100 | n³ |
| до 10⁵ | n log n |
Если в условии стоит «n ≤ 20» или «вернуть **все** варианты» — это прямое указание на перебор. Искать полиномиальное решение в таком случае бессмысленно: его не существует либо оно не требуется.

## Типичные ошибки

1. **`results.push(current)` вместо `results.push([...current])`** — в результате окажутся ссылки на один и тот же мутирующийся массив. Ошибка номер один.
2. **Забыт откат** — `pop`, `used[i] = false`, `set.delete(...)`. Состояние протекает в соседние ветки.
3. **Откат снял не все изменения** — если на шаге менялось три вещи, отменить нужно три.
4. **Нет базы** или база недостижима — бесконечная рекурсия.
5. **`start` против цикла с нуля** — перепутаны подмножества (нужен `start`) и перестановки (нужен весь диапазон).
6. **`i` против `i + 1`** — разрешены ли повторы элемента.
7. **Дубликаты во входе** не обработаны — нужна сортировка плюс отсечение.
8. **Нет отсечений** — перебор, который мог пройти за секунду, работает минуты.
9. **Слишком глубокая рекурсия** — при n порядка 10⁵ переполнение стека.

## Чеклист

- «Вернуть все варианты / комбинации / расстановки» → перебор с возвратом
- n ≤ 20 в ограничениях → почти наверняка перебор
- Порядок не важен, элементы не повторяются → подмножества, параметр `start`
- Порядок важен → перестановки, массив `used`
- Элемент можно брать несколько раз → рекурсия с `i`, а не `i + 1`
- Во входе дубликаты → отсортировать и добавить отсечение по соседу
- Перебор слишком долгий → искать отсечение; если его нет — задача на ДП
- Всегда: копия при записи результата, симметричный откат после рекурсии
