Структура, которой почти не пользуются во фронтенде, но которую регулярно спрашивают на собеседованиях. Задачи на списки проверяют аккуратность работы со ссылками — и почти все решаются двумя-тремя стандартными приёмами.

← [К оглавлению](../)

## Что это

**Связный список (linked list)** — последовательность узлов, где каждый узел хранит значение и ссылку на следующий узел.

```
head → [1|•] → [2|•] → [3|•] → null
```

**Узел (node)** — объект с полями `val` (значение) и `next` (ссылка на следующий узел или `null`).
**Голова (head)** — первый узел. Ссылка на него — единственный вход в список.
**Хвост (tail)** — последний узел, у него `next === null`.

```js
/**
 * Узел односвязного списка.
 */
class ListNode {
  /**
   * @param {*} val — значение узла
   * @param {ListNode|null} next — ссылка на следующий узел
   */
  constructor(val = 0, next = null) {
    this.val = val;
    this.next = next;
  }
}

// Построение списка 1 → 2 → 3
const head = new ListNode(1, new ListNode(2, new ListNode(3)));
```

**`val = 0, next = null`** — значения параметров по умолчанию: если аргумент не передан, используется указанное значение.

### Виды списков

- **Односвязный** — только `next`. Чаще всего именно он и встречается.
- **Двусвязный** — есть и `next`, и `prev`. Позволяет ходить в обе стороны и удалять узел за O(1), зная только его.
- **Циклический** — хвост ссылается обратно на какой-то узел, `null` в конце нет.

## Массив против списка

| **Операция** | **Массив** | **Связный список** |
| --- | --- | --- |
| Доступ по индексу | O(1) | O(n) — нужно идти от головы |
| Вставка в начало | O(n) | O(1) |
| Вставка в конец | O(1) | O(n), либо O(1) с хранением tail |
| Удаление узла, когда он уже найден | O(n) | O(1) |
| Поиск значения | O(n) | O(n) |
| Память | компактно | накладные расходы на ссылки |
Практический вывод: список хорош, когда много вставок и удалений в середине и не нужен доступ по индексу.

:::note
Во фронтенде вы со списками почти не сталкиваетесь — их место занимают массивы. Но идея «узел со ссылкой на следующий» лежит в основе деревьев, графов и внутреннего устройства React Fiber. Так что тема не такая абстрактная, как кажется.

:::
## Три приёма, решающие большинство задач

### Приём 1. Фиктивный узел (dummy node)

**Проблема.** Операции с головой списка — особый случай: у головы нет предыдущего узла, поэтому её удаление или вставка перед ней требуют отдельной ветки кода.

**Решение.** Завести фиктивный узел, который стоит **перед** головой. Тогда у настоящей головы появляется «предыдущий», и все случаи обрабатываются единообразно.

```js
const dummy = new ListNode(0, head);   // dummy → head → ...
// ... работаем, не думая про особый случай головы ...
return dummy.next;   // настоящая голова — возможно, уже другая
```

Это самый полезный приём темы. Он убирает половину краевых случаев.

### Приём 2. Два указателя: быстрый и медленный

`slow` двигается на один узел за шаг, `fast` — на два. Когда `fast` достигает конца, `slow` находится ровно в середине.

Тот же приём находит цикл: в циклическом списке быстрый рано или поздно догонит медленного.

### Приём 3. Разворот через три указателя

Стандартная процедура разворота списка. Разбирается ниже.

## Задача 1. Развернуть список

**Условие.** Развернуть односвязный список: `1→2→3→null` превращается в `3→2→1→null`.

### Ход мысли

Нужно у каждого узла переставить `next` на предыдущий. Проблема: как только мы переписали `node.next`, мы теряем доступ к остатку списка. Поэтому сохраняем следующий узел **до** перезаписи.

Отсюда три указателя: `prev` (куда разворачиваем), `current` (кого разворачиваем), `next` (что сохранить, чтобы не потерять).

### Решение

```js
/**
 * Разворачивает односвязный список.
 * @param {ListNode|null} head
 * @returns {ListNode|null} новая голова
 */
function reverseList(head) {
  let prev = null;      // до первого узла ничего нет — это будущий хвост
  let current = head;

  while (current !== null) {
    // 1. Запоминаем следующий узел ДО того, как порвём связь
    const next = current.next;

    // 2. Разворачиваем ссылку текущего узла назад
    current.next = prev;

    // 3. Сдвигаем оба указателя на шаг вперёд
    prev = current;
    current = next;
  }

  // Цикл закончился при current === null,
  // значит prev указывает на последний обработанный узел — новую голову
  return prev;
}
```

### Разбор

- **Порядок трёх шагов нельзя менять.** Если сначала выполнить `current.next = prev`, а потом попытаться взять `current.next` — получим `prev`, и остаток списка будет потерян навсегда.
- **`prev = null` изначально** — бывшая голова становится хвостом, и её `next` должен стать `null`. Это получается автоматически на первой итерации.
- **Возвращаем `prev`, а не `current`** — `current` уже `null`.

### Сложность

Время **O(n)**, память **O(1)**.

:::tip
Этот цикл стоит выучить наизусть, как таблицу умножения. Он встречается сам по себе, входит в «проверить палиндромность списка», в «перегруппировать список» и во множество других задач. Тренируйте до состояния «пишу не задумываясь».

:::
### Рекурсивный вариант

```js
function reverseListRecursive(head) {
  // База: пустой список или один узел — разворачивать нечего
  if (head === null || head.next === null) return head;

  // Рекурсивно разворачиваем ХВОСТ. newHead — голова развёрнутого хвоста,
  // то есть последний узел исходного списка
  const newHead = reverseListRecursive(head.next);

  // head.next — это узел, который в развёрнутом хвосте стал последним.
  // Заставляем его ссылаться назад на head
  head.next.next = head;
  head.next = null;   // head становится новым хвостом

  return newHead;   // голова не меняется на всех уровнях рекурсии
}
```

Память **O(n)** на стек вызовов — поэтому итеративная версия лучше. Но рекурсивную полезно уметь объяснить: строка `head.next.next = head` — хороший тест на понимание ссылок.

## Задача 2. Найти середину списка

**Условие.** Вернуть средний узел. При чётной длине — второй из двух средних.

### Решение

```js
/**
 * Средний узел списка.
 * @param {ListNode|null} head
 * @returns {ListNode|null}
 */
function middleNode(head) {
  let slow = head;
  let fast = head;

  // fast движется вдвое быстрее.
  // Проверяем и fast, и fast.next — иначе fast.next.next
  // упадёт с ошибкой при нечётной длине
  while (fast !== null && fast.next !== null) {
    slow = slow.next;
    fast = fast.next.next;
  }

  return slow;
}
```

### Разбор

- **Порядок проверок в `while`** важен: `fast !== null` должно идти первым. JS вычисляет `&&` слева направо и останавливается на первом ложном (**короткое замыкание**), поэтому `fast.next` не будет вычисляться при `fast === null`.
- **Чётная длина.** Для `1→2→3→4`: `slow` окажется на `3`. Если нужен первый из двух средних, используйте `while (fast.next !== null && fast.next.next !== null)`.

Время **O(n)**, память **O(1)**.

## Задача 3. Обнаружить цикл

**Условие.** Есть ли в списке цикл?

**Цикл** — ситуация, когда `next` какого-то узла ведёт на уже пройденный узел. Обход такого списка никогда не закончится.

### Ход мысли

Вариант через `Set` посещённых узлов очевиден и работает за O(n) времени и O(n) памяти.

Но есть решение за O(1) памяти — **алгоритм Флойда**, он же «черепаха и заяц». Если цикл есть, быстрый указатель обязательно догонит медленного: внутри цикла расстояние между ними сокращается на 1 за шаг, поэтому встреча неизбежна.

### Решение

```js
/**
 * Есть ли цикл в списке.
 * @param {ListNode|null} head
 * @returns {boolean}
 */
function hasCycle(head) {
  let slow = head;
  let fast = head;

  while (fast !== null && fast.next !== null) {
    slow = slow.next;          // шаг 1
    fast = fast.next.next;     // шаг 2

    // Сравниваем сами объекты-узлы по ссылке, а не по значению:
    // значения могут повторяться, а узел уникален
    if (slow === fast) return true;
  }

  // fast дошёл до null — список конечен
  return false;
}
```

### Поиск начала цикла

```js
/**
 * Узел, с которого начинается цикл, или null.
 * @param {ListNode|null} head
 * @returns {ListNode|null}
 */
function detectCycleStart(head) {
  let slow = head;
  let fast = head;

  // Фаза 1: ищем точку встречи
  while (fast !== null && fast.next !== null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow === fast) {
      // Фаза 2: один указатель возвращаем в голову,
      // дальше оба идут с одинаковой скоростью.
      // Встретятся ровно в начале цикла
      let ptr = head;
      while (ptr !== slow) {
        ptr = ptr.next;
        slow = slow.next;
      }
      return ptr;
    }
  }

  return null;
}
```

**Почему вторая фаза работает.** Пусть до начала цикла `a` шагов, а точка встречи находится в `b` шагах от начала цикла, длина цикла `c`. К моменту встречи медленный прошёл `a + b`, быстрый — вдвое больше, `2(a + b)`, и разница между ними кратна длине цикла: `a + b = k·c`. Отсюда `a = k·c − b` — то есть пройти `a` шагов от головы это то же самое, что пройти от точки встречи до начала цикла (возможно, сделав несколько полных кругов). Поэтому указатели встретятся именно там.

Проговорить это доказательство на собеседовании — сильный ход. Заучивать формулу без понимания смысла нет.

Время **O(n)**, память **O(1)**.

## Задача 4. Удалить n-й узел с конца

**Условие.** Удалить n-й узел, считая с конца, и вернуть голову.

Пример: `1→2→3→4→5`, `n = 2` → `1→2→3→5`.

### Ход мысли

Длина неизвестна, а второй проход делать не хочется. Приём: пустить два указателя с **разрывом в n узлов**. Когда быстрый дойдёт до конца, медленный будет ровно перед удаляемым.

Удаление головы — особый случай (`n` равно длине списка). Здесь и пригодится фиктивный узел.

### Решение

```js
/**
 * Удаляет n-й узел с конца списка.
 * @param {ListNode|null} head
 * @param {number} n — номер с конца, начиная с 1
 * @returns {ListNode|null} голова изменённого списка
 */
function removeNthFromEnd(head, n) {
  // Фиктивный узел убирает особый случай «удаляем голову»
  const dummy = new ListNode(0, head);

  let fast = dummy;
  let slow = dummy;

  // Разводим указатели на n + 1 шаг.
  // Именно +1, чтобы slow остановился ПЕРЕД удаляемым узлом:
  // для удаления нужен предыдущий
  for (let i = 0; i <= n; i++) {
    fast = fast.next;
  }

  // Двигаем оба, пока быстрый не выйдет за конец
  while (fast !== null) {
    fast = fast.next;
    slow = slow.next;
  }

  // slow.next — удаляемый узел. Перекидываем ссылку через него
  slow.next = slow.next.next;

  // Возвращаем dummy.next, а не head: если удалили голову,
  // head теперь указывает на выброшенный узел
  return dummy.next;
}
```

### Разбор

- **`i <= n`** в цикле — то есть `n + 1` итерация. Проверьте руками на списке `1→2`, `n = 2` (удаляем голову): `fast` пройдёт `dummy→1→2` и станет `null`... точнее, после трёх шагов окажется за пределами — цикл `while` не выполнится, `slow` останется на `dummy`, и `dummy.next` станет `2`. Верно.
- **`return dummy.next`** — обязательно. `return head` сломается при удалении головы.
- Если `n` больше длины списка, `fast = fast.next` упадёт. По условию такого не бывает, но уточнить у интервьюера стоит.

Время **O(n)** — один проход. Память **O(1)**.

## Задача 5. Слияние двух отсортированных списков

**Условие.** Даны два отсортированных списка. Слить их в один отсортированный.

### Решение

```js
/**
 * Сливает два отсортированных списка.
 * @param {ListNode|null} l1
 * @param {ListNode|null} l2
 * @returns {ListNode|null}
 */
function mergeTwoLists(l1, l2) {
  // Фиктивный узел избавляет от особого случая «первый элемент результата»
  const dummy = new ListNode(0);
  let tail = dummy;   // последний узел собираемого списка

  while (l1 !== null && l2 !== null) {
    if (l1.val <= l2.val) {
      tail.next = l1;    // присоединяем узел из первого списка
      l1 = l1.next;
    } else {
      tail.next = l2;
      l2 = l2.next;
    }
    tail = tail.next;    // хвост сдвигается на только что присоединённый узел
  }

  // Один список кончился — второй уже отсортирован,
  // присоединяем его остаток целиком одной ссылкой
  tail.next = (l1 !== null) ? l1 : l2;

  return dummy.next;
}
```

### Разбор

- **Узлы переиспользуются, новые не создаются** — мы только переставляем ссылки. Память O(1).
- **`tail.next = l1 !== null ? l1 : l2`** — элегантная концовка: в отличие от массивов, где остаток нужно копировать поэлементно, здесь достаточно одной ссылки.
- **`<=`** обеспечивает стабильность.

Время **O(n + m)**, память **O(1)**.

## Задача 6. Список — палиндром?

**Условие.** Проверить, читается ли список одинаково в обе стороны. Требуется O(1) памяти.

### Ход мысли

Собрать значения в массив и проверить двумя указателями — O(n) памяти. Для O(1) нужно комбинировать приёмы: найти середину, развернуть вторую половину, сравнить половины.

Эта задача — хороший пример того, как из трёх изученных приёмов собирается решение.

### Решение

```js
/**
 * Является ли список палиндромом. O(1) дополнительной памяти.
 * @param {ListNode|null} head
 * @returns {boolean}
 */
function isPalindromeList(head) {
  if (head === null || head.next === null) return true;

  // Шаг 1: находим середину (приём «быстрый и медленный»)
  let slow = head;
  let fast = head;
  while (fast.next !== null && fast.next.next !== null) {
    slow = slow.next;
    fast = fast.next.next;
  }
  // slow — последний узел первой половины

  // Шаг 2: разворачиваем вторую половину (приём «три указателя»)
  let second = reverseList(slow.next);

  // Шаг 3: сравниваем половины.
  // Вторая половина может быть короче на один узел — это нормально,
  // поэтому условием цикла берём именно её
  let first = head;
  let result = true;
  let iter = second;
  while (iter !== null) {
    if (first.val !== iter.val) {
      result = false;
      break;
    }
    first = first.next;
    iter = iter.next;
  }

  // Шаг 4: восстанавливаем список — хорошая практика,
  // функция-предикат не должна портить входные данные
  slow.next = reverseList(second);

  return result;
}
```

### Разбор

- **Композиция приёмов** — здесь переиспользуется `reverseList` из задачи 1. На собеседовании прямо скажите: «использую функцию разворота, которую уже написала».
- **Восстановление списка** в шаге 4 — деталь, которую почти никто не делает. Упомянуть её — заметный плюс: это разговор о побочных эффектах, а не только об алгоритме.
- **Условие цикла по второй половине** — при нечётной длине средний элемент не с чем сравнивать, и он корректно игнорируется.

Время **O(n)**, память **O(1)**.

## Типичные ошибки

1. **Потеря остатка списка.** Перезаписали `node.next`, не сохранив следующий узел. Всегда сохраняйте `next` до изменения.
2. **Возврат `head` вместо `dummy.next`** после операций, которые могли изменить голову.
3. **Обращение к `null.next`.** Проверяйте `node !== null` перед каждым переходом; при `fast.next.next` нужны обе проверки.
4. **Бесконечный цикл** при обходе списка с циклом. Если не уверены в отсутствии цикла — используйте алгоритм Флойда.
5. **Сравнение узлов по значению вместо ссылки.** `slow === fast` сравнивает объекты, и это правильно; `slow.val === fast.val` — ошибка.
6. **Забытый `prev = null`** на старте разворота — старая голова сохранит ссылку вперёд, получится цикл.
7. **Рекурсия на длинном списке** — переполнение стека при n порядка 10⁵.

## Чеклист

- Меняется голова списка → фиктивный узел
- «Середина», «цикл», «n-й с конца» → быстрый и медленный указатели
- «Развернуть», «переставить» → три указателя `prev`/`current`/`next`
- Нужно объединить или переупорядочить → фиктивный узел плюс `tail`
- Перед каждым `.next` — мысленная проверка на `null`
- Нарисуйте список из 2–3 узлов и прогоните код руками. На списках это работает лучше, чем что-либо другое

## Задачи для тренировки

1. **Удалить дубликаты из отсортированного списка.**
2. **Пересечение двух списков** — найти общий узел.
3. **Сложить два числа**, заданных списками цифр в обратном порядке.
4. **Развернуть список по группам из k узлов** — трудная, комбинирует приёмы.
5. **Сортировка списка слиянием** — O(n log n), O(1) памяти.
6. **Копировать список со случайными указателями** — требует `Map`.
