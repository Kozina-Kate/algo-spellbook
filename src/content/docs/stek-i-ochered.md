Две простейшие структуры данных, отличающиеся только порядком выдачи элементов. За этой простотой скрывается целый класс задач — от проверки скобок до монотонного стека.

## Стек

**Стек (stack)** — коллекция с дисциплиной **LIFO**: last in, first out — «последним пришёл, первым вышел». Как стопка тарелок: кладём и берём только сверху.

Операции:

- **push** — положить элемент на верх
- **pop** — снять верхний элемент и вернуть его
- **peek** (top) — посмотреть верхний, не снимая
- **isEmpty** — пуст ли стек

В JavaScript отдельного типа для стека нет — используют массив:

```js
const stack = [];

stack.push(1);                    // положили. O(1) амортизированное
stack.push(2);
const top = stack[stack.length - 1];  // peek: посмотреть верх, O(1)
const popped = stack.pop();       // сняли верхний, вернёт 2. O(1)
const empty = stack.length === 0; // проверка пустоты
```

:::caution
**`pop()` на пустом массиве возвращает `undefined`, а не бросает ошибку.** Это источник трудноуловимых багов: код продолжает работать с `undefined` и падает где-то дальше. Всегда проверяйте `stack.length > 0` перед `pop`.

:::
### Где стек возникает

- Проверка парности скобок
- Отмена действий (undo)
- Вычисление выражений
- Обход в глубину без рекурсии
- **Стек вызовов** — сама рекурсия работает на стеке; это объясняет, почему любая рекурсия переписывается в цикл со стеком

## Очередь

**Очередь (queue)** — дисциплина **FIFO**: first in, first out. Как очередь в кассу: добавляем в хвост, забираем из головы.

Операции: **enqueue** (добавить в хвост), **dequeue** (забрать из головы), **peek**, **isEmpty**.

Наивная реализация массивом работает, но с ловушкой:

```js
const queue = [];
queue.push(1);        // enqueue — O(1), нормально
const first = queue.shift();   // dequeue — O(n)!  Плохо
```

`shift()` удаляет из начала, сдвигая **все** остальные элементы. В цикле это даёт O(n²).

### Правильная очередь через указатель

```js
/**
 * Очередь на массиве с указателем головы.
 * Все операции — O(1).
 */
class Queue {
  constructor() {
    this.items = [];   // хранилище
    this.head = 0;     // индекс первого актуального элемента
  }

  /**
   * Добавить элемент в хвост. O(1) амортизированное.
   */
  enqueue(item) {
    this.items.push(item);
  }

  /**
   * Забрать элемент из головы. O(1).
   * @returns {*} элемент или undefined, если очередь пуста
   */
  dequeue() {
    if (this.isEmpty()) return undefined;

    const item = this.items[this.head];
    // Обнуляем ссылку, чтобы сборщик мусора мог освободить объект.
    // Для чисел не критично, для объектов — важно
    this.items[this.head] = undefined;
    this.head++;

    // Периодическая чистка: когда «мусорная» голова занимает
    // больше половины массива, отрезаем её.
    // Без этого массив растёт бесконечно при длинной работе
    if (this.head > 32 && this.head * 2 > this.items.length) {
      this.items = this.items.slice(this.head);
      this.head = 0;
    }

    return item;
  }

  /** Посмотреть голову, не удаляя. O(1). */
  peek() {
    return this.isEmpty() ? undefined : this.items[this.head];
  }

  /** Количество элементов в очереди. */
  get size() {
    return this.items.length - this.head;
  }

  isEmpty() {
    return this.size === 0;
  }
}
```

### Разбор

- **`this.head`** — вместо физического удаления просто двигаем указатель. Это превращает O(n) в O(1).
- **`get size()`** — геттер: обращение `queue.size` без скобок вызывает эту функцию. Удобно и читается как свойство.
- **Периодическая чистка** — амортизированно бесплатна: каждая чистка стоит O(n), но происходит не чаще, чем раз в n/2 операций.

:::tip
На собеседовании чаще всего достаточно упрощённой версии — массив плюс переменная `head`, без класса. Главное — **проговорить, что `shift()` это O(n)**, и показать, что вы обходите проблему осознанно. Это один из самых характерных JS-специфичных моментов, который интервьюеры ждут.

:::
## Дек

**Дек (deque, double-ended queue)** — очередь с доступом к обоим концам. Нужен для монотонной очереди (максимум в скользящем окне, см. [Скользящее окно](../skolzjashhee-okno/)).

В задачах на собеседовании обычно хватает массива: `push`/`pop` — O(1), `shift` — O(n), но вызывается редко. Проговорите это ограничение вслух.

## Задача 1. Валидные скобки

**Условие.** Строка состоит из символов `()[]{}`. Проверить, что все скобки корректно закрыты и вложены.

Пример: `'([]{})'` → `true`. `'([)]'` → `false`. `'('` → `false`.

### Ход мысли

Классическая задача на стек. Открывающую скобку кладём на стек. При встрече закрывающей смотрим верх стека: там должна лежать соответствующая открывающая. Если да — снимаем; если нет — строка невалидна.

В конце стек должен быть пуст: непустой стек означает незакрытые скобки.

### Решение

```js
/**
 * Проверяет корректность расстановки скобок.
 * @param {string} s — строка из символов ()[]{}
 * @returns {boolean}
 */
function isValidBrackets(s) {
  const stack = [];

  // Соответствие «закрывающая → открывающая».
  // Именно в таком направлении — по закрывающей скобке
  // нам нужно быстро узнать, какая открывающая ей нужна
  const pairs = new Map([
    [')', '('],
    [']', '['],
    ['}', '{'],
  ]);

  for (const ch of s) {
    if (pairs.has(ch)) {
      // Это закрывающая скобка.
      // pop() снимает верх; на пустом стеке вернёт undefined,
      // что не совпадёт ни с одной скобкой — и мы корректно вернём false
      const top = stack.pop();
      if (top !== pairs.get(ch)) return false;
    } else {
      // Открывающая — кладём на стек
      stack.push(ch);
    }
  }

  // Пустой стек — все скобки закрыты
  return stack.length === 0;
}
```

### Разбор

- **`new Map([[')', '('], ...])`** — инициализация `Map` массивом пар. Направление «закрывающая → открывающая» выбрано не случайно: `pairs.has(ch)` заодно служит проверкой «является ли символ закрывающей скобкой».
- **`stack.pop()` на пустом стеке** — `undefined`, сравнение с ним вернёт `false`, и функция корректно отработает случай `')('`. Это приятный случай, когда «опасное» поведение `pop` работает на нас. Но проговорить его стоит явно.
- **Финальная проверка `stack.length === 0`** — без неё строка `'('` ошибочно прошла бы как валидная.

### Сложность

Время **O(n)**, память **O(n)** — в худшем случае (все скобки открывающие) стек вырастет до длины строки.

## Задача 2. Минимальный стек

**Условие.** Реализовать стек, у которого кроме `push`/`pop`/`top` есть операция `getMin` — минимум среди всех элементов, **за O(1)**.

### Ход мысли

Наивно — искать минимум проходом по стеку, но это O(n).

Приём: держать **второй стек** минимумов. На каждом `push` кладём в него текущий минимум (меньшее из нового элемента и предыдущего минимума). Тогда вершина второго стека всегда содержит минимум текущего состояния.

Почему это работает: стек меняется только на вершине, поэтому история минимумов «синхронна» истории элементов.

### Решение

```js
/**
 * Стек с получением минимума за O(1).
 */
class MinStack {
  constructor() {
    this.stack = [];     // сами элементы
    this.minStack = [];   // минимум на момент каждого push
  }

  /**
   * Положить элемент. O(1).
   * @param {number} val
   */
  push(val) {
    this.stack.push(val);

    // Новый минимум — меньшее из val и текущего минимума.
    // Если minStack пуст, val и есть минимум
    const currentMin = this.minStack.length === 0
      ? val
      : Math.min(val, this.minStack[this.minStack.length - 1]);

    this.minStack.push(currentMin);
  }

  /**
   * Снять верхний элемент. O(1).
   * Оба стека снимаются синхронно — в этом суть приёма
   */
  pop() {
    this.minStack.pop();
    return this.stack.pop();
  }

  /** Верхний элемент без удаления. O(1). */
  top() {
    return this.stack[this.stack.length - 1];
  }

  /** Минимум среди всех элементов стека. O(1). */
  getMin() {
    return this.minStack[this.minStack.length - 1];
  }
}
```

### Разбор

- **Два стека одинаковой длины.** Инвариант: `minStack[i]` — минимум среди `stack[0..i]`. Он поддерживается тем, что оба стека всегда меняются вместе.
- **Тернарный оператор** для случая пустого стека.
- **Дубликаты минимума** обрабатываются корректно: если текущий минимум кладётся повторно, он и попадёт в `minStack` повторно, и при `pop` снимется ровно один экземпляр.

**Память** — O(n) дополнительно. Существует вариант с хранением разностей, экономящий память, но объяснять его сложнее; на собеседовании достаточно упомянуть, что такой существует.

## Задача 3. Обратная польская запись

**Условие.** Вычислить выражение в постфиксной записи: `['2', '1', '+', '3', '*']` означает `(2 + 1) * 3 = 9`.

**Обратная польская запись (postfix, RPN)** — форма записи, где оператор идёт **после** операндов. Скобки не нужны, порядок вычисления однозначен.

### Решение

```js
/**
 * Вычисляет выражение в обратной польской записи.
 * @param {string[]} tokens — числа и операторы + - * /
 * @returns {number}
 */
function evalRPN(tokens) {
  const stack = [];

  // Операторы как функции: ключ — символ, значение — функция двух аргументов
  const operators = {
    '+': (a, b) => a + b,
    '-': (a, b) => a - b,
    '*': (a, b) => a * b,
    // Math.trunc отбрасывает дробную часть В СТОРОНУ НУЛЯ:
    // trunc(-2.7) === -2, а floor(-2.7) === -3.
    // В задачах на RPN обычно требуется именно усечение к нулю
    '/': (a, b) => Math.trunc(a / b),
  };

  for (const token of tokens) {
    if (token in operators) {
      // Порядок снятия важен: второй операнд лежит СВЕРХУ,
      // потому что был положен последним
      const b = stack.pop();
      const a = stack.pop();
      stack.push(operators[token](a, b));
    } else {
      // Number() превращает строку в число.
      // parseInt остановился бы на первом нечисловом символе,
      // Number строже — вернёт NaN при мусоре
      stack.push(Number(token));
    }
  }

  // В корректном выражении в конце остаётся ровно одно значение
  return stack.pop();
}
```

### Разбор

- **`token in operators`** — проверка наличия ключа в объекте. Для `Map` аналог — `.has()`.
- **`operators[token](a, b)`** — доступ к функции по ключу и немедленный вызов.
- **Порядок `b` затем `a`** — критическая деталь. Для `-` и `/` порядок операндов меняет результат: `['5','3','-']` это `5 - 3 = 2`, а не `3 - 5`.
- **`Math.trunc`** против `Math.floor` — различаются на отрицательных числах. Уточните у интервьюера требуемое поведение.

Время **O(n)**, память **O(n)**.

## Монотонный стек

Самый мощный приём этой темы — и неочевидный.

**Монотонный стек** — стек, в котором элементы всегда упорядочены (возрастают или убывают). Инвариант поддерживается тем, что перед добавлением нового элемента мы снимаем все, нарушающие порядок.

**Что он решает:** задачи вида «для каждого элемента найти ближайший больший/меньший справа или слева».

**Почему это O(n):** каждый элемент кладётся на стек ровно один раз и снимается не более одного раза. Суммарно 2n операций, несмотря на вложенный `while`.

### Задача 4. Следующий больший элемент

**Условие.** Для каждого элемента массива найти первый элемент справа, который его больше. Если такого нет — вернуть −1.

Пример: `[2, 1, 2, 4, 3]` → `[4, 2, 4, -1, -1]`.

### Ход мысли

Наивно — для каждого элемента идти вправо, O(n²).

Идея монотонного стека: держим на стеке **индексы** элементов, которые ещё «ждут» своего большего соседа. Значения этих элементов убывают снизу вверх.

Когда приходит новый элемент, он становится ответом для всех элементов на вершине стека, которые его меньше. Снимаем их и записываем ответ. Затем кладём текущий индекс — теперь он тоже ждёт.

### Решение

```js
/**
 * Для каждого элемента — первый больший элемент справа.
 * @param {number[]} nums
 * @returns {number[]} массив той же длины, -1 если большего нет
 */
function nextGreaterElements(nums) {
  const n = nums.length;

  // Заполняем -1 заранее: элементы, для которых ответ не найдётся,
  // так и останутся с -1
  const result = new Array(n).fill(-1);

  // Стек ИНДЕКСОВ. Значения по ним убывают от дна к вершине
  const stack = [];

  for (let i = 0; i < n; i++) {
    // Пока текущий элемент больше того, что на вершине —
    // он и есть ответ для вершины
    while (stack.length > 0 && nums[i] > nums[stack[stack.length - 1]]) {
      const idx = stack.pop();
      result[idx] = nums[i];
    }

    // Текущий элемент тоже ждёт своего большего соседа
    stack.push(i);
  }

  // Всё, что осталось на стеке, большего соседа не имеет —
  // у них уже стоит -1 из инициализации

  return result;
}
```

### Разбор

- **Хранение индексов, а не значений** — обязательно: ответ нужно записать в конкретную позицию результата.
- **`nums[stack[stack.length - 1]]`** — значение элемента на вершине стека. Двойная индексация читается тяжело; на собеседовании полезно завести промежуточную переменную `const topIdx = stack[stack.length - 1]`.
- **`new Array(n).fill(-1)`** — предзаполнение избавляет от отдельной обработки «не найдено».
- **Строгое `>`** — определяет поведение при равных элементах. Для «следующего большего или равного» нужно `>=`. Уточните у интервьюера.

### Сложность

Время **O(n)** — каждый индекс кладётся и снимается не более одного раза. Память **O(n)**.

### Задача 5. Ежедневные температуры

**Условие.** Для каждого дня определить, через сколько дней станет теплее. Если потепления не будет — 0.

Пример: `[73,74,75,71,69,72,76,73]` → `[1,1,4,2,1,1,0,0]`.

Это ровно тот же монотонный стек, только записываем не значение, а **расстояние**:

```js
/**
 * Через сколько дней станет теплее.
 * @param {number[]} temperatures
 * @returns {number[]}
 */
function dailyTemperatures(temperatures) {
  const n = temperatures.length;
  const result = new Array(n).fill(0);
  const stack = [];   // индексы дней, ждущих потепления

  for (let i = 0; i < n; i++) {
    while (
      stack.length > 0 &&
      temperatures[i] > temperatures[stack[stack.length - 1]]
    ) {
      const prevDay = stack.pop();
      // Разница индексов и есть количество дней ожидания
      result[prevDay] = i - prevDay;
    }
    stack.push(i);
  }

  return result;
}
```

Время **O(n)**, память **O(n)**.

Умение увидеть, что две внешне разные задачи — один и тот же шаблон, и есть то, что отличает подготовленного кандидата.

## Обход в глубину без рекурсии

Стек позволяет переписать любую рекурсию в цикл. Это нужно, когда глубина рекурсии рискует превысить лимит стека вызовов (~10 000 в JS).

```js
/**
 * Обход дерева в глубину без рекурсии, порядок preorder (корень-лево-право).
 * @param {Object|null} root — узел с полями val, left, right
 * @returns {number[]} значения в порядке обхода
 */
function dfsIterative(root) {
  if (root === null) return [];

  const result = [];
  const stack = [root];

  while (stack.length > 0) {
    const node = stack.pop();
    result.push(node.val);

    // Кладём ПРАВОГО первым, чтобы ЛЕВЫЙ оказался сверху
    // и был обработан раньше — стек переворачивает порядок
    if (node.right !== null) stack.push(node.right);
    if (node.left !== null) stack.push(node.left);
  }

  return result;
}
```

Подробнее про обходы — [Деревья](../derevja/).

## Типичные ошибки

1. **`shift()` в цикле** — скрытый O(n²). Главная JS-ошибка в этой теме.
2. **`pop()` без проверки пустоты** — `undefined` расползается по коду.
3. **Забыта финальная проверка стека** в задаче о скобках.
4. **Перепутан порядок операндов** при снятии двух элементов.
5. **Хранение значений вместо индексов** в монотонном стеке.
6. **`if` вместо `while`** при снятии элементов монотонного стека — снимается только один, инвариант ломается.
7. **Утверждение «O(n²)» про монотонный стек** — не заметить амортизацию. Объясните, что каждый элемент обрабатывается дважды.

## Чеклист

- «Парность», «вложенность», «последний открытый» → стек
- «Обработать в порядке поступления», «по уровням» → очередь
- «Ближайший больший/меньший элемент» → монотонный стек
- «Максимум в окне» → монотонный дек
- Рекурсия слишком глубокая → переписать через явный стек
- Используете `shift()` → замените на указатель

## Задачи для тренировки

1. **Очередь через два стека** — классика на понимание обеих структур.
2. **Стек через две очереди** — обратная задача.
3. **Упростить путь в файловой системе** (`/a/./b/../c` → `/a/c`) — стек каталогов.
4. **Максимальный прямоугольник в гистограмме** — монотонный стек, трудная.
5. **Ловушка для дождевой воды** — решается и двумя указателями, и монотонным стеком.
6. **Удалить k цифр, чтобы число стало минимальным** — монотонный стек.
