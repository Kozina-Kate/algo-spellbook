## Термины

**Граф** — набор **вершин (узлов)** и **рёбер**, соединяющих пары вершин.

- **Ориентированный (directed)** граф — рёбра имеют направление: из A в B можно, из B в A не обязательно. Пример: подписки, зависимости задач.
- **Неориентированный (undirected)** — рёбра двусторонние. Пример: дружба, дороги.
- **Взвешенный** — у рёбер есть вес (расстояние, стоимость).
- **Степень вершины** — количество инцидентных ей рёбер. В ориентированном графе различают **входящую** и **исходящую** степень.
- **Путь** — последовательность вершин, соединённых рёбрами.
- **Цикл** — путь, начинающийся и заканчивающийся в одной вершине.
- **Связная компонента** — максимальная группа вершин, между любыми двумя из которых есть путь.
- **DAG (directed acyclic graph)** — ориентированный граф без циклов. На нём работает топологическая сортировка.

Дерево — частный случай: связный граф без циклов, где рёбер ровно на одно меньше, чем вершин.

## Представление графа

### Список смежности — основной способ

Для каждой вершины хранится список её соседей. Память O(V + E), где V — число вершин, E — рёбер.

```js
// Граф: 0—1, 0—2, 1—2, 2—3
const graph = new Map([
  [0, [1, 2]],
  [1, [0, 2]],
  [2, [0, 1, 3]],
  [3, [2]],
]);

// Соседи вершины 2
graph.get(2);   // [0, 1, 3]
```

### Построение из списка рёбер

Условие часто даёт рёбра массивом пар — граф нужно собрать самому. Это стандартная заготовка:

```js
/**
 * Строит список смежности из списка рёбер.
 * @param {number} n — количество вершин (0..n-1)
 * @param {number[][]} edges — рёбра [from, to]
 * @param {boolean} directed — ориентированный ли граф
 * @returns {Map<number, number[]>}
 */
function buildGraph(n, edges, directed = false) {
  const graph = new Map();

  // Инициализируем ВСЕ вершины, включая изолированные.
  // Без этого graph.get(v) вернёт undefined для вершины без рёбер
  for (let i = 0; i < n; i++) {
    graph.set(i, []);
  }

  for (const [from, to] of edges) {
    graph.get(from).push(to);
    // В неориентированном графе ребро добавляется в обе стороны
    if (!directed) {
      graph.get(to).push(from);
    }
  }

  return graph;
}
```

:::caution
**Забыть добавить обратное ребро** в неориентированном графе — ошибка номер один в этой теме. Она не вызывает падения: алгоритм отработает и выдаст неправильный ответ.

Вторая по частоте — **не инициализировать изолированные вершины**, из-за чего `graph.get(v)` возвращает `undefined` и код падает на `for...of undefined`.

:::
### Матрица смежности

Двумерный массив: `matrix[i][j] === 1`, если есть ребро. Память O(V²) — оправдана только для плотных графов. В задачах на собеседовании встречается как **готовый вход** («дана матрица связей»).

### Неявный граф

Часто граф в условии не задан явно. **Сетка (grid)** — самый частый случай: клетки это вершины, соседние клетки соединены рёбрами.

```js
// Четыре направления: вверх, вниз, влево, вправо
const DIRECTIONS = [[-1, 0], [1, 0], [0, -1], [0, 1]];

// Соседи клетки (row, col)
for (const [dr, dc] of DIRECTIONS) {
  const nr = row + dr;
  const nc = col + dc;
  // Проверка границ обязательна перед обращением к grid[nr][nc]
  if (nr >= 0 && nr < rows && nc >= 0 && nc < cols) {
    // (nr, nc) — валидный сосед
  }
}
```

Умение распознать «задача про сетку = задача про граф» — половина успеха в этой теме.

## Обход в глубину (DFS)

Идём вглубь, пока можем, потом возвращаемся. Отличие от дерева — множество `visited`.

```js
/**
 * Обход в глубину из стартовой вершины.
 * @param {Map<number, number[]>} graph — список смежности
 * @param {number} start — стартовая вершина
 * @returns {number[]} вершины в порядке посещения
 */
function dfs(graph, start) {
  const visited = new Set();   // без него обход зациклится на первом же цикле
  const order = [];

  function visit(node) {
    // Уже были здесь — выходим. Это ЕДИНСТВЕННОЕ отличие от обхода дерева
    if (visited.has(node)) return;

    visited.add(node);   // помечаем ДО рекурсии, иначе цикл всё равно случится
    order.push(node);

    // graph.get(node) может быть undefined для неизвестной вершины —
    // `|| []` страхует от падения
    for (const neighbor of graph.get(node) || []) {
      visit(neighbor);
    }
  }

  visit(start);
  return order;
}
```

### Итеративная версия

Нужна при больших графах — рекурсия глубиной 10⁵ переполнит стек.

```js
function dfsIterative(graph, start) {
  const visited = new Set();
  const order = [];
  const stack = [start];

  while (stack.length > 0) {
    const node = stack.pop();

    // Проверяем при СНЯТИИ: одна вершина могла попасть на стек несколько раз
    if (visited.has(node)) continue;

    visited.add(node);
    order.push(node);

    for (const neighbor of graph.get(node) || []) {
      if (!visited.has(neighbor)) {
        stack.push(neighbor);
      }
    }
  }

  return order;
}
```

**Сложность.** Время **O(V + E)** — каждая вершина обрабатывается раз, каждое ребро просматривается раз (дважды в неориентированном). Память **O(V)**.

## Обход в ширину (BFS)

Расходимся кругами от старта. Главное свойство: **BFS находит кратчайший путь в невзвешенном графе**, потому что вершины посещаются в порядке возрастания расстояния от старта.

```js
/**
 * Кратчайшие расстояния от старта до всех достижимых вершин.
 * @param {Map<number, number[]>} graph
 * @param {number} start
 * @returns {Map<number, number>} вершина → расстояние в рёбрах
 */
function bfs(graph, start) {
  const distances = new Map([[start, 0]]);
  const queue = [start];
  let head = 0;   // указатель вместо shift() — shift это O(n)

  while (head < queue.length) {
    const node = queue[head];
    head++;

    for (const neighbor of graph.get(node) || []) {
      // Не посещали — значит нашли кратчайший путь до него именно сейчас
      if (!distances.has(neighbor)) {
        distances.set(neighbor, distances.get(node) + 1);
        queue.push(neighbor);
      }
    }
  }

  return distances;
}
```

:::note
**Почему BFS даёт именно кратчайший путь.** Вершины извлекаются из очереди в порядке неубывания расстояния от старта. Когда мы впервые видим вершину, мы пришли к ней по кратчайшему возможному маршруту — любой другой путь прошёл бы через вершину, которую мы обработаем позже, то есть был бы длиннее.

Именно поэтому `distances.set` вызывается **при добавлении в очередь**, а не при извлечении. Иначе одна вершина попадёт в очередь несколько раз.

Важно: это верно только для **невзвешенного** графа (или когда все веса равны). Для разных весов нужен алгоритм Дейкстры — BFS с приоритетной очередью вместо обычной.

:::
**Сложность.** Время **O(V + E)**, память **O(V)**.

## Задача 1. Количество островов

**Условие.** Дана матрица из `'1'` (суша) и `'0'` (вода). Остров — группа соседних по стороне клеток суши. Посчитать количество островов.

```
11000
11000
00100
00011     → 3 острова
```

### Ход мысли

Это задача про связные компоненты в неявном графе.

Идём по всем клеткам. Встретили непосещённую сушу — это новый остров, увеличиваем счётчик и «заливаем» весь остров обходом, помечая клетки посещёнными. Так каждый остров будет посчитан ровно один раз.

Приём называется **заливкой (flood fill)**.

### Решение

```js
/**
 * Количество островов в матрице.
 * @param {string[][]} grid — матрица из '1' и '0'
 * @returns {number}
 */
function numIslands(grid) {
  if (grid.length === 0) return 0;

  const rows = grid.length;
  const cols = grid[0].length;
  let count = 0;

  /**
   * Заливает весь остров, начиная с клетки (r, c),
   * помечая клетки как посещённые.
   */
  function sink(r, c) {
    // Единая проверка: вышли за границы ИЛИ это не суша.
    // Порядок условий важен — проверка границ ДО обращения к grid[r][c],
    // иначе будет обращение к undefined[c]
    if (r < 0 || r >= rows || c < 0 || c >= cols || grid[r][c] !== '1') {
      return;
    }

    // Помечаем клетку как посещённую, меняя её прямо в матрице.
    // Экономит O(rows*cols) памяти на отдельном visited,
    // но МУТИРУЕТ вход — обязательно проговорите это вслух
    grid[r][c] = '0';

    // Рекурсивно заливаем четырёх соседей
    sink(r - 1, c);
    sink(r + 1, c);
    sink(r, c - 1);
    sink(r, c + 1);
  }

  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (grid[r][c] === '1') {
        count++;      // нашли новый остров
        sink(r, c);   // и утопили его целиком, чтобы не считать дважды
      }
    }
  }

  return count;
}
```

### Разбор

- **Объединённая проверка в начале `sink`** — стандартный приём для сеток: вместо проверки каждого соседа перед вызовом мы проверяем один раз внутри. Код становится заметно короче.
- **Порядок условий** — проверка границ строго до обращения к элементу. `||` с коротким замыканием гарантирует, что `grid[r][c]` не вычислится при выходе за границы.
- **Мутация входа вместо `visited`** — допустимый компромисс, но о нём нужно сказать. Если мутировать нельзя, заведите `visited` как `Set` строковых ключей `` `${r},${c}` `` или отдельную матрицу булевых значений.

### Сложность

Время **O(rows · cols)** — каждая клетка обрабатывается не больше одного раза. Память **O(rows · cols)** в худшем случае на стек рекурсии (вся матрица — суша).

:::caution
На большой матрице (например, 1000×1000, целиком суша) рекурсия уйдёт на глубину миллион и переполнит стек. Правильный ответ на собеседовании: «здесь возможен stack overflow, при больших размерах переписала бы на итеративный BFS со стеком/очередью». Это именно тот комментарий, который отличает внимательного кандидата.

:::
## Задача 2. Кратчайший путь в лабиринте

**Условие.** В матрице `0` — проход, `1` — стена. Найти минимальное число шагов от левого верхнего угла до правого нижнего, двигаясь по четырём направлениям.

### Решение

```js
/**
 * Кратчайший путь в матрице-лабиринте.
 * @param {number[][]} grid — 0 проход, 1 стена
 * @returns {number} число клеток в пути, или -1 если пути нет
 */
function shortestPath(grid) {
  const rows = grid.length;
  if (rows === 0) return -1;
  const cols = grid[0].length;

  // Старт или финиш заблокированы — пути нет
  if (grid[0][0] === 1 || grid[rows - 1][cols - 1] === 1) return -1;

  const DIRECTIONS = [[-1, 0], [1, 0], [0, -1], [0, 1]];

  // Очередь троек [строка, столбец, пройденное расстояние]
  const queue = [[0, 0, 1]];
  let head = 0;

  // Отдельная матрица посещённых — вход не мутируем
  const visited = Array.from({ length: rows }, () =>
    new Array(cols).fill(false)
  );
  visited[0][0] = true;

  while (head < queue.length) {
    const [r, c, dist] = queue[head];
    head++;

    // Дошли до финиша. BFS гарантирует, что это кратчайший путь
    if (r === rows - 1 && c === cols - 1) return dist;

    for (const [dr, dc] of DIRECTIONS) {
      const nr = r + dr;
      const nc = c + dc;

      // Проверяем: в границах, не стена, не посещали
      if (
        nr >= 0 && nr < rows &&
        nc >= 0 && nc < cols &&
        grid[nr][nc] === 0 &&
        !visited[nr][nc]
      ) {
        visited[nr][nc] = true;      // помечаем при ДОБАВЛЕНИИ в очередь
        queue.push([nr, nc, dist + 1]);
      }
    }
  }

  return -1;   // очередь опустела, финиш не достигнут
}
```

### Разбор

- **Расстояние хранится прямо в очереди** — вместо отдельной структуры. Альтернатива — обрабатывать очередь послойно, как в BFS по уровням дерева.
- **`Array.from({length: rows}, () => new Array(cols).fill(false))`** — создание матрицы. Через `new Array(rows).fill(new Array(...))` все строки оказались бы одним массивом.
- **Пометка при добавлении, а не при извлечении** — иначе одна клетка попадёт в очередь несколько раз, и сложность вырастет.
- **`const [r, c, dist] = queue[head]`** — деструктуризация массива в три переменные.

Время **O(rows · cols)**, память **O(rows · cols)**.

## Задача 3. Обнаружение цикла в ориентированном графе

**Условие.** Есть ли в ориентированном графе цикл?

### Ход мысли

Обычного `visited` недостаточно. Вершина, посещённая раньше, могла быть в **другой** ветке обхода — это не цикл. Цикл — это возврат к вершине, которая находится **в текущем пути**.

Отсюда трёхцветная маркировка:

- **белый (0)** — не посещали
- **серый (1)** — в процессе обработки, находится в текущем пути DFS
- **чёрный (2)** — полностью обработана вместе со всем поддеревом

Встретили серую вершину — нашли цикл.

### Решение

```js
/**
 * Есть ли цикл в ориентированном графе.
 * @param {number} n — количество вершин
 * @param {Map<number, number[]>} graph
 * @returns {boolean}
 */
function hasCycleDirected(n, graph) {
  const WHITE = 0, GRAY = 1, BLACK = 2;
  const color = new Array(n).fill(WHITE);

  function dfs(node) {
    color[node] = GRAY;   // вошли в вершину — она в текущем пути

    for (const neighbor of graph.get(node) || []) {
      if (color[neighbor] === GRAY) {
        return true;   // ребро назад в текущий путь — это цикл
      }
      // Белую вершину обходим; чёрную пропускаем — она уже проверена
      if (color[neighbor] === WHITE && dfs(neighbor)) {
        return true;
      }
    }

    color[node] = BLACK;   // вышли из вершины — путь через неё закрыт
    return false;
  }

  // Граф может быть несвязным — запускаем обход из каждой непосещённой вершины
  for (let i = 0; i < n; i++) {
    if (color[i] === WHITE && dfs(i)) return true;
  }

  return false;
}
```

:::note
**В неориентированном графе всё иначе.** Там достаточно обычного `visited`, но нужно **не считать циклом возврат к родителю** — ребро `A—B` позволяет вернуться из B в A, и это не цикл. Поэтому в рекурсию передают родителя и пропускают его при переборе соседей.

:::
Время **O(V + E)**, память **O(V)**.

## Задача 4. Топологическая сортировка

**Условие.** Даны курсы и зависимости: чтобы пройти курс `a`, нужно сначала пройти курс `b`. Составить порядок прохождения всех курсов, либо определить, что это невозможно.

**Топологическая сортировка** — линейный порядок вершин DAG, при котором каждое ребро идёт слева направо. Существует тогда и только тогда, когда в графе нет циклов.

### Ход мысли

**Алгоритм Кана** (BFS-версия) нагляднее рекурсивного и заодно обнаруживает цикл.

**Входящая степень (in-degree)** вершины — сколько рёбер в неё входит, то есть сколько зависимостей у курса.

Алгоритм: берём все вершины с нулевой входящей степенью (курсы без предварительных требований) — их можно проходить сразу. Обрабатываем вершину, «снимаем» её рёбра, уменьшая входящие степени соседей. У кого степень упала до нуля — добавляем в очередь.

Если в итоге обработаны не все вершины, оставшиеся образуют цикл.

### Решение

```js
/**
 * Порядок прохождения курсов с учётом зависимостей.
 * @param {number} numCourses — количество курсов (0..numCourses-1)
 * @param {number[][]} prerequisites — пары [курс, требуемый_ранее_курс]
 * @returns {number[]} корректный порядок, или [] если его нет
 */
function findOrder(numCourses, prerequisites) {
  // Список смежности: из требования — в курс, который оно открывает
  const graph = new Map();
  for (let i = 0; i < numCourses; i++) {
    graph.set(i, []);
  }

  // inDegree[i] — сколько курсов нужно пройти перед курсом i
  const inDegree = new Array(numCourses).fill(0);

  for (const [course, prereq] of prerequisites) {
    graph.get(prereq).push(course);   // ребро prereq → course
    inDegree[course]++;
  }

  // Стартуем со всех курсов без зависимостей
  const queue = [];
  for (let i = 0; i < numCourses; i++) {
    if (inDegree[i] === 0) queue.push(i);
  }

  const order = [];
  let head = 0;

  while (head < queue.length) {
    const course = queue[head];
    head++;
    order.push(course);

    // «Проходим» курс — снимаем по одной зависимости с тех,
    // кто его требовал
    for (const next of graph.get(course)) {
      inDegree[next]--;
      // Все зависимости сняты — курс стал доступен
      if (inDegree[next] === 0) {
        queue.push(next);
      }
    }
  }

  // Обработали не все курсы — значит в графе цикл,
  // и корректного порядка не существует
  return order.length === numCourses ? order : [];
}
```

### Разбор

- **Направление рёбер.** Ребро идёт **от требования к курсу**: сначала требование, потом курс. Перепутать направление — самая частая ошибка; тогда `inDegree` считается не для тех вершин.
- **`inDegree[next]--` с последующей проверкой на ноль** — сердце алгоритма.
- **Финальная проверка длины** — одновременно и обнаружение цикла. Отдельный алгоритм поиска цикла не нужен.
- **`[course, prereq]`** — порядок элементов в паре задаётся условием задачи, обязательно перечитайте его.

Время **O(V + E)**, память **O(V + E)**.

## Задача 5. Клонирование графа

**Условие.** Дан узел связного неориентированного графа. Вернуть глубокую копию всего графа.

### Ход мысли

Сложность в том, что при наивном копировании циклы приводят к бесконечной рекурсии, а общие соседи копируются по несколько раз.

Решение — `Map` «оригинальный узел → его копия». Перед копированием узла проверяем, не скопирован ли он уже.

### Решение

```js
/**
 * Узел графа.
 */
class GraphNode {
  constructor(val = 0, neighbors = []) {
    this.val = val;
    this.neighbors = neighbors;
  }
}

/**
 * Глубокая копия связного неориентированного графа.
 * @param {GraphNode|null} node — любой узел графа
 * @returns {GraphNode|null}
 */
function cloneGraph(node) {
  if (node === null) return null;

  // Ключ — оригинальный объект-узел, значение — его копия.
  // Map умеет работать с объектами как с ключами, обычный объект — нет
  const cloned = new Map();

  function clone(original) {
    // Уже копировали — возвращаем готовую копию.
    // Это и разрывает бесконечную рекурсию на циклах
    if (cloned.has(original)) {
      return cloned.get(original);
    }

    // Создаём копию БЕЗ соседей и сразу регистрируем её.
    // Порядок критичен: если сосед сошлётся обратно на нас,
    // он должен найти копию в Map, а не начать копировать заново
    const copy = new GraphNode(original.val);
    cloned.set(original, copy);

    // Теперь рекурсивно копируем соседей
    for (const neighbor of original.neighbors) {
      copy.neighbors.push(clone(neighbor));
    }

    return copy;
  }

  return clone(node);
}
```

### Разбор

- **`Map` с объектными ключами** — то, чего не умеет обычный объект. Здесь это принципиально.
- **Регистрация копии до обхода соседей** — самая важная строка. Обратный порядок даёт бесконечную рекурсию на любом цикле.

Время **O(V + E)**, память **O(V)**.

## Типичные ошибки

1. **Забыто обратное ребро** в неориентированном графе.
2. **Не инициализированы изолированные вершины** — `graph.get(v)` возвращает `undefined`.
3. **Нет `visited`** — бесконечный цикл.
4. **Пометка посещения при извлечении из очереди, а не при добавлении** — вершины дублируются в очереди.
5. **Обычный `visited` для поиска цикла в ориентированном графе** — нужна трёхцветная маркировка.
6. **Обход запущен только из одной вершины**, хотя граф несвязный. Нужен цикл по всем вершинам.
7. **`shift()`** в BFS.
8. **Обращение к `grid[r][c]` до проверки границ.**
9. **Глубокая рекурсия** на большой сетке — переполнение стека.

## Чеклист

- Сетка, лабиринт, карта → неявный граф, клетки = вершины
- «Сколько групп / областей / компонент» → DFS или BFS с подсчётом запусков
- «Кратчайший путь», рёбра без весов → BFS
- «Кратчайший путь», рёбра с весами → Дейкстра (BFS с кучей)
- «Порядок с учётом зависимостей» → топологическая сортировка
- «Можно ли выполнить всё» / «есть ли взаимная блокировка» → поиск цикла
- «Копировать структуру со ссылками» → `Map` оригинал → копия
- Всегда: инициализация всех вершин, `visited`, обход всех компонент

## Задачи для тренировки

1. **Максимальная площадь острова** — та же заливка, но с подсчётом размера.
2. **Окружённые области** — заливка от границ, инверсия логики.
3. **Расписание курсов** — только проверка возможности, без построения порядка.
4. **Двудольный ли граф** — раскраска в два цвета обходом.
5. **Гниющие апельсины** — многоисточниковый BFS (в очередь кладутся сразу все стартовые клетки).
6. **Число провинций** — компоненты связности по матрице смежности.
7. **Word Ladder** — BFS по неявному графу слов, трудная.
