Тема, которой боятся больше всего. На деле это всего лишь перебор, который перестал пересчитывать одно и то же. Если вы умеете писать рекурсию, вы уже на полпути.

## Что это

**Динамическое программирование (ДП, dynamic programming)** — метод решения задач, при котором задача разбивается на подзадачи, каждая подзадача решается ровно один раз, а результат сохраняется.

Название историческое и ничего не объясняет: «программирование» здесь означает «планирование», а не написание кода.

ДП применимо, когда есть два свойства:

- **Оптимальная подструктура** — оптимальное решение задачи строится из оптимальных решений подзадач. Например, кратчайший путь из A в C через B состоит из кратчайшего пути A→B и кратчайшего B→C.
- **Перекрывающиеся подзадачи** — одни и те же подзадачи возникают многократно. Именно это отличает ДП от «разделяй и властвуй»: в сортировке слиянием подзадачи не пересекаются, поэтому кеш там не нужен.

:::note
**ДП против жадности.** Жадный алгоритм принимает решение и больше к нему не возвращается. ДП рассматривает все варианты решения, но не пересчитывает уже посчитанное.

Практическое правило: если жадное решение ломается на контрпримере, а перебор слишком медленный — это ДП. Подробнее про границу — [Жадные алгоритмы](../zhadnye-algoritmy-i-kucha/).

:::
## Два стиля

### Сверху вниз: мемоизация

Пишем обычную рекурсию, добавляем кеш. Естественно и близко к формулировке задачи.

### Снизу вверх: табуляция

Заводим массив, заполняем его от базовых случаев к искомому. Нет рекурсии, значит нет риска переполнения стека.

```js
// Сверху вниз
function fibMemo(n, memo = new Map()) {
  if (n <= 1) return n;
  if (memo.has(n)) return memo.get(n);
  const result = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
  memo.set(n, result);
  return result;
}

// Снизу вверх
function fibTab(n) {
  if (n <= 1) return n;

  const dp = new Array(n + 1);   // dp[i] — i-е число Фибоначчи
  dp[0] = 0;                     // база
  dp[1] = 1;                     // база

  // Каждое следующее выводим из двух предыдущих
  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
  }

  return dp[n];
}

// Снизу вверх с оптимизацией памяти: нужны только два последних значения
function fibOptimized(n) {
  if (n <= 1) return n;

  let prev = 0;
  let curr = 1;

  for (let i = 2; i <= n; i++) {
    // Деструктуризация: правая часть вычисляется целиком до присваивания,
    // поэтому старое curr попадает в prev корректно
    [prev, curr] = [curr, prev + curr];
  }

  return curr;
}
```

Три версии одной задачи: **O(n)** времени во всех, память **O(n)** в первых двух и **O(1)** в третьей.

Такой путь — «рекурсия → мемоизация → таблица → оптимизация памяти» — стандартный сценарий ответа на собеседовании. Показать его целиком гораздо ценнее, чем сразу выдать оптимальный код.

## Как решать задачу на ДП

Пять шагов. Выполняйте их по порядку, вслух — интервьюер оценивает именно процесс.

1. **Определите состояние.** Что такое `dp[i]`? Ответьте одним предложением, максимально точно. «`dp[i]` — максимальная сумма подмассива, **заканчивающегося** в позиции i» — это состояние. «`dp[i]` — что-то про сумму» — нет. Большинство провалов на ДП происходит именно здесь.
2. **Выпишите переход.** Как `dp[i]` выражается через предыдущие значения? Это рекуррентное соотношение.
3. **Укажите базу.** Какие значения известны без вычислений?
4. **Определите порядок вычисления.** В каком порядке заполнять таблицу, чтобы нужные значения уже были готовы?
5. **Найдите ответ.** Это `dp[n]`? Максимум по всему массиву? Что-то ещё?

:::tip
**Приём, который выручает: сначала напишите честный перебор.** Даже если он O(2ⁿ). В нём уже содержится определение состояния — это набор параметров рекурсивной функции. Дальше остаётся добавить кеш по этим параметрам, и ДП готово.

Путь «перебор → мемоизация → таблица» надёжнее, чем попытка сразу угадать формулу.

:::
## Задача 1. Лестница

**Условие.** Лестница из n ступеней. За шаг можно подняться на 1 или 2 ступени. Сколькими способами можно достичь верха?

### Пять шагов

1. **Состояние:** `dp[i]` — число способов добраться до ступени i.
2. **Переход:** на ступень i можно попасть с i−1 (шагом на 1) или с i−2 (шагом на 2). Способы не пересекаются и покрывают всё: `dp[i] = dp[i-1] + dp[i-2]`.
3. **База:** `dp[0] = 1` (один способ никуда не идти), `dp[1] = 1`.
4. **Порядок:** от малых i к большим.
5. **Ответ:** `dp[n]`.

Это те же числа Фибоначчи — и это типично: ДП часто сводит внешне разные задачи к одному соотношению.

```js
/**
 * Число способов подняться по лестнице из n ступеней шагами 1 и 2.
 * @param {number} n
 * @returns {number}
 */
function climbStairs(n) {
  if (n <= 2) return n;

  // Храним только два последних значения — больше не нужно
  let twoBack = 1;   // способов дойти до ступени n-2
  let oneBack = 2;   // способов дойти до ступени n-1

  for (let i = 3; i <= n; i++) {
    const current = oneBack + twoBack;
    twoBack = oneBack;
    oneBack = current;
  }

  return oneBack;
}
```

Время **O(n)**, память **O(1)**.

## Задача 2. Ограбление домов

**Условие.** На улице дома с суммами денег. Нельзя грабить два соседних дома. Максимальная добыча?

Пример: `[2, 7, 9, 3, 1]` → `12` (дома 2, 9 и 1).

### Пять шагов

1. **Состояние:** `dp[i]` — максимальная добыча с первых i+1 домов (с домов `0..i`).
2. **Переход:** для дома i есть два варианта. Грабим его — тогда i−1 пропущен, добавляем к `dp[i-2]`. Не грабим — добыча та же, что `dp[i-1]`. Берём лучший: `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`.
3. **База:** `dp[0] = nums[0]`, `dp[1] = max(nums[0], nums[1])`.
4. **Порядок:** слева направо.
5. **Ответ:** `dp[n-1]`.

### Решение

```js
/**
 * Максимальная сумма из несоседних элементов.
 * @param {number[]} nums — суммы в домах
 * @returns {number}
 */
function rob(nums) {
  if (nums.length === 0) return 0;
  if (nums.length === 1) return nums[0];

  // prev2 — лучший результат до дома i-2
  // prev1 — лучший результат до дома i-1
  let prev2 = nums[0];
  let prev1 = Math.max(nums[0], nums[1]);

  for (let i = 2; i < nums.length; i++) {
    // Либо пропускаем дом i (берём prev1),
    // либо грабим его и прибавляем к результату двухдомовой давности
    const current = Math.max(prev1, prev2 + nums[i]);

    prev2 = prev1;
    prev1 = current;
  }

  return prev1;
}
```

### Разбор

- **Определение состояния как «лучший результат до i включительно», а не «обязательно грабим i»** — принципиально. Второе определение тоже рабочее, но потребует брать максимум в конце. Обе формулировки корректны; путать их внутри одного решения — нет.
- **Два варианта в `Math.max`** — это и есть перебор, свёрнутый в одну строку.
- **Свёртка до двух переменных** — типичная оптимизация памяти, когда переход смотрит только на фиксированное число предыдущих состояний.

Время **O(n)**, память **O(1)**.

## Задача 3. Размен монет

**Условие.** Даны номиналы монет и сумма. Минимальное количество монет, дающих эту сумму. Монет каждого номинала неограниченно. Если сумму не набрать — вернуть −1.

Пример: `coins = [1, 3, 4]`, `amount = 6` → `2` (монеты 3 и 3).

Та самая задача, на которой ломается жадность.

### Пять шагов

1. **Состояние:** `dp[i]` — минимальное число монет для суммы i.
2. **Переход:** последняя монета могла быть любого номинала `c ≤ i`. Тогда до неё была сумма `i - c`: `dp[i] = min(dp[i - c] + 1)` по всем подходящим c.
3. **База:** `dp[0] = 0` — пустую сумму набираем нулём монет.
4. **Порядок:** от 1 до amount.
5. **Ответ:** `dp[amount]`, либо −1, если недостижимо.

### Решение

```js
/**
 * Минимальное число монет для набора суммы.
 * @param {number[]} coins — номиналы, каждый доступен неограниченно
 * @param {number} amount — целевая сумма
 * @returns {number} минимальное число монет или -1
 */
function coinChange(coins, amount) {
  // Infinity как маркер «недостижимо».
  // Удобнее числа-заглушки: Infinity + 1 остаётся Infinity,
  // и сравнения работают как надо
  const dp = new Array(amount + 1).fill(Infinity);

  dp[0] = 0;   // база

  // Внешний цикл по суммам: к моменту вычисления dp[i]
  // все меньшие суммы уже посчитаны
  for (let i = 1; i <= amount; i++) {
    for (const coin of coins) {
      // Монета не должна превышать набираемую сумму
      if (coin <= i) {
        // Берём эту монету последней: к решению для остатка добавляем 1
        dp[i] = Math.min(dp[i], dp[i - coin] + 1);
      }
    }
  }

  // Так и осталось Infinity — сумму не набрать данными номиналами
  return dp[amount] === Infinity ? -1 : dp[amount];
}
```

### Разбор

- **`Infinity` вместо `-1` или `Number.MAX_SAFE_INTEGER`** — важный выбор. `MAX_SAFE_INTEGER + 1` тихо теряет точность, а `Infinity + 1 === Infinity`, и `Math.min` работает корректно. Проговорить этот выбор — хороший сигнал.
- **Порядок циклов: снаружи суммы, внутри монеты.** Так к моменту вычисления `dp[i]` все `dp[i - coin]` готовы.
- **`coin <= i`** — защита от отрицательного индекса.

### Сложность

Время **O(amount · количество монет)**, память **O(amount)**.

:::caution
**Порядок циклов в задачах про монеты меняет смысл.**

- Сумма снаружи, монеты внутри → каждая монета доступна многократно, порядок монет **не важен** (комбинации).
- Монеты снаружи, сумма внутри → это шаблон задачи о рюкзаке.

В близкой задаче «сколькими способами набрать сумму» перестановка циклов даёт **разные ответы**: один порядок считает комбинации (`1+2` и `2+1` — одно), другой — последовательности (разные). Всегда проверяйте на маленьком примере, что именно вы считаете.

:::
## Задача 4. Наибольшая возрастающая подпоследовательность

**Условие.** Найти длину самой длинной строго возрастающей подпоследовательности.

**Подпоследовательность** — набор элементов в исходном порядке, но **не обязательно подряд**. В отличие от подмассива, который всегда непрерывен.

Пример: `[10, 9, 2, 5, 3, 7, 101, 18]` → `4` (это `[2, 3, 7, 101]`).

### Пять шагов

1. **Состояние:** `dp[i]` — длина наибольшей возрастающей подпоследовательности, **заканчивающейся ровно в элементе i**. Слово «заканчивающейся» здесь ключевое: без него переход не выписать.
2. **Переход:** смотрим на все `j < i`. Если `nums[j] < nums[i]`, подпоследовательность из j можно продлить: `dp[i] = max(dp[j] + 1)`.
3. **База:** `dp[i] = 1` — сам элемент всегда образует последовательность длины 1.
4. **Порядок:** слева направо.
5. **Ответ:** **максимум по всему `dp`**, а не `dp[n-1]`. Последовательность может заканчиваться где угодно.

### Решение

```js
/**
 * Длина наибольшей строго возрастающей подпоследовательности.
 * @param {number[]} nums
 * @returns {number}
 */
function lengthOfLIS(nums) {
  if (nums.length === 0) return 0;

  // dp[i] — длина НВП, заканчивающейся в позиции i.
  // Минимум 1 — сам элемент
  const dp = new Array(nums.length).fill(1);

  for (let i = 1; i < nums.length; i++) {
    for (let j = 0; j < i; j++) {
      // Элемент j меньше — значит последовательность,
      // заканчивающуюся в j, можно продлить элементом i
      if (nums[j] < nums[i]) {
        dp[i] = Math.max(dp[i], dp[j] + 1);
      }
    }
  }

  // Ответ — лучшая из всех, а не последняя.
  // Math.max(...dp) — спред разворачивает массив в аргументы
  return Math.max(...dp);
}
```

### Разбор

- **Определение состояния с привязкой к «заканчивается в i»** — это то, что делает переход выразимым. Формулировка «`dp[i]` — НВП среди первых i элементов» звучит естественнее, но из неё переход не выводится: непонятно, можно ли продлить.
- **Ответ — максимум по массиву.** Частая ошибка — вернуть `dp[n-1]`.
- **`Math.max(...dp)`** — спред. Осторожно: на массивах длиной порядка 10⁵ спред может превысить лимит аргументов функции. Безопаснее `dp.reduce((a, b) => Math.max(a, b), 0)`. На собеседовании упомянуть это ограничение — плюс.

### Сложность

Время **O(n²)**, память **O(n)**.

Существует решение за **O(n log n)** через бинарный поиск по массиву «минимальных хвостов». Достаточно упомянуть его существование; писать обычно не просят.

## Задача 5. Максимальная сумма подмассива

**Условие.** Найти непрерывный подмассив с максимальной суммой.

Пример: `[-2, 1, -3, 4, -1, 2, 1, -5, 4]` → `6` (подмассив `[4, -1, 2, 1]`).

Известна как **алгоритм Кадане** — частный случай ДП, свёрнутый до двух переменных.

### Пять шагов

1. **Состояние:** `dp[i]` — максимальная сумма подмассива, **заканчивающегося в i**.
2. **Переход:** либо продлеваем предыдущий подмассив, либо начинаем новый с текущего элемента: `dp[i] = max(nums[i], dp[i-1] + nums[i])`.
3. **База:** `dp[0] = nums[0]`.
4. **Порядок:** слева направо.
5. **Ответ:** максимум по `dp`.

### Решение

```js
/**
 * Максимальная сумма непрерывного подмассива.
 * @param {number[]} nums
 * @returns {number}
 */
function maxSubArray(nums) {
  // Начинаем с первого элемента, а не с нуля:
  // массив может состоять целиком из отрицательных чисел,
  // и тогда ответ — наибольшее (наименее отрицательное) из них
  let currentSum = nums[0];   // лучшая сумма, заканчивающаяся здесь
  let bestSum = nums[0];      // лучшая сумма за всё время

  for (let i = 1; i < nums.length; i++) {
    // Ключевое решение: если накопленная сумма отрицательна,
    // она только ухудшит результат — выгоднее начать заново
    currentSum = Math.max(nums[i], currentSum + nums[i]);

    bestSum = Math.max(bestSum, currentSum);
  }

  return bestSum;
}
```

### Разбор

- **Инициализация `nums[0]`, а не нулём** — самая частая ошибка в этой задаче. С нуля функция вернёт `0` на массиве из одних отрицательных чисел, что неверно (пустой подмассив обычно не разрешён — уточните).
- **`Math.max(nums[i], currentSum + nums[i])`** — буквальная запись «начать заново или продлить».
- **Две переменные вместо массива** — состояние зависит только от предыдущего.

Время **O(n)**, память **O(1)**.

## Двумерное ДП

Когда состояние определяется двумя параметрами, таблица становится двумерной.

### Задача 6. Уникальные пути

**Условие.** Робот в левом верхнем углу сетки m×n. Может двигаться только вправо или вниз. Сколько путей до правого нижнего угла?

#### Пять шагов

1. **Состояние:** `dp[i][j]` — число путей до клетки (i, j).
2. **Переход:** в клетку можно попасть только сверху или слева: `dp[i][j] = dp[i-1][j] + dp[i][j-1]`.
3. **База:** первая строка и первый столбец — по одному пути (только прямо).
4. **Порядок:** по строкам сверху вниз, внутри строки слева направо — так оба слагаемых уже посчитаны.
5. **Ответ:** `dp[m-1][n-1]`.

```js
/**
 * Число путей из левого верхнего в правый нижний угол сетки.
 * Движение только вправо и вниз.
 * @param {number} m — строк
 * @param {number} n — столбцов
 * @returns {number}
 */
function uniquePaths(m, n) {
  // Матрица m×n, заполненная единицами.
  // Единицы сразу задают базу: первая строка и первый столбец
  const dp = Array.from({ length: m }, () => new Array(n).fill(1));

  // Начинаем с (1,1): нулевая строка и нулевой столбец — база
  for (let i = 1; i < m; i++) {
    for (let j = 1; j < n; j++) {
      dp[i][j] = dp[i - 1][j] + dp[i][j - 1];
    }
  }

  return dp[m - 1][n - 1];
}
```

**`Array.from({length: m}, () => new Array(n).fill(1))`** — создание матрицы. Через `new Array(m).fill(new Array(n))` все строки оказались бы **одним и тем же** массивом; см. [Структуры данных в JS](../struktury-dannyh-v-js/).

Время **O(m·n)**, память **O(m·n)**. Память сжимается до **O(n)**: хранить достаточно одну строку, обновляя её на месте.

### Задача 7. Наибольшая общая подпоследовательность

**Условие.** Найти длину наибольшей общей подпоследовательности двух строк.

Пример: `'abcde'` и `'ace'` → `3` (это `'ace'`).

Базовая задача двумерного ДП. На ней же строится расстояние Левенштейна и `git diff`.

#### Пять шагов

1. **Состояние:** `dp[i][j]` — длина НОП для первых `i` символов первой строки и первых `j` символов второй. Индексация **по длинам префиксов**, а не по позициям — поэтому таблица на единицу больше.
2. **Переход:** если `text1[i-1] === text2[j-1]`, символы совпали и их можно добавить к общей подпоследовательности: `dp[i-1][j-1] + 1`. Иначе один из символов не участвует: `max(dp[i-1][j], dp[i][j-1])`.
3. **База:** `dp[0][j] = dp[i][0] = 0` — с пустой строкой ничего не общего.
4. **Порядок:** по строкам.
5. **Ответ:** `dp[m][n]`.

```js
/**
 * Длина наибольшей общей подпоследовательности двух строк.
 * @param {string} text1
 * @param {string} text2
 * @returns {number}
 */
function longestCommonSubsequence(text1, text2) {
  const m = text1.length;
  const n = text2.length;

  // Таблица (m+1) × (n+1): нулевая строка и столбец — пустые префиксы.
  // Лишняя строка и столбец избавляют от проверок границ в переходе
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      // Осторожно с индексами: dp[i][j] соответствует
      // символам text1[i-1] и text2[j-1]
      if (text1[i - 1] === text2[j - 1]) {
        // Символы совпали — удлиняем НОП более коротких префиксов
        dp[i][j] = dp[i - 1][j - 1] + 1;
      } else {
        // Не совпали — выбрасываем один символ из одной из строк
        // и берём лучший вариант
        dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
      }
    }
  }

  return dp[m][n];
}
```

#### Разбор

- **Размер `(m+1) × (n+1)`** — стандартный приём двумерного ДП по строкам. Нулевая строка/столбец кодируют пустой префикс и убирают все проверки границ.
- **Сдвиг индексов `text1[i-1]`** — прямое следствие. Здесь ошибаются чаще всего; проговорите соответствие вслух до написания цикла.
- **`max(dp[i-1][j], dp[i][j-1])`** — «пропустить символ из первой строки» либо «из второй».

Время **O(m·n)**, память **O(m·n)** (сжимаемо до O(n)).

## Задача 8. Рюкзак 0/1

**Условие.** Есть предметы с весами и ценностями, и рюкзак вместимостью W. Каждый предмет можно взять **не более одного раза**. Максимальная суммарная ценность?

Классический шаблон, к которому сводится множество задач.

```js
/**
 * Задача о рюкзаке 0/1.
 * @param {number[]} weights — веса предметов
 * @param {number[]} values — ценности предметов
 * @param {number} capacity — вместимость рюкзака
 * @returns {number} максимальная ценность
 */
function knapsack(weights, values, capacity) {
  // dp[w] — максимальная ценность при вместимости ровно w
  const dp = new Array(capacity + 1).fill(0);

  for (let i = 0; i < weights.length; i++) {
    // Идём по вместимости В ОБРАТНОМ порядке.
    // Это гарантирует, что dp[w - weights[i]] ещё не обновлялся
    // на ТЕКУЩЕМ предмете, то есть предмет не будет взят дважды
    for (let w = capacity; w >= weights[i]; w--) {
      dp[w] = Math.max(
        dp[w],                              // не берём предмет i
        dp[w - weights[i]] + values[i]      // берём предмет i
      );
    }
  }

  return dp[capacity];
}
```

:::caution
**Направление внутреннего цикла — вся суть задачи о рюкзаке.**

- **Обратный порядок** (`w` убывает) → каждый предмет берётся не более одного раза. Это рюкзак 0/1.
- **Прямой порядок** (`w` возрастает) → предмет можно брать многократно. Это неограниченный рюкзак, к нему сводится задача о размене монет.

Одна строка меняет смысл задачи. Если запомнить только одно про ДП — пусть это будет она.

:::
Время **O(n · capacity)**, память **O(capacity)**.

## Как распознать задачу на ДП

Сигналы в условии:

- «максимальное / минимальное количество», «наибольшая / наименьшая»
- «сколькими способами»
- «возможно ли достичь»
- на каждом шаге есть выбор, и решения влияют на будущие
- перебор очевиден, но слишком медленный
- жадность даёт неверный ответ на контрпримере

Сигналы против ДП:

- нужно вернуть **все** варианты, а не их количество → это [перебор с возвратом](../rekursija-i-backtracking/)
- есть доказуемо корректный жадный критерий → жадность
- подзадачи не перекрываются → «разделяй и властвуй»

## Типичные ошибки

1. **Размытое определение состояния.** Если не можете описать `dp[i]` одним точным предложением — переход не выпишется. Тратьте время именно здесь.
2. **Забыто слово «заканчивающийся в i»** в определении. Из-за него ответ — максимум по массиву, а не последний элемент.
3. **Возврат `dp[n-1]` вместо максимума.**
4. **Неверная база.** Инициализация нулём вместо `nums[0]` в Кадане, забытый `dp[0] = 0` в размене монет.
5. **Перепутано направление внутреннего цикла** в рюкзаке.
6. **Сдвиг индексов** в двумерном ДП по строкам: `text1[i]` вместо `text1[i-1]`.
7. **`new Array(m).fill(new Array(n))`** — все строки это один массив.
8. **`MAX_SAFE_INTEGER` вместо `Infinity`** как маркер недостижимости.
9. **Попытка сразу написать таблицу**, минуя перебор. Если формула не видна — начните с рекурсии.
10. **Мемоизация без ключа по всем параметрам** — если состояние двумерное, ключ тоже должен быть.

## Чеклист

- Определите `dp[i]` одним предложением, прежде чем писать код
- Не видите перехода → напишите перебор, потом добавьте кеш
- Проверьте базу на минимальном входе: n = 0, n = 1, все элементы отрицательные
- Проверьте, откуда берётся ответ: `dp[n]` или максимум по массиву
- Переход смотрит на фиксированное число предыдущих состояний → память сжимается до O(1)
- Двумерное ДП по строкам → таблица `(m+1) × (n+1)`, помните про сдвиг индексов
- Рюкзак: предмет один раз → обратный цикл; многократно → прямой
- Проговорите путь «перебор → мемоизация → таблица» вслух, даже если сразу знаете ответ

## Задачи для тренировки

1. **Минимальная сумма пути в сетке** — двумерное ДП, простая.
2. **Разбиение строки по словарю** — можно ли разрезать строку на слова из словаря.
3. **Дом грабителя II** — дома по кругу, первый и последний соседние.
4. **Расстояние Левенштейна** — минимальное число правок между строками.
5. **Разбиение на два подмножества равной суммы** — сводится к рюкзаку.
6. **Наибольшая палиндромная подпоследовательность** — сводится к НОП строки с её разворотом.
7. **Лучшее время покупки и продажи акций с ограничениями** — ДП по состояниям, трудная.
