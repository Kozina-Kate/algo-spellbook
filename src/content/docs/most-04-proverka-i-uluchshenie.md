Простое решение корректно, но корректность и эффективность — разные свойства. Теперь посмотрим, сколько работы оно выполняет при росте входа.

:::note[Перед началом]
**Занятие 4 из 4 · 25–30 минут**

**Нужно знать:** простое решение и методы `Set`. **После занятия:** сможете найти дорогую повторяющуюся операцию и обосновать улучшение.
:::

## Сначала подтверждаем корректность

Не оптимизируйте код, который ещё не проверен. Для `missingNumber` нужен как минимум такой набор:

| Случай | Вход | Ожидаемый ответ |
| --- | --- | ---: |
| пропуск в середине | `[3, 0, 1]` | 2 |
| пропуск в начале | `[1]` | 0 |
| пропуск в конце | `[0, 1]` | 2 |
| произвольный порядок | `[4, 2, 1, 0]` | 3 |

Простая реализация проходит все четыре случая.

## Ищем повторную работу

```js
function missingNumber(numbers) {
  for (let candidate = 0; candidate <= numbers.length; candidate += 1) {
    if (!numbers.includes(candidate)) {
      return candidate;
    }
  }
}
```

Внешний цикл перебирает кандидатов. Внутри каждой итерации `includes` может просмотреть весь массив от начала до конца.

Для массива длины `n` получается примерно такая картина:

```text
до n кандидатов × до n просмотренных элементов
```

Если длина увеличится в 10 раз, количество сравнений в худшем случае вырастет примерно в 100 раз. Позже это будет записываться как `O(n²)`.

## Формулируем узкое место

**Узкое место** — операция, на которую уходит основная часть работы.

Здесь проблема не в самом цикле кандидатов, а в повторном вопросе:

> Есть ли это число в массиве?

Мы много раз заново просматриваем одни и те же элементы. Значит, нужна структура, которая запомнит все присутствующие числа и будет быстро отвечать на вопрос о наличии.

## Меняем Array на Set для поиска

```js
const presentNumbers = new Set(numbers);
```

Конструктор `new Set(numbers)` один раз проходит по массиву и создаёт множество его значений. Затем `presentNumbers.has(candidate)` проверяет наличие без последовательного просмотра всего массива.

## Улучшенное решение

```js
function missingNumber(numbers) {
  const presentNumbers = new Set(numbers);

  for (let candidate = 0; candidate <= numbers.length; candidate += 1) {
    if (!presentNumbers.has(candidate)) {
      return candidate;
    }
  }
}
```

### Разбор изменений

- `new Set(numbers)` подготавливает данные для быстрых проверок.
- Цикл кандидатов и его границы не изменились.
- `presentNumbers.has(candidate)` заменяет `numbers.includes(candidate)`.
- Условие и `return` сохраняют прежнюю логику.

Мы изменили способ хранения информации, но не изменили контракт функции.

## Сравниваем варианты

| Свойство | Массив и `includes` | `Set` и `has` |
| --- | --- | --- |
| Корректность | да | да |
| Подготовка дополнительной структуры | нет | один проход по массиву |
| Проверка одного кандидата | до полного прохода | в среднем постоянное время |
| Время при росте входа | `O(n²)` | `O(n)` |
| Дополнительная память | `O(1)` | `O(n)` |
| Простота первого объяснения | максимальная | немного сложнее |

`Set` ускоряет программу ценой дополнительной памяти. Такой обмен — один из главных мотивов алгоритмов.

:::note
Обозначения `O(n)` и `O(n²)` пока можно читать как «растёт примерно вместе с длиной» и «растёт примерно как квадрат длины». Точный язык и правила подсчёта — в следующей главе.
:::

## Проверяем, что оптимизация не изменила ответ

После изменения структуры данных снова запускаем **весь** набор проверок:

```js
console.log(missingNumber([3, 0, 1]) === 2);
console.log(missingNumber([1]) === 0);
console.log(missingNumber([0, 1]) === 2);
console.log(missingNumber([4, 2, 1, 0]) === 3);
```

Ожидаемый вывод — четыре значения `true`.

## Предскажите результат

```js
const numbers = [4, 2, 1, 0];
const presentNumbers = new Set(numbers);

console.log(presentNumbers.has(2));
console.log(presentNumbers.has(3));
console.log(presentNumbers.size);
```

<details>
<summary>Ответ</summary>

`has(2)` вернёт `true`, `has(3)` — `false`. Размер множества равен `4`, потому что во входе четыре различных числа.

</details>

## Самостоятельная практика

Возьмите вход `[5, 0, 1, 3, 2]` и:

1. запишите ожидаемый ответ;
2. пройдите улучшенный код вручную;
3. перечислите содержимое `presentNumbers`;
4. укажите кандидата, на котором выполнится `return`;
5. объясните одним предложением, почему `Set` быстрее повторных `includes`.

<details>
<summary>Решение</summary>

Полный диапазон — от `0` до `5`. Отсутствует `4`. Множество содержит `5`, `0`, `1`, `3`, `2`. Кандидаты `0`, `1`, `2`, `3` присутствуют, на кандидате `4` метод `has` вернёт `false`, и функция вернёт `4`.

</details>
