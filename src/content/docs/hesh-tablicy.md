## Что такое хеш-таблица

**Хеш-таблица (hash table, хеш-мапа)** — структура данных для хранения пар «ключ → значение» с доступом за O(1) в среднем.

Как она работает. Есть массив ячеек («корзин», buckets). Есть **хеш-функция** — функция, которая превращает ключ любого типа в число. Это число по остатку от деления на размер массива даёт индекс корзины. Чтобы найти значение по ключу, не нужно перебирать — достаточно посчитать хеш и прыгнуть сразу в нужную ячейку.

**Коллизия** — ситуация, когда два разных ключа дали один индекс. Решается по-разному: в каждой корзине держат список элементов, либо ищут следующую свободную ячейку. Из-за коллизий O(1) — это «в среднем»; в патологическом худшем случае может выродиться в O(n), но на собеседовании достаточно сказать «O(1) в среднем».

В JavaScript хеш-таблицы — это `Map`, `Set` и обычный объект. Реализовывать их руками не нужно, нужно понимать, **когда** их доставать.

## Ключевая идея: обменять память на время

Наивное решение ищет что-то повторным проходом по массиву — это O(n) на каждый поиск. Хеш-таблица заранее запоминает, что где лежит, и поиск становится O(1). Платим памятью O(n), выигрываем во времени.

Формулировка для собеседования: **«Здесь я трачу O(n) дополнительной памяти, чтобы убрать вложенный цикл и получить O(n) по времени вместо O(n²)».**

## Как распознать задачу на хеш-таблицу

Признаки в условии:

- «найти пару элементов, которые...»
- «есть ли дубликаты»
- «сколько раз встречается»
- «сгруппировать по признаку»
- «найти первый неповторяющийся»
- «являются ли строки анаграммами»
- в наивном решении вы пишете `arr.includes(...)` или `indexOf` внутри цикла

## Задача 1. Сумма двух (Two Sum)

**Условие.** Дан массив целых чисел `nums` и число `target`. Найти индексы двух различных элементов, сумма которых равна `target`. Гарантируется, что ответ существует и он единственный.

Пример: `nums = [2, 7, 11, 15]`, `target = 9` → `[0, 1]`, потому что `2 + 7 = 9`.

### Наивное решение

```js
function twoSumNaive(nums, target) {
  for (let i = 0; i < nums.length; i++) {
    for (let j = i + 1; j < nums.length; j++) {
      if (nums[i] + nums[j] === target) return [i, j];
    }
  }
  return [];
}
// Время O(n²), память O(1)
```

### Ход мысли

Что мы делаем лишний раз? Для каждого `nums[i]` мы **ищем** по всему массиву число `target - nums[i]`. Этот поиск — O(n).

Назовём `target - nums[i]` **дополнением (complement)**: число, которого не хватает до цели. Если бы мы могли спрашивать «а встречалось ли уже число X?» за O(1) — задача решилась бы одним проходом.

Именно это умеет `Map`. Идём по массиву слева направо и храним в `Map` соответствие **значение → его индекс** для всех уже просмотренных элементов. Для текущего элемента считаем дополнение и проверяем, лежит ли оно в `Map`.

Почему достаточно смотреть только назад: любая пара `(i, j)` с `i < j` будет обнаружена в момент, когда мы дойдём до `j` — потому что `i` к тому времени уже в `Map`.

### Решение

```js
/**
 * Находит индексы двух чисел, дающих в сумме target.
 * @param {number[]} nums — входной массив чисел
 * @param {number} target — искомая сумма
 * @returns {number[]} пара индексов, либо пустой массив
 */
function twoSum(nums, target) {
  // seen хранит: значение элемента → его индекс.
  // Кладём сюда только те элементы, которые уже прошли.
  const seen = new Map();

  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];  // чего не хватает до target

    // has() — проверка наличия ключа за O(1).
    // Если дополнение уже встречалось — пара найдена.
    if (seen.has(complement)) {
      // get() возвращает индекс, под которым лежало дополнение.
      // Он меньше i, поэтому ставим его первым.
      return [seen.get(complement), i];
    }

    // Дополнение не нашли — запоминаем текущий элемент,
    // он может стать дополнением для кого-то справа.
    seen.set(nums[i], i);
  }

  return [];  // по условию сюда не дойдём, но функция должна что-то вернуть
}
```

### Разбор функций

- **`new Map()`** — создаёт пустую хеш-таблицу. Выбрана вместо объекта, потому что ключи здесь числа, а объект превратил бы их в строки.
- **`map.has(key)`** — есть ли такой ключ. Возвращает `true`/`false`, O(1) в среднем.
- **`map.get(key)`** — значение по ключу, либо `undefined`. O(1).
- **`map.set(key, value)`** — записать пару, перезаписав существующую. O(1).
- **`nums.length`** — свойство массива, количество элементов.

### Сложность

Время **O(n)** — один проход, внутри только O(1)-операции. Память **O(n)** — в худшем случае в `Map` попадут все элементы.

### Ловушки

- **Порядок в ответе.** `seen.get(complement)` — индекс более раннего элемента, он должен идти первым.
- **Запись до проверки.** Если сначала `seen.set(...)`, а потом проверять — при `target = 6` и элементе `3` функция найдёт «пару» из одного и того же элемента с самим собой. Проверка строго до записи.
- **Дубликаты.** `seen.set` перезапишет индекс для повторного значения. Для этой задачи не страшно: ответ единственный, и более ранний индекс уже будет найден раньше, чем произойдёт перезапись.

## Задача 2. Группировка анаграмм

**Условие.** Дан массив строк. Сгруппировать анаграммы.

**Анаграмма** — слово, полученное перестановкой букв другого: `eat`, `tea`, `ate` — анаграммы друг друга.

Пример: `['eat','tea','tan','ate','nat','bat']` → `[['eat','tea','ate'], ['tan','nat'], ['bat']]`.

### Ход мысли

Нужен **канонический ключ** — одинаковое представление для всех анаграмм одной группы. Если отсортировать буквы слова, все анаграммы дадут одну и ту же строку: `eat`, `tea`, `ate` → все `aet`.

Дальше — обычная группировка по ключу через `Map`.

### Решение

```js
/**
 * Группирует строки-анаграммы.
 * @param {string[]} strs
 * @returns {string[][]} массив групп
 */
function groupAnagrams(strs) {
  // ключ (отсортированные буквы) → массив исходных слов
  const groups = new Map();

  for (const word of strs) {
    // split('') разбивает строку в массив символов: 'eat' → ['e','a','t']
    // sort() сортирует массив строк лексикографически (для букв это то, что нужно)
    // join('') склеивает обратно: ['a','e','t'] → 'aet'
    const key = word.split('').sort().join('');

    // Если группы с таким ключом ещё нет — создаём пустой массив
    if (!groups.has(key)) {
      groups.set(key, []);
    }

    // get(key) возвращает ССЫЛКУ на массив, поэтому push меняет
    // сохранённый в Map массив, повторный set не нужен
    groups.get(key).push(word);
  }

  // values() отдаёт итератор значений; спред превращает его в массив
  return [...groups.values()];
}
```

### Разбор функций

- **`String.prototype.split('')`** — строка → массив символов. O(k), где k — длина слова.
- **`Array.prototype.sort()`** — здесь **без компаратора намеренно**: элементы уже строки, а дефолтная сортировка как раз лексикографическая. Для чисел компаратор был бы обязателен.
- **`Array.prototype.join('')`** — массив → строка без разделителя.
- **`map.values()`** — итератор по значениям. Сам по себе не массив, поэтому оборачиваем в `[...]`.
- **`for...of`** — перебор значений итерируемого объекта. Для массива даёт элементы (в отличие от `for...in`, который даёт индексы-строки и в алгоритмах не используется).

### Сложность

Пусть n слов, максимальная длина слова k. Время **O(n · k log k)** — для каждого слова сортировка его букв. Память **O(n · k)** на хранение групп.

### Оптимизация: ключ без сортировки

Если строки только из строчных латинских букв, ключ можно строить за O(k) — через счётчик букв:

```js
function anagramKey(word) {
  // 26 ячеек — по одной на каждую букву латиницы
  const counts = new Array(26).fill(0);
  const aCode = 'a'.charCodeAt(0);   // 97

  for (const ch of word) {
    // charCodeAt(0) — числовой код символа.
    // Вычитая код 'a', получаем 0 для 'a', 1 для 'b', ... 25 для 'z'
    counts[ch.charCodeAt(0) - aCode]++;
  }

  // join('#') — разделитель обязателен: без него [1,11] и [11,1]
  // дали бы одинаковую строку '111'
  return counts.join('#');
}
```

- **`new Array(26).fill(0)`** — массив из 26 нулей. `fill(v)` заполняет все ячейки значением `v`.
- **`charCodeAt(i)`** — код символа в позиции `i`. Для латиницы совпадает с ASCII.

Итого время **O(n · k)**. Это хороший ответ на вопрос интервьюера «а можно быстрее?».

## Задача 3. Первый неповторяющийся символ

**Условие.** Вернуть индекс первого символа строки, который встречается ровно один раз. Если такого нет — вернуть −1.

Пример: `'leetcode'` → `0` (символ `l`); `'loveleetcode'` → `2` (символ `v`).

### Ход мысли

Одним проходом не обойтись: чтобы понять, что символ не повторяется, нужно знать про всю строку. Значит, два прохода. Первый — посчитать частоты. Второй — найти первый символ с частотой 1.

Два последовательных прохода — это всё ещё O(n), см. [Сложность](../slozhnost-algoritmov/).

### Решение

```js
/**
 * Индекс первого неповторяющегося символа, или -1.
 * @param {string} s
 * @returns {number}
 */
function firstUniqChar(s) {
  const freq = new Map();

  // Проход 1: считаем, сколько раз встречается каждый символ
  for (const ch of s) {
    // get вернёт undefined для нового символа; `|| 0` подставит ноль
    freq.set(ch, (freq.get(ch) || 0) + 1);
  }

  // Проход 2: идём по индексам и ищем первый с частотой 1.
  // Порядок важен — нужен именно ПЕРВЫЙ, поэтому идём по строке, а не по Map
  for (let i = 0; i < s.length; i++) {
    if (freq.get(s[i]) === 1) return i;
  }

  return -1;
}
```

### Разбор функций

- **`for (const ch of s)`** — строка итерируема, перебор даёт символы по одному.
- **`(freq.get(ch) || 0) + 1`** — идиома инкремента счётчика. `||` возвращает правый операнд, если левый ложный (`undefined` ложный).
- **`s[i]`** — символ по индексу, O(1).

Второй проход можно вести и по `Map` — в `Map` сохраняется порядок вставки, а значит первый символ с частотой 1 в переборе `Map` и будет ответом. Но тогда придётся отдельно доставать индекс, поэтому проход по строке проще.

### Сложность

Время **O(n)** — два прохода. Память **O(k)**, где k — размер алфавита (для латиницы это константа, то есть фактически O(1)).

## Задача 4. Содержит ли массив дубликаты

**Условие.** Вернуть `true`, если в массиве есть хотя бы одно повторяющееся значение.

### Решение

```js
// Вариант 1: самый короткий
function containsDuplicate(nums) {
  // Set отбрасывает дубликаты. Если размер уменьшился — дубликаты были
  return new Set(nums).size !== nums.length;
}

// Вариант 2: с досрочным выходом — на практике быстрее
function containsDuplicateEarly(nums) {
  const seen = new Set();
  for (const n of nums) {
    // has() — O(1). Нашли повтор — выходим, не дочитывая массив
    if (seen.has(n)) return true;
    seen.add(n);
  }
  return false;
}
```

### Разбор функций

- **`new Set(iterable)`** — множество уникальных значений из коллекции.
- **`set.size`** — количество элементов, свойство.
- **`set.has(v)` / `set.add(v)`** — проверка и добавление, O(1).

Обе версии — O(n) по времени и памяти. Второй вариант предпочтительнее: он не строит множество целиком, если дубликат нашёлся в начале. На собеседовании стоит назвать оба и объяснить разницу — это показывает внимание к деталям.

## Задача 5. Подмассив с нулевой суммой

**Условие.** Есть ли в массиве непустой непрерывный подмассив с суммой 0?

Пример: `[4, 2, -3, 1, 6]` → `true`, потому что `2 + (-3) + 1 = 0`.

### Ход мысли

Здесь хеш-таблица работает вместе с идеей префиксных сумм ([отдельная страница](../prefiksnye-summy/)).

**Префиксная сумма** `P[i]` — сумма первых `i` элементов. Сумма подмассива с `i` по `j` равна `P[j+1] − P[i]`. Если эта разность равна нулю, значит `P[j+1] === P[i]` — две **равные** префиксные суммы.

Отсюда критерий: подмассив с нулевой суммой существует тогда и только тогда, когда среди префиксных сумм есть два одинаковых значения.

### Решение

```js
function hasZeroSumSubarray(nums) {
  // Пустой префикс имеет сумму 0 — его обязательно кладём заранее,
  // иначе потеряется случай, когда нулевой подмассив начинается с индекса 0
  const prefixSums = new Set([0]);
  let sum = 0;

  for (const n of nums) {
    sum += n;                        // текущая префиксная сумма
    if (prefixSums.has(sum)) return true;  // такая уже была → между ними ноль
    prefixSums.add(sum);
  }

  return false;
}
```

Время **O(n)**, память **O(n)**.

Этот приём — «храню в хеш-таблице увиденные префиксные суммы» — обобщается на задачу «сколько подмассивов имеют сумму k», которая встречается на собеседованиях очень часто.

## Типичные ошибки

1. **Использовать объект вместо `Map` для числовых ключей.** Ключи станут строками; при смешанных типах появятся неочевидные совпадения.
2. **Проверять `if (map.get(key))` вместо `map.has(key)`.** Если хранимое значение `0`, проверка ложно провалится.
3. **Забывать про порядок «проверить, потом записать»** в Two Sum.
4. **Не класть начальное значение** (`Set([0])`, `Map([[0, 1]])`) в задачах с префиксными суммами — теряется случай подмассива от начала.
5. **Строить ключ конкатенацией без разделителя** — `[1,11]` и `[11,1]` дадут одинаковый ключ.
6. **Сообщать O(1) по памяти**, когда используется `Map`. Память O(n) — это цена метода, её нужно честно назвать.

## Чеклист

- Вижу вложенный цикл, где внутренний ищет элемент → `Map`/`Set`
- Нужен счётчик → `freq.set(x, (freq.get(x) || 0) + 1)`
- Нужна группировка → построить канонический ключ, `Map: ключ → массив`
- Нужна проверка наличия → `Set`
- Нужен индекс найденного → `Map: значение → индекс`

## Задачи для тренировки

1. **Пересечение двух массивов** — вернуть общие элементы без повторов.
2. **Валидная анаграмма** — являются ли две строки анаграммами (O(n), без сортировки).
3. **Большинство элементов** — найти элемент, встречающийся более n/2 раз.
4. **Сколько подмассивов имеют сумму k** — обобщение задачи 5.
5. **Самый длинный подмассив из одинаковых элементов после k замен** — комбинация с [окном](../skolzjashhee-okno/).
