Частный, но очень частый случай двух указателей: оба идут в одну сторону, а между ними — «окно», подотрезок, который мы поддерживаем в актуальном состоянии.

← [К оглавлению](../)

## Что это

**Подмассив (подотрезок, subarray)** — непрерывный кусок массива. `[2, 3]` — подмассив `[1, 2, 3, 4]`, а `[1, 3]` — нет, потому что элементы не подряд.

**Подпоследовательность (subsequence)** — элементы в том же порядке, но не обязательно подряд. `[1, 3]` — подпоследовательность. Разницу спрашивают на собеседованиях, путать её нельзя.

**Скользящее окно (sliding window)** — техника, при которой мы держим два индекса, `left` и `right`, обозначающих границы подотрезка, и двигаем их вправо, пересчитывая характеристику окна за O(1) вместо полного пересчёта за O(k).

Ключевая идея: когда окно сдвигается на одну позицию, меняется всего два элемента — один входит справа, один выходит слева. Значит, сумму/счётчики можно **обновить**, а не считать заново.

## Два вида окна

### Окно фиксированного размера

Размер `k` задан в условии. Правая граница двигается, левая следует за ней на расстоянии `k`.

```js
let sum = 0;
for (let right = 0; right < arr.length; right++) {
  sum += arr[right];                 // элемент вошёл в окно

  if (right >= k) {
    sum -= arr[right - k];           // элемент вышел из окна слева
  }

  if (right >= k - 1) {
    // окно полной длины k готово — обрабатываем
  }
}
```

### Окно переменного размера

Размер не задан; окно растёт, пока условие выполняется, и сжимается, когда нарушается.

```js
let left = 0;
for (let right = 0; right < arr.length; right++) {
  // расширяем окно: добавили arr[right]

  while (/* условие нарушено */) {
    // сжимаем окно слева: убрали arr[left]
    left++;
  }

  // здесь окно [left..right] валидно — обновляем ответ
}
```

:::note
Почему внутренний `while` не делает алгоритм квадратичным. `left` за всё время выполнения только увеличивается и не может превысить n. Значит, суммарно внутренний цикл сделает не больше n шагов **за весь алгоритм**, а не n шагов на каждой итерации внешнего. Итого O(n). Это рассуждение называется **амортизационным анализом**, и его стоит проговорить вслух — оно часто становится отдельным вопросом.

:::
## Когда применять

Признаки в условии:

- «непрерывный подмассив / подстрока»
- «максимальный / минимальный по длине отрезок, удовлетворяющий условию»
- «ровно k элементов», «не более k различных»
- «без повторяющихся символов»
- наивное решение — два вложенных цикла по началу и концу отрезка

:::caution
Окно переменного размера корректно работает, когда характеристика **монотонна**: расширение окна не может «улучшить» нарушенное условие. Для сумм это верно только при **неотрицательных** элементах — если в массиве есть отрицательные числа, добавление элемента может уменьшить сумму, и окно ломается. В таких случаях нужны [префиксные суммы](../prefiksnye-summy/) с хеш-таблицей.

:::
## Задача 1. Максимальная сумма подмассива длины k

**Условие.** Найти максимальную сумму непрерывного подмассива ровно из `k` элементов.

Пример: `[2, 1, 5, 1, 3, 2]`, `k = 3` → `9` (подмассив `[5, 1, 3]`).

### Наивное решение

```js
function maxSumNaive(arr, k) {
  let best = -Infinity;
  for (let i = 0; i + k <= arr.length; i++) {
    let sum = 0;
    for (let j = i; j < i + k; j++) sum += arr[j];  // пересчитываем целиком
    best = Math.max(best, sum);
  }
  return best;
}
// O(n · k)
```

### Ход мысли

Соседние окна отличаются двумя элементами. Окно `[i..i+k-1]` и окно `[i+1..i+k]` имеют общую часть — пересчитывать её бессмысленно. Достаточно: прибавить вошедший элемент, вычесть вышедший.

### Решение

```js
/**
 * Максимальная сумма подмассива фиксированной длины k.
 * @param {number[]} arr
 * @param {number} k — длина окна
 * @returns {number} максимальная сумма, или null если массив короче k
 */
function maxSumFixedWindow(arr, k) {
  // Краевой случай: окна длины k просто не существует
  if (arr.length < k || k <= 0) return null;

  let windowSum = 0;

  // Считаем сумму самого первого окна: элементы с 0 по k-1
  for (let i = 0; i < k; i++) {
    windowSum += arr[i];
  }

  let best = windowSum;

  // Двигаем окно вправо: right — индекс ВХОДЯЩЕГО элемента
  for (let right = k; right < arr.length; right++) {
    // Добавили правый, убрали тот, что выпал слева.
    // right - k — индекс элемента, который только что покинул окно
    windowSum += arr[right] - arr[right - k];
    best = Math.max(best, windowSum);
  }

  return best;
}
```

### Разбор

- **`arr[right] - arr[right - k]`** — одной строкой: вошёл `arr[right]`, вышел `arr[right - k]`. Проверьте на примере: при `k = 3` и `right = 3` окно было `[0,1,2]`, стало `[1,2,3]`; вышел индекс `0 = 3 - 3`. Сходится.
- **`Math.max(best, windowSum)`** — обновление рекорда.
- **`return null`** — явная обработка краевого случая. На собеседовании уточните у интервьюера, что возвращать в такой ситуации.

### Сложность

Время **O(n)** вместо O(n·k). Память **O(1)**.

## Задача 2. Самая длинная подстрока без повторяющихся символов

**Условие.** Найти длину самой длинной подстроки, в которой нет повторяющихся символов.

Пример: `'abcabcbb'` → `3` (подстрока `'abc'`). `'bbbbb'` → `1`. `'pwwkew'` → `3` (`'wke'`).

### Ход мысли

Окно переменного размера. Расширяем вправо, пока символы уникальны. Как только входящий символ уже есть в окне — сжимаем слева, пока дубликат не уйдёт.

Чтобы проверять «есть ли символ в окне» за O(1), держим `Set` с символами текущего окна.

### Решение через Set

```js
/**
 * Длина самой длинной подстроки без повторов.
 * @param {string} s
 * @returns {number}
 */
function lengthOfLongestSubstring(s) {
  const inWindow = new Set();   // символы, которые сейчас внутри окна
  let left = 0;
  let best = 0;

  for (let right = 0; right < s.length; right++) {
    const ch = s[right];

    // Пока входящий символ уже есть в окне — сжимаем окно слева.
    // Гарантированно завершится: дубликат где-то внутри окна,
    // и рано или поздно left до него дойдёт
    while (inWindow.has(ch)) {
      inWindow.delete(s[left]);   // символ покидает окно
      left++;
    }

    inWindow.add(ch);   // теперь можно добавить входящий

    // Длина окна [left..right] — это right - left + 1.
    // «+1», потому что обе границы включительно
    best = Math.max(best, right - left + 1);
  }

  return best;
}
```

### Разбор функций

- **`set.has(v)` / `set.add(v)` / `set.delete(v)`** — проверка, добавление, удаление за O(1).
- **`right - left + 1`** — длина отрезка с включёнными границами. Забыть `+1` — классическая ошибка на единицу (**off-by-one error**). Проверяйте на окне из одного элемента: `left === right`, длина должна быть 1.

### Оптимизация через Map

Вместо посимвольного сжатия можно прыгнуть сразу за позицию предыдущего вхождения символа:

```js
function lengthOfLongestSubstringFast(s) {
  const lastSeen = new Map();   // символ → индекс последнего вхождения
  let left = 0;
  let best = 0;

  for (let right = 0; right < s.length; right++) {
    const ch = s[right];

    // Если символ встречался И его вхождение внутри текущего окна —
    // двигаем левую границу за него.
    // Проверка >= left обязательна: вхождение могло быть ДО окна,
    // тогда двигать left назад нельзя
    if (lastSeen.has(ch) && lastSeen.get(ch) >= left) {
      left = lastSeen.get(ch) + 1;
    }

    lastSeen.set(ch, right);
    best = Math.max(best, right - left + 1);
  }

  return best;
}
```

Асимптотика та же — O(n), но константа меньше: `left` перемещается прыжками. Проверка `>= left` — тонкое место, на котором часто ловят; объясните её вслух.

### Сложность

Время **O(n)**, память **O(min(n, размер алфавита))**.

## Задача 3. Минимальный подмассив с суммой не меньше target

**Условие.** Массив **положительных** чисел и число `target`. Найти минимальную длину непрерывного подмассива с суммой ≥ `target`. Если такого нет — вернуть 0.

Пример: `target = 7`, `[2, 3, 1, 2, 4, 3]` → `2` (подмассив `[4, 3]`).

### Ход мысли

Здесь окно сжимается не при нарушении условия, а наоборот — **когда условие уже выполнено**: мы хотим найти минимальную длину, поэтому, добившись суммы ≥ target, пробуем сжать окно, пока условие ещё держится.

Положительность элементов критична: она гарантирует, что сумма растёт при расширении и убывает при сжатии.

### Решение

```js
/**
 * Минимальная длина подмассива с суммой >= target.
 * @param {number} target
 * @param {number[]} nums — массив ПОЛОЖИТЕЛЬНЫХ чисел
 * @returns {number} минимальная длина, или 0 если подходящего нет
 */
function minSubArrayLen(target, nums) {
  let left = 0;
  let sum = 0;
  // Начинаем с «бесконечности», чтобы любая найденная длина оказалась меньше
  let best = Infinity;

  for (let right = 0; right < nums.length; right++) {
    sum += nums[right];   // расширяем окно вправо

    // Пока условие выполняется — фиксируем ответ и сжимаем слева.
    // Именно while, а не if: возможно, сжать удастся несколько раз подряд
    while (sum >= target) {
      best = Math.min(best, right - left + 1);
      sum -= nums[left];
      left++;
    }
  }

  // Если best не изменился — подходящего подмассива не было
  return best === Infinity ? 0 : best;
}
```

### Разбор

- **`Infinity`** — стартовое значение для поиска минимума: больше любого числа.
- **`best === Infinity ? 0 : best`** — тернарный оператор: `условие ? значение_если_истина : значение_если_ложь`. Проверка «нашли ли мы вообще хоть что-то».
- **`while`, а не `if`** — после добавления большого элемента окно может сжаться сразу на несколько позиций.

### Сложность

Время **O(n)** — `left` и `right` суммарно проходят массив по разу. Память **O(1)**.

## Задача 4. Максимум в каждом окне размера k

**Условие.** Для каждого окна длины `k` вернуть максимум.

Пример: `[1,3,-1,-3,5,3,6,7]`, `k = 3` → `[3, 3, 5, 5, 6, 7]`.

### Ход мысли

Наивно — для каждого окна искать максимум за O(k), итого O(n·k). Нужно быстрее.

Приём — **монотонный дек** (двусторонняя очередь, в которой значения убывают). Храним в деке **индексы** элементов-кандидатов на максимум. Инвариант: значения по этим индексам убывают слева направо, поэтому максимум окна всегда лежит в голове дека.

Когда приходит новый элемент, все кандидаты с меньшим значением становятся бесполезны: новый элемент и больше, и «свежее» — он останется в окне дольше. Поэтому их выбрасываем с хвоста.

Подробнее про монотонные структуры — [Стек и очередь](../stek-i-ochered/).

### Решение

```js
/**
 * Максимум в каждом окне длины k.
 * @param {number[]} nums
 * @param {number} k
 * @returns {number[]} массив максимумов, длина nums.length - k + 1
 */
function maxSlidingWindow(nums, k) {
  const result = [];
  // deque хранит ИНДЕКСЫ. Значения по ним убывают от головы к хвосту
  const deque = [];

  for (let right = 0; right < nums.length; right++) {
    // 1. Удаляем из головы индексы, выпавшие за левую границу окна.
    // Левая граница текущего окна — right - k + 1
    if (deque.length > 0 && deque[0] <= right - k) {
      deque.shift();
    }

    // 2. Удаляем с хвоста всех кандидатов, которые меньше входящего:
    // они уже никогда не станут максимумом
    while (deque.length > 0 && nums[deque[deque.length - 1]] < nums[right]) {
      deque.pop();
    }

    // 3. Добавляем текущий индекс
    deque.push(right);

    // 4. Окно набрало полную длину — голова дека и есть максимум
    if (right >= k - 1) {
      result.push(nums[deque[0]]);
    }
  }

  return result;
}
```

### Разбор функций

- **`deque[deque.length - 1]`** — последний элемент массива (хвост дека).
- **`deque.pop()`** — удалить с конца, O(1).
- **`deque.shift()`** — удалить с начала, формально O(n). Здесь это происходит не больше одного раза за итерацию и суммарно не больше n раз, так что на общую оценку не влияет. На собеседовании отметьте это отдельно — и скажите, что в проде взяли бы кольцевой буфер.
- **`right - k`** — последний индекс, который уже вне окна.

### Сложность

Время **O(n)** — каждый индекс добавляется и удаляется ровно один раз. Память **O(k)**.

## Задача 5. Перестановка одной строки внутри другой

**Условие.** Содержит ли строка `s2` подстроку, которая является перестановкой строки `s1`?

Пример: `s1 = 'ab'`, `s2 = 'eidbaooo'` → `true` (подстрока `'ba'`).

### Ход мысли

Перестановка `s1` — это подстрока той же длины с тем же **составом букв**. Значит, окно фиксированной длины `s1.length`, а сравниваем частотные словари.

Сравнивать словари целиком на каждом шаге — O(26) на шаг; это константа, но можно и аккуратнее — вести счётчик совпавших букв. Начнём с понятной версии.

### Решение

```js
/**
 * Есть ли в s2 подстрока — перестановка s1.
 * @param {string} s1
 * @param {string} s2
 * @returns {boolean}
 */
function checkInclusion(s1, s2) {
  // Окно длиннее строки — перестановки быть не может
  if (s1.length > s2.length) return false;

  const A_CODE = 'a'.charCodeAt(0);
  const need = new Array(26).fill(0);    // сколько каких букв нужно
  const window = new Array(26).fill(0);  // сколько каких букв в текущем окне

  // Считаем эталонные частоты и одновременно заполняем первое окно
  for (let i = 0; i < s1.length; i++) {
    need[s1.charCodeAt(i) - A_CODE]++;
    window[s2.charCodeAt(i) - A_CODE]++;
  }

  if (sameCounts(need, window)) return true;

  // Двигаем окно длины s1.length по s2
  for (let right = s1.length; right < s2.length; right++) {
    window[s2.charCodeAt(right) - A_CODE]++;              // вошла буква
    window[s2.charCodeAt(right - s1.length) - A_CODE]--;  // вышла буква

    if (sameCounts(need, window)) return true;
  }

  return false;
}

/**
 * Совпадают ли два массива счётчиков поэлементно.
 * @param {number[]} a
 * @param {number[]} b
 * @returns {boolean}
 */
function sameCounts(a, b) {
  for (let i = 0; i < a.length; i++) {
    if (a[i] !== b[i]) return false;
  }
  return true;
}
```

### Разбор

- **`s.charCodeAt(i) - A_CODE`** — превращает букву в индекс 0..25. Массив из 26 чисел здесь быстрее `Map`, потому что алфавит фиксирован.
- **`sameCounts`** — вынесена в отдельную функцию ради читаемости. Её стоимость O(26) = O(1), поэтому на асимптотику она не влияет.
- **`right - s1.length`** — индекс выходящей буквы, та же арифметика, что в задаче 1.

### Сложность

Время **O(n)**, где n — длина `s2` (множитель 26 — константа). Память **O(1)** — два массива фиксированного размера.

## Типичные ошибки

1. **Забыт `+1` в длине окна.** `right - left` вместо `right - left + 1`.
2. **`if` вместо `while`** при сжатии окна — за один шаг сжать может быть недостаточно.
3. **Обновление ответа не в том месте.** Для «максимальной длины» ответ обновляют **после** восстановления валидности окна; для «минимальной длины» — **внутри** цикла сжатия, пока условие ещё выполняется.
4. **Применение окна к массиву с отрицательными числами** в задачах на сумму. Условие монотонности нарушается — окно даёт неверный ответ.
5. **Не убран элемент из структуры при сжатии.** Сдвинули `left`, но забыли `set.delete` / уменьшить счётчик — окно «помнит» то, чего в нём уже нет.
6. **Не обработан случай, когда окно не помещается** (`arr.length < k`).

## Чеклист

- «Непрерывный подотрезок» + «максимальный/минимальный» → окно
- Размер отрезка задан → окно фиксированной длины, вход/выход одной строкой
- Размер не задан, есть условие валидности → окно переменной длины с `while`-сжатием
- Нужен максимум/минимум внутри окна → монотонный дек
- Есть отрицательные числа и речь про сумму → не окно, а [префиксные суммы](../prefiksnye-summy/)

## Задачи для тренировки

1. **Средние значения всех окон длины k** — разминочная.
2. **Самая длинная подстрока не более чем с k различными символами.**
3. **Максимальное число последовательных единиц, если можно заменить k нулей.**
4. **Минимальное окно-подстрока**, содержащее все символы другой строки — трудная, но очень частая на собеседованиях.
5. **Подмассив с произведением меньше k** (все элементы положительные).
