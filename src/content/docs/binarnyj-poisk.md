Алгоритм с идеальным соотношением «простая идея — много ошибок в реализации». Написать бинарный поиск без багов с первого раза — отдельный навык, который тренируют специально.

← [К оглавлению](../)

## Идея

**Бинарный поиск (двоичный поиск, binary search)** — поиск в **отсортированной** последовательности делением пополам.

Смотрим на средний элемент. Если он равен искомому — нашли. Если меньше — искомое может быть только справа, левую половину отбрасываем целиком. Если больше — отбрасываем правую.

Каждый шаг уменьшает область поиска вдвое. Из n элементов до одного — log₂(n) шагов. Для миллиона элементов это 20 шагов вместо миллиона.

**Предусловие:** данные должны быть отсортированы (или обладать свойством монотонности — об этом в разделе про поиск по ответу). Без этого алгоритм неприменим.

## Шаблон, который стоит выучить наизусть

```js
/**
 * Классический бинарный поиск: индекс target или -1.
 * @param {number[]} nums — массив, отсортированный по возрастанию
 * @param {number} target — искомое значение
 * @returns {number} индекс найденного элемента, или -1
 */
function binarySearch(nums, target) {
  let left = 0;
  let right = nums.length - 1;   // ОБА конца включены в область поиска

  // <=, а не <: при left === right остался один непроверенный элемент,
  // и его тоже нужно рассмотреть
  while (left <= right) {
    // Середина. Формула с вычитанием защищает от переполнения
    // при очень больших индексах — в JS это скорее хорошая привычка,
    // в других языках — необходимость
    const mid = left + Math.floor((right - left) / 2);

    if (nums[mid] === target) {
      return mid;
    } else if (nums[mid] < target) {
      left = mid + 1;    // mid уже проверен и не подходит — исключаем его
    } else {
      right = mid - 1;   // то же самое с другой стороны
    }
  }

  return -1;   // область поиска пуста, элемента нет
}
```

### Разбор каждой строки

- **`right = nums.length - 1`** — последний **индекс**, а не длина. Это соответствует выбору «оба конца включены» (полуинтервал `[left, right]`).
- **`while (left <= right)`** — пока область непуста. С `left < right` последний элемент остался бы непроверенным.
- **`left + Math.floor((right - left) / 2)`** — середина. Можно писать `Math.floor((left + right) / 2)` — в JS это тоже работает, но привычка к безопасной форме пригодится.
- **`Math.floor`** — округление вниз. Без него `mid` был бы дробным и `nums[mid]` дал бы `undefined`.
- **`mid + 1` и `mid - 1`** — сдвиг на единицу обязателен. `left = mid` при `left === right` даст бесконечный цикл.

:::caution
Три инварианта, которые должны согласовываться между собой. Если поменять один — нужно поменять и остальные:

1. Начальные границы: `right = n - 1` или `right = n`
2. Условие цикла: `left <= right` или `left < right`
3. Обновление: `right = mid - 1` или `right = mid`

Комбинация «`right = n - 1` + `left <= right` + `mid ± 1`» — самосогласованная. Не смешивайте её с другими.

:::
## Почему это O(log n)

На каждом шаге область сокращается вдвое: n → n/2 → n/4 → ... → 1. Число шагов — это количество делений на 2, то есть log₂(n).

Память **O(1)** для итеративной версии. Рекурсивная версия — O(log n) на стек вызовов, поэтому итеративная предпочтительнее.

## Поиск границ: самый полезный вариант

На практике чаще нужен не «найти элемент», а «найти **первый** элемент, удовлетворяющий условию». Это называют **lower bound** и **upper bound**.

**lower bound** — индекс первого элемента `>= target`.
**upper bound** — индекс первого элемента `> target`.

Из них выводится всё остальное: наличие элемента, количество вхождений, позиция для вставки.

```js
/**
 * Индекс первого элемента >= target.
 * Если все элементы меньше target — вернёт nums.length.
 * @param {number[]} nums — отсортированный массив
 * @param {number} target
 * @returns {number}
 */
function lowerBound(nums, target) {
  let left = 0;
  let right = nums.length;   // ВНИМАНИЕ: length, а не length - 1.
                             // right — позиция «за концом», она допустима как ответ

  // Строгое <: когда left === right, ответ найден
  while (left < right) {
    const mid = left + Math.floor((right - left) / 2);

    if (nums[mid] < target) {
      left = mid + 1;   // mid точно не подходит (он меньше target)
    } else {
      right = mid;      // mid МОЖЕТ быть ответом — не исключаем его!
    }
  }

  return left;   // left === right — это и есть граница
}

/**
 * Индекс первого элемента > target.
 */
function upperBound(nums, target) {
  let left = 0;
  let right = nums.length;

  while (left < right) {
    const mid = left + Math.floor((right - left) / 2);
    // Отличие от lowerBound ровно в одном знаке: <= вместо <
    if (nums[mid] <= target) {
      left = mid + 1;
    } else {
      right = mid;
    }
  }

  return left;
}
```

### Что из них можно получить

```js
// Есть ли элемент в массиве
function contains(nums, target) {
  const i = lowerBound(nums, target);
  return i < nums.length && nums[i] === target;
  // Проверка i < nums.length обязательна: lowerBound может вернуть length
}

// Сколько раз встречается элемент
function countOccurrences(nums, target) {
  return upperBound(nums, target) - lowerBound(nums, target);
}

// Куда вставить элемент, сохранив сортировку
function insertPosition(nums, target) {
  return lowerBound(nums, target);
}
```

:::tip
Разница между `lowerBound` и `upperBound` — один символ (`<` против `<=`). Не пытайтесь запомнить обе функции по отдельности: запомните `lowerBound` и правило «для upper — добавить знак равенства».

:::
## Задача 1. Первая и последняя позиция элемента

**Условие.** В отсортированном массиве найти индексы первого и последнего вхождения `target`. Если элемента нет — `[-1, -1]`.

Пример: `[5, 7, 7, 8, 8, 10]`, `target = 8` → `[3, 4]`.

### Решение

```js
/**
 * Первое и последнее вхождение target.
 * @param {number[]} nums — отсортированный массив
 * @param {number} target
 * @returns {number[]} [первый индекс, последний индекс] или [-1, -1]
 */
function searchRange(nums, target) {
  const first = lowerBound(nums, target);

  // Элемента нет, если граница вышла за массив
  // или значение на границе — не target
  if (first === nums.length || nums[first] !== target) {
    return [-1, -1];
  }

  // upperBound — первый элемент СТРОГО больше target,
  // значит последнее вхождение target на позицию левее
  const last = upperBound(nums, target) - 1;

  return [first, last];
}
```

Время **O(log n)** — два бинарных поиска. Память **O(1)**.

Это хороший пример того, как правильно выбранные примитивы делают задачу тривиальной. Писать поиск первого и последнего вхождения «с нуля» намного более чревато ошибками.

## Задача 2. Поиск в повёрнутом отсортированном массиве

**Условие.** Отсортированный массив повернули в неизвестной точке: `[0,1,2,4,5,6,7]` → `[4,5,6,7,0,1,2]`. Найти индекс `target` за O(log n). Дубликатов нет.

### Ход мысли

Массив не отсортирован целиком, но у него есть ключевое свойство: **при делении пополам хотя бы одна из половин обязательно отсортирована**.

Определяем, какая именно: если `nums[left] <= nums[mid]`, отсортирована левая половина, иначе правая. Затем проверяем, попадает ли `target` в диапазон отсортированной половины. Если да — ищем там, если нет — в другой.

### Решение

```js
/**
 * Поиск в повёрнутом отсортированном массиве без дубликатов.
 * @param {number[]} nums
 * @param {number} target
 * @returns {number} индекс или -1
 */
function searchRotated(nums, target) {
  let left = 0;
  let right = nums.length - 1;

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);

    if (nums[mid] === target) return mid;

    // Какая половина отсортирована?
    // <= важно для случая, когда в области поиска два элемента
    if (nums[left] <= nums[mid]) {
      // Левая половина [left..mid] отсортирована.
      // Попадает ли target в её диапазон?
      if (nums[left] <= target && target < nums[mid]) {
        right = mid - 1;   // да — ищем слева
      } else {
        left = mid + 1;    // нет — значит в правой части
      }
    } else {
      // Правая половина [mid..right] отсортирована
      if (nums[mid] < target && target <= nums[right]) {
        left = mid + 1;
      } else {
        right = mid - 1;
      }
    }
  }

  return -1;
}
```

### Разбор

- **`nums[left] <= nums[mid]`** — определение отсортированной половины. Если бы левая половина содержала точку поворота, значение в `mid` было бы меньше значения в `left`.
- **Двойные неравенства** (`nums[left] <= target && target < nums[mid]`) — проверка попадания в диапазон. Границы включительно/исключительно подобраны так, чтобы случай `nums[mid] === target` уже был обработан выше.

Время **O(log n)**, память **O(1)**.

## Бинарный поиск по ответу

Самое мощное применение техники — и самое неочевидное. Здесь **нет отсортированного массива вообще**.

**Идея.** Иногда задача формулируется как «найти минимальное/максимальное значение X, при котором выполняется условие». Если условие **монотонно** — то есть существует граница, слева от которой ответ всегда «нет», а справа всегда «да», — можно бинарным поиском искать саму эту границу.

```
X:        1    2    3    4    5    6    7    8
условие:  нет  нет  нет  ДА   ДА   ДА   ДА   ДА
                          ↑
                    ищем эту границу
```

**Как распознать.** В условии есть слова «минимальный максимум», «максимальный минимум», «наименьшее возможное значение, при котором...», а диапазон возможных ответов известен и велик.

**Шаблон:**

```js
let left = минимально возможный ответ;
let right = максимально возможный ответ;

while (left < right) {
  const mid = left + Math.floor((right - left) / 2);
  if (isFeasible(mid)) {
    right = mid;       // mid подходит — но, может, есть ответ поменьше
  } else {
    left = mid + 1;    // mid не подходит — ответ строго больше
  }
}

return left;   // минимальный подходящий ответ
```

## Задача 3. Коко ест бананы

**Условие.** Есть `piles` кучек бананов и `h` часов. За час обезьяна съедает не больше `k` бананов из одной кучки (если в кучке меньше — доедает её и час всё равно потрачен). Найти минимальную скорость `k`, при которой все бананы будут съедены за `h` часов.

Пример: `piles = [3, 6, 7, 11]`, `h = 8` → `4`.

### Ход мысли

Перебирать все `k` от 1 до максимума — O(max · n), слишком медленно.

Но заметим монотонность: **если скорость `k` достаточна, то и любая большая скорость достаточна**. Значит, есть граница — минимальная достаточная скорость. Её и ищем бинарным поиском.

Диапазон ответа: от `1` (медленнее нельзя) до `max(piles)` (быстрее бессмысленно — за час съедается максимум одна кучка).

Функция проверки: при данной скорости посчитать нужное время и сравнить с `h`.

### Решение

```js
/**
 * Минимальная скорость поедания, чтобы успеть за h часов.
 * @param {number[]} piles — размеры кучек
 * @param {number} h — доступные часы
 * @returns {number} минимальная достаточная скорость
 */
function minEatingSpeed(piles, h) {
  let left = 1;                   // минимально осмысленная скорость
  let right = Math.max(...piles); // быстрее нет смысла

  while (left < right) {
    const mid = left + Math.floor((right - left) / 2);

    if (hoursNeeded(piles, mid) <= h) {
      right = mid;      // успеваем — пробуем скорость поменьше
    } else {
      left = mid + 1;   // не успеваем — нужна скорость побольше
    }
  }

  return left;
}

/**
 * Сколько часов нужно при скорости speed.
 * @param {number[]} piles
 * @param {number} speed
 * @returns {number} количество часов
 */
function hoursNeeded(piles, speed) {
  let hours = 0;
  for (const pile of piles) {
    // Math.ceil — округление ВВЕРХ: остаток кучки тоже съедается
    // за полный час. Кучка 7 при скорости 3 — это 3 часа, не 2.33
    hours += Math.ceil(pile / speed);
  }
  return hours;
}
```

### Разбор функций

- **`Math.max(...piles)`** — спред раскладывает массив в аргументы. Осторожно: на массивах в сотни тысяч элементов возможно переполнение стека аргументов; безопаснее `piles.reduce((a, b) => Math.max(a, b), 0)`. Это стоит проговорить.
- **`Math.ceil(x)`** — округление вверх: `Math.ceil(2.1)` → `3`. Ключевой момент задачи: неполный час всё равно считается целым.
- **`hoursNeeded`** — вынесенная функция проверки. Выносить её отдельно — хорошая практика: она делает структуру решения видимой и упрощает объяснение.

### Сложность

Время **O(n · log(max(piles)))** — бинарный поиск по диапазону скоростей, внутри каждого шага проход по кучкам. Память **O(1)**.

## Задача 4. Квадратный корень целого числа

**Условие.** Вернуть целую часть квадратного корня из `x`, не используя `Math.sqrt`.

### Решение

```js
/**
 * Целая часть квадратного корня.
 * @param {number} x — неотрицательное целое
 * @returns {number}
 */
function mySqrt(x) {
  if (x < 2) return x;   // краевые случаи: 0 и 1

  let left = 1;
  let right = Math.floor(x / 2);   // для x >= 4 корень не больше x/2
  let answer = 1;

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);
    const square = mid * mid;

    if (square === x) {
      return mid;
    } else if (square < x) {
      answer = mid;      // подходит как кандидат — запоминаем
      left = mid + 1;    // пробуем найти больше
    } else {
      right = mid - 1;
    }
  }

  return answer;   // последний кандидат, чей квадрат не превысил x
}
```

### Разбор

- **`answer`** — отдельная переменная для «лучшего найденного» кандидата. Приём, который выручает, когда точное совпадение может не существовать.
- **`Math.floor(x / 2)`** как верхняя граница — простая и корректная оценка для `x >= 4`.

Время **O(log x)**, память **O(1)**.

## Типичные ошибки

1. **Бесконечный цикл.** Если `left = mid` (без `+1`) при `left === right`, границы перестают меняться. Признак: код «зависает». Всегда проверяйте, что область поиска гарантированно сокращается.
2. **Рассогласование инвариантов.** `right = nums.length` вместе с `while (left <= right)` даст обращение к `nums[nums.length]` → `undefined`. Выберите одну из двух самосогласованных схем и придерживайтесь её.
3. **Забыт `Math.floor`.** `mid` станет дробным, `nums[mid]` вернёт `undefined`, сравнения начнут молча давать `false`.
4. **Не проверена граница результата.** `lowerBound` может вернуть `nums.length` — обращение по этому индексу даст `undefined`.
5. **Применение к неотсортированным данным.** Алгоритм отработает и вернёт неверный ответ — без единой ошибки в консоли.
6. **Немонотонное условие** в поиске по ответу. Если «да» и «нет» чередуются, бинарный поиск неприменим.

## Как отлаживать бинарный поиск на собеседовании

Возьмите массив из **двух** элементов и прогоните код руками. Большинство ошибок на единицу проявляются именно на двух элементах: `left = 0`, `right = 1`, `mid = 0` — и видно, сдвигаются ли границы.

Затем проверьте: пустой массив, один элемент, элемент меньше всех, элемент больше всех.

## Чеклист

- Массив отсортирован, нужен конкретный элемент → классический шаблон
- Нужна граница (первый ≥, первый >) → `lowerBound` / `upperBound`
- «Минимальное значение, при котором выполняется условие» → бинарный поиск по ответу
- Диапазон ответов известен и огромен, а проверка одного варианта дешёвая → почти наверняка поиск по ответу
- Перед применением: убедитесь в монотонности

## Задачи для тренировки

1. **Позиция вставки** — куда вставить элемент в отсортированный массив.
2. **Найти минимум в повёрнутом массиве.**
3. **Найти пик** — элемент, больший обоих соседей, за O(log n).
4. **Разделить массив на k частей** так, чтобы максимальная сумма части была минимальной (поиск по ответу).
5. **Медиана двух отсортированных массивов** — трудная, но показательная.
