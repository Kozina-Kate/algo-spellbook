Ошибка — не признак неспособности программировать, а информация о месте, где ожидание разошлось с реальностью. Отладка — последовательное сужение этого расхождения.

:::note[Перед началом]
**Урок 8 из 9 · 20–25 минут**

**Нужно знать:** функции, условия и массивы. **После урока:** сможете различить типы ошибок, найти первый неверный шаг и проверить функцию несколькими примерами.
:::

## Три вида проблем

### Синтаксическая ошибка

JavaScript не может разобрать запись.

```js
console.log("hello"; // SyntaxError: пропущена закрывающая скобка
```

Сначала смотрите на указанную строку и строку перед ней: причина иногда находится чуть выше.

### Ошибка во время выполнения

Запись понятна, но выполнить действие невозможно.

```js
console.log(total); // ReferenceError: total is not defined
```

`ReferenceError` часто означает опечатку в имени или обращение к переменной вне её области видимости.

```js
const value = null;
console.log(value.length); // TypeError
```

`TypeError` означает, что операция не подходит полученному значению.

### Логическая ошибка

Код запускается, но возвращает неверный ответ.

```js
function isEven(number) {
  return number % 2 === 1; // на самом деле проверяет положительные нечётные
}
```

Сообщения об ошибке нет, поэтому нужны примеры и трассировка.

## Алгоритм отладки

1. Зафиксируйте конкретный вход и ожидаемый ответ.
2. Запустите код и запишите фактический ответ.
3. Найдите первое место, где состояние стало неожиданным.
4. Исправьте одну причину.
5. Повторите все проверки, а не только упавшую.

Не меняйте пять строк одновременно: тогда неизвестно, какое изменение помогло и не сломало ли оно другой случай.

## Наблюдение через console.log

```js
function positiveSum(numbers) {
  let sum = 0;

  for (const number of numbers) {
    console.log("до", { number, sum });

    if (number > 0) {
      sum += number;
    }

    console.log("после", { number, sum });
  }

  return sum;
}
```

Временные выводы показывают не только значение, но и момент: до или после изменения. Объект `{ number, sum }` выводит оба значения с именами.

После исправления лишние отладочные выводы удаляют.

## Простая проверка функции

```js
function multiply(a, b) {
  return a * b;
}

console.log(multiply(2, 3) === 6);   // true
console.log(multiply(-2, 4) === -8); // true
console.log(multiply(0, 10) === 0);  // true
```

Каждая строка сравнивает фактический результат с ожидаемым. `true` означает, что проверка прошла.

Для более читаемого сообщения создадим вспомогательную функцию:

```js
function check(actual, expected, testName) {
  if (actual === expected) {
    console.log("✓", testName);
  } else {
    console.log("✗", testName, { actual, expected });
  }
}

check(multiply(2, 3), 6, "положительные числа");
check(multiply(-2, 4), -8, "разные знаки");
```

### Разбор check

- `actual` — фактически полученное значение;
- `expected` — ожидаемое значение;
- `testName` — подпись проверки;
- `actual === expected` сравнивает результаты;
- первая ветка сообщает об успехе;
- вторая показывает оба различающихся значения;
- функция ничего не возвращает, потому что её задача — вывести диагностическое сообщение.

:::caution
Строгое сравнение подходит для чисел, строк и boolean, но два отдельных массива с одинаковыми элементами не считаются равными: `[1, 2] === [1, 2]` возвращает `false`. Сравнение массивов подробно добавим вместе с интерактивными тестами.
:::

## Какие примеры проверять

Минимальный набор:

- обычный случай;
- самый маленький допустимый вход;
- пустой вход, если он разрешён;
- ноль и отрицательные числа;
- повторяющиеся значения;
- случай, в котором ответ находится в начале или конце.

Такие входы называют **краевыми случаями**: именно там чаще всего скрываются ошибки в границах и начальных значениях.

## Предскажите результат

```js
function firstElement(numbers) {
  return numbers[1];
}

console.log(firstElement([8, 9, 10]));
```

<details>
<summary>Ответ</summary>

Код выполнится без сообщения об ошибке, но вернёт `9`, а не первый элемент `8`. Это логическая ошибка: первый индекс массива равен `0`.

## Измените код

Добавьте в `check` четвёртый параметр `details`. При неуспешной проверке выводите его вместе с фактическим и ожидаемым значениями. Убедитесь, что успешная проверка остаётся короткой.

## Самостоятельная практика: отладка Multiply

Задача [Multiply на Codewars](https://www.codewars.com/kata/50654ddff44f800200000004/javascript) специально относится к категории Debugging. Проверьте эту неверную реализацию:

```js
function multiply(a, b) {
  a * b;
}
```

1. Запишите ожидаемый результат `multiply(2, 3)`.
2. Посмотрите фактическое значение.
3. Найдите отсутствующую конструкцию.

<details>
<summary>Разбор</summary>

Выражение `a * b` вычисляется, но результат не возвращается. Функция без `return` отдаёт `undefined`.

```js
function multiply(a, b) {
  return a * b;
}
```

</details>

## Типичные ошибки при отладке

- читать только слово `Error` и игнорировать тип, строку и сообщение;
- проверять функцию на одном удобном примере;
- исправлять симптом вместо первого неверного шага;
- оставлять отладочный вывод внутри окончательного решения;
- менять код до того, как сформулирован ожидаемый результат.
