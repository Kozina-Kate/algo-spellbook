Что реально происходит внутри массива, объекта, `Map` и `Set`, и сколько стоит каждая операция. Эта страница — фундамент: почти каждое ускорение решения сводится к замене одной структуры на другую.

## Сводная таблица стоимости операций

Держите её в голове — на собеседовании она нужна постоянно.

| **Операция** | **Array** | **Object** | **Map** | **Set** |
| --- | --- | --- | --- | --- |
| Доступ по индексу/ключу | O(1) | O(1) | O(1) | — |
| Поиск значения | O(n) | O(n) | O(n) | O(1) |
| Проверка наличия ключа | — | O(1) | O(1) | O(1) |
| Вставка в конец | O(1)* | O(1) | O(1) | O(1) |
| Вставка в начало | O(n) | — | — | — |
| Удаление с конца | O(1) | — | — | — |
| Удаление из начала/середины | O(n) | O(1) по ключу | O(1) | O(1) |
| Перебор всех элементов | O(n) | O(n) | O(n) | O(n) |
\* амортизированное — см. [Сложность алгоритмов](../slozhnost-algoritmov/)

Главный вывод: **O(1) для `Map` и `Set` — это и есть ваш основной инструмент ускорения**. Если в наивном решении внутри цикла происходит поиск по массиву — заменяйте на `Map`/`Set` и получайте O(n) вместо O(n²).

## Массив (Array)

**Массив** — упорядоченная последовательность элементов, доступных по целочисленному индексу от 0.

В классическом понимании (C, Java) массив — непрерывный блок памяти, поэтому адрес элемента считается арифметикой: начало + индекс × размер. Отсюда O(1) на доступ по индексу.

В JS всё сложнее: массив — это объект, и формально ключи в нём строковые. Но движки (V8) оптимизируют: если массив «плотный» (нет дыр) и элементы одного типа, он хранится как настоящий непрерывный массив. Для задач на собеседовании считайте, что доступ по индексу — O(1).

:::caution
Не создавайте «дырявые» массивы: `const a = []; a[1000] = 5;`. Движок переключит массив в режим словаря, и производительность просядет. Для заполнения используйте `new Array(n).fill(0)`.

:::
### Методы массива, которые нужны в задачах

```js
const arr = [3, 1, 4, 1, 5];

arr.length;              // 5 — свойство (без скобок), количество элементов
arr.push(9);             // добавить в конец, вернёт новую длину. O(1) аморт.
arr.pop();               // удалить последний и вернуть его. O(1)
arr.unshift(0);          // добавить в начало. O(n) — все сдвигаются!
arr.shift();             // удалить первый и вернуть его. O(n) — все сдвигаются!
```

`push`/`pop` работают с концом массива — дёшево. `shift`/`unshift` работают с началом — каждый элемент нужно сдвинуть, поэтому O(n).

```js
arr.slice(1, 3);         // НОВЫЙ массив из элементов с индексами 1 и 2. O(k)
arr.splice(1, 2);        // УДАЛИТЬ 2 элемента с индекса 1, изменив исходный. O(n)
arr.concat([7, 8]);      // новый массив = arr + [7,8]. O(n+m)
```

`slice(start, end)` — копия участка, `end` не включается. Не меняет исходный массив.
`splice(start, deleteCount, ...items)` — **меняет** исходный массив: удаляет и/или вставляет. Легко перепутать со `slice` — на собеседовании проговаривайте, какой из них используете.

```js
arr.indexOf(4);          // индекс первого вхождения, или -1. O(n)
arr.includes(4);         // true/false. O(n)
arr.find(x => x > 3);    // первый подходящий ЭЛЕМЕНТ, или undefined. O(n)
arr.findIndex(x => x>3); // ИНДЕКС первого подходящего, или -1. O(n)
```

Все четыре — линейный поиск. Внутри цикла превращают решение в O(n²). Это ошибка номер один.

```js
arr.map(x => x * 2);           // новый массив той же длины
arr.filter(x => x > 2);        // новый массив из подошедших элементов
arr.reduce((acc, x) => acc + x, 0); // свернуть массив в одно значение
arr.forEach(x => console.log(x));   // просто обойти, ничего не возвращает
```

`reduce(fn, initial)` — самый неочевидный. `fn` получает аккумулятор (накопленное значение) и текущий элемент, возвращает новый аккумулятор. `initial` — стартовое значение аккумулятора. Сумма массива: `arr.reduce((acc, x) => acc + x, 0)`.

:::tip
На собеседовании обычный `for` часто лучше, чем цепочка `map().filter()`. Причины: из `for` можно выйти досрочно через `break`, он не создаёт промежуточных массивов, и его проще отлаживать вслух. Цепочка из трёх методов — это три прохода по массиву.

:::
```js
arr.sort((a, b) => a - b);     // сортировка НА МЕСТЕ, O(n log n)
arr.reverse();                 // разворот НА МЕСТЕ, O(n)
arr.join('-');                 // склеить в строку через разделитель. O(n)
```

### Создание массивов

```js
new Array(5).fill(0);              // [0, 0, 0, 0, 0]
Array.from({ length: 5 }, (_, i) => i);  // [0, 1, 2, 3, 4]
```

`Array.from(source, mapFn)` — создаёт массив из итерируемого объекта или объекта с `length`. Второй аргумент — функция, получающая элемент и индекс. `_` — общепринятое имя для неиспользуемого параметра.

**Двумерный массив — с осторожностью:**

```js
// НЕПРАВИЛЬНО: все строки — ОДИН И ТОТ ЖЕ массив
const bad = new Array(3).fill(new Array(3).fill(0));
bad[0][0] = 1;   // изменит все три строки!

// ПРАВИЛЬНО: каждая строка создаётся отдельно
const grid = Array.from({ length: 3 }, () => new Array(3).fill(0));
```

Причина: `fill` кладёт **одну и ту же ссылку** во все ячейки. `Array.from` с функцией вызывает её для каждой строки заново, создавая разные массивы. Это классическая ловушка на собеседовании по матрицам.

## Строка (String)

**Строка неизменяема (immutable).** Любая «модификация» создаёт новую строку.

```js
const s = 'hello';
s[0];                  // 'h' — доступ по индексу, O(1)
s.length;              // 5
s[0] = 'H';            // молча ничего не сделает — строки неизменяемы
```

```js
s.charAt(0);           // 'h'
s.charCodeAt(0);       // 104 — числовой код символа (для латиницы = ASCII)
String.fromCharCode(104); // 'h' — обратная операция
```

`charCodeAt(i)` часто используется, чтобы превратить букву в индекс массива: `'c'.charCodeAt(0) - 'a'.charCodeAt(0)` даёт 2. Так делают частотный массив из 26 ячеек вместо `Map`.

```js
s.slice(1, 3);         // 'el' — подстрока, O(k)
s.substring(1, 3);     // 'el' — почти то же, но не понимает отрицательные индексы
s.indexOf('ll');       // 2 — позиция подстроки или -1
s.includes('ell');     // true
s.split('');           // ['h','e','l','l','o'] — строка в массив символов
s.toLowerCase();       // 'hello' — новая строка
s.trim();              // убрать пробелы по краям
s.repeat(2);           // 'hellohello'
```

`split(sep)` — разбить строку по разделителю в массив. `split('')` разбивает посимвольно, `split(' ')` — по словам.

**Разворот строки** — идиома, которую спрашивают часто:

```js
const reversed = s.split('').reverse().join('');
// split('') → массив символов, reverse() → развернуть на месте, join('') → склеить
// O(n) по времени, O(n) по памяти
```

:::caution
`s += x` в цикле — O(n²), потому что каждая конкатенация создаёт новую строку и копирует всё содержимое. Собирайте в массив и делайте `join` в конце.

:::
## Объект (Object)

**Объект** — набор пар «ключ → значение». Ключи только строки и символы; числовой ключ молча превращается в строку.

```js
const obj = { a: 1, b: 2 };

obj.a;           // 1 — доступ O(1)
obj['a'];        // то же самое
obj.c = 3;       // добавление O(1)
delete obj.b;    // удаление O(1)
'a' in obj;      // true — проверка наличия ключа
obj.hasOwnProperty('a');  // true, не смотрит в прототип
```

```js
Object.keys(obj);     // ['a', 'c'] — массив ключей, O(n)
Object.values(obj);   // [1, 3] — массив значений, O(n)
Object.entries(obj);  // [['a',1], ['c',3]] — массив пар, O(n)
```

:::caution
Проверять наличие через `if (obj[key])` опасно: значение `0`, `''` или `false` — ложные, и проверка провалится, хотя ключ есть. Используйте `if (key in obj)` или `if (obj[key] !== undefined)`.

:::
## Map — то, что стоит использовать вместо объекта

**`Map`** — хеш-таблица: пары «ключ → значение», где ключом может быть **что угодно**, включая числа, объекты, `NaN`.

```js
const m = new Map();

m.set('a', 1);      // добавить или перезаписать. O(1)
m.get('a');         // 1, или undefined если нет. O(1)
m.has('a');         // true/false. O(1)
m.delete('a');      // удалить, вернёт true если было. O(1)
m.size;             // количество пар — свойство, не метод
m.clear();          // очистить всё
```

Перебор:

```js
for (const [key, value] of m) { /* ... */ }   // пары, в порядке вставки
for (const key of m.keys()) { /* ... */ }
for (const value of m.values()) { /* ... */ }
```

`[key, value]` — деструктуризация массива: `Map` при переборе отдаёт двухэлементные массивы, а запись сразу раскладывает их в две переменные.

**Почему `Map` лучше объекта в алгоритмических задачах:**

1. Ключи любого типа — числа остаются числами, не превращаются в строки.
2. Есть `.size` — у объекта пришлось бы делать `Object.keys(obj).length`, а это O(n).
3. Гарантирован порядок вставки при переборе.
4. Нет наследуемых ключей из прототипа — не бывает сюрпризов вроде ключа `'constructor'`.

### Идиома: частотный словарь

Самая часто встречающаяся конструкция во всём пособии — посчитать, сколько раз встречается каждый элемент.

```js
function countFrequency(items) {
  const freq = new Map();
  for (const item of items) {
    // (freq.get(item) || 0) — если ключа ещё нет, get вернёт undefined,
    // а `|| 0` подставит ноль. Затем прибавляем единицу.
    freq.set(item, (freq.get(item) || 0) + 1);
  }
  return freq;
}

countFrequency(['a', 'b', 'a']);  // Map { 'a' => 2, 'b' => 1 }
// Время O(n), память O(k), где k — число различных элементов
```

Запомните строку `freq.set(x, (freq.get(x) || 0) + 1)` наизусть — она понадобится в десятке задач.

## Set — множество уникальных значений

**`Set`** — коллекция уникальных значений без ключей. Под капотом та же хеш-таблица.

```js
const s = new Set();

s.add(1);        // добавить, дубликат игнорируется. O(1)
s.has(1);        // true/false. O(1)
s.delete(1);     // удалить. O(1)
s.size;          // количество

new Set([1, 2, 2, 3]);          // Set {1, 2, 3} — дубликаты схлопнулись
[...new Set([1, 2, 2, 3])];     // [1, 2, 3] — обратно в массив
```

`[...someSet]` — спред превращает любую итерируемую коллекцию в массив.

**Типовые применения:**

```js
// Есть ли дубликаты? O(n) вместо O(n²)
function hasDuplicates(arr) {
  return new Set(arr).size !== arr.length;
}

// Пересечение двух массивов
function intersection(a, b) {
  const setB = new Set(b);             // O(m) — теперь проверка в b стоит O(1)
  return [...new Set(a)].filter(x => setB.has(x));
}
// Время O(n + m). Без Set было бы O(n · m)
```

## Как выбрать структуру: решающее дерево

- Нужен **порядок и доступ по индексу** → массив
- Нужно **быстро проверять наличие** → `Set`
- Нужно **сопоставить ключу значение** (счётчик, индекс, группа) → `Map`
- Нужен **последний добавленный** элемент → массив как стек (`push`/`pop`)
- Нужен **первый добавленный** → очередь через указатель, не `shift`
- Нужен **минимальный/максимальный** на каждом шаге → куча

## Копирование: мелкое и глубокое

**Мелкая копия (shallow)** копирует только верхний уровень; вложенные объекты остаются общими.

```js
const orig = [[1, 2], [3, 4]];
const shallow = [...orig];
shallow[0][0] = 99;     // orig тоже изменился — вложенные массивы общие!
```

**Глубокая копия (deep)** копирует всю структуру:

```js
const deep = structuredClone(orig);   // современный способ
const deep2 = JSON.parse(JSON.stringify(orig));  // старый, теряет undefined, Date, функции
```

Зачем это в алгоритмах: в переборе с возвратом ([backtracking](../rekursija-i-backtracking/)) результат нужно сохранять **копией** — иначе все сохранённые варианты окажутся одним и тем же изменяющимся массивом.

## Числа: о чём стоит помнить

```js
Number.MAX_SAFE_INTEGER;    // 9007199254740991 = 2^53 - 1
```

Все числа в JS — 64-битные с плавающей точкой. Целые числа точны только до 2⁵³. Если в задаче фигурируют большие произведения — скажите вслух: «здесь возможна потеря точности, в проде взяла бы BigInt».

```js
Math.floor(2.7);   // 2   — вниз
Math.ceil(2.1);    // 3   — вверх
Math.round(2.5);   // 3   — к ближайшему
Math.trunc(-2.7);  // -2  — отбросить дробную часть (для отрицательных ≠ floor!)
Math.abs(-5);      // 5
Math.min(1, 2, 3); // 1
Math.max(...arr);  // максимум массива через спред. Осторожно: падает на очень больших массивах
```

Целочисленное деление: `Math.floor(a / b)`. Остаток: `a % b`. Для отрицательных `%` в JS возвращает отрицательный результат: `-7 % 3` → `-1`, а не `2`.

## Чеклист по структурам

1. В цикле есть `includes` / `indexOf` / `find` по массиву → замените на `Set`/`Map`
2. Используете `shift()` в цикле → замените на указатель `head`
3. Собираете строку через `+=` в цикле → собирайте в массив и `join`
4. Создаёте матрицу через `fill(new Array(...))` → используйте `Array.from`
5. Сортируете числа → не забудьте компаратор `(a, b) => a - b`
6. Проверяете наличие ключа через `if (obj[key])` → используйте `in` или `!== undefined`
