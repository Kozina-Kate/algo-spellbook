Предподсчёт, который позволяет отвечать на вопрос «какова сумма отрезка?» за O(1) вместо O(n). Работает там, где скользящее окно ломается — при отрицательных числах.

← [К оглавлению](../)

## Идея

**Префиксная сумма** `P[i]` — сумма первых `i` элементов массива. По определению `P[0] = 0` (сумма пустого префикса).

Для массива `[3, 1, 4, 1, 5]`:

```
индекс:   0   1   2   3   4   5
P:        0   3   4   8   9   14
          ↑   ↑   ↑
       пусто  3  3+1
```

Главная формула:

```
сумма элементов с индекса l по r включительно = P[r + 1] - P[l]
```

Проверим на примере: сумма с 1 по 3 — это `1 + 4 + 1 = 6`. По формуле: `P[4] - P[1] = 9 - 3 = 6`. Сходится.

**Почему работает.** `P[r+1]` — сумма всего от начала до `r`. `P[l]` — сумма всего от начала до `l-1`. Вычитая, мы убираем «лишнее начало» и оставляем ровно нужный кусок.

:::tip
Массив `P` делают длиной `n + 1` с нулём в начале именно для того, чтобы формула работала без исключений для `l = 0`. Если делать `P` длины `n`, придётся каждый раз писать `l === 0 ? P[r] : P[r] - P[l-1]` — лишний источник ошибок.

:::
## Построение

```js
/**
 * Строит массив префиксных сумм.
 * @param {number[]} nums
 * @returns {number[]} массив длины nums.length + 1, где P[i] — сумма первых i элементов
 */
function buildPrefix(nums) {
  // Длина n+1, первый элемент — 0 (сумма пустого префикса)
  const prefix = new Array(nums.length + 1).fill(0);

  for (let i = 0; i < nums.length; i++) {
    // Каждая следующая сумма = предыдущая + текущий элемент
    prefix[i + 1] = prefix[i] + nums[i];
  }

  return prefix;
}
```

**Разбор.** `new Array(n + 1).fill(0)` создаёт массив нужной длины, заполненный нулями — без `fill` массив был бы «дырявым», что плохо для производительности (см. [Структуры данных](../struktury-dannyh-v-js/)). Смещение на единицу (`prefix[i + 1]`) — то самое, что делает формулу универсальной.

Построение — **O(n)** времени и **O(n)** памяти. Каждый последующий запрос суммы — **O(1)**.

## Когда применять

- Много запросов «сумма отрезка» к неизменяемому массиву
- «Сколько подмассивов с суммой k» — в паре с хеш-таблицей
- В массиве есть **отрицательные** числа, и скользящее окно неприменимо
- Двумерная версия: сумма прямоугольника в матрице
- Разностный массив: много операций «прибавить значение на отрезке»

## Задача 1. Сумма диапазона, много запросов

**Условие.** Дан неизменяемый массив. Нужно отвечать на множество запросов `sumRange(left, right)` — сумма элементов с `left` по `right` включительно.

### Ход мысли

Если запрос один — проще посчитать циклом за O(n). Но запросов много (скажем, q штук), и наивно выйдет O(q · n). Предподсчёт за O(n) делает каждый запрос O(1), итого O(n + q).

Это общий приём: **заплатить один раз за подготовку, чтобы потом отвечать мгновенно**.

### Решение

```js
/**
 * Структура для быстрых запросов суммы на отрезке.
 */
class NumArray {
  /**
   * @param {number[]} nums — исходный массив (не изменяется)
   */
  constructor(nums) {
    // Предподсчёт выполняется один раз при создании объекта
    this.prefix = new Array(nums.length + 1).fill(0);
    for (let i = 0; i < nums.length; i++) {
      this.prefix[i + 1] = this.prefix[i] + nums[i];
    }
  }

  /**
   * Сумма элементов с left по right включительно.
   * @param {number} left
   * @param {number} right
   * @returns {number}
   */
  sumRange(left, right) {
    // right + 1, потому что правая граница включительная
    return this.prefix[right + 1] - this.prefix[left];
  }
}

const na = new NumArray([-2, 0, 3, -5, 2, -1]);
na.sumRange(0, 2);   // 1
na.sumRange(2, 5);   // -1
```

### Разбор конструкций

- **`class` / `constructor`** — конструктор вызывается при `new NumArray(...)` и выполняет предподсчёт один раз.
- **`this.prefix`** — поле объекта; сохраняется между вызовами `sumRange`, в этом весь смысл.
- **`right + 1`** — не забывайте: в `prefix` индексы сдвинуты на единицу относительно исходного массива.

### Сложность

Конструктор **O(n)**, каждый `sumRange` **O(1)**, память **O(n)**.

## Задача 2. Сколько подмассивов имеют сумму k

**Условие.** Дан массив целых чисел (могут быть отрицательные) и число `k`. Посчитать количество непрерывных подмассивов с суммой ровно `k`.

Пример: `[1, 1, 1]`, `k = 2` → `2` (два подмассива `[1,1]`).

:::caution
Скользящее окно здесь **не работает**: при отрицательных элементах сумма не растёт монотонно при расширении окна, и сжатие слева не гарантирует правильности.

:::
### Ход мысли

Подмассив `[l..r]` имеет сумму `k`, если `P[r+1] - P[l] = k`, то есть `P[l] = P[r+1] - k`.

Значит, идя по массиву и держа текущую префиксную сумму `P[r+1]`, нужно спросить: **сколько раз ранее встречалась префиксная сумма, равная `текущая - k`?** Каждое такое вхождение даёт один подходящий подмассив.

Хранить «сколько раз встречалась каждая префиксная сумма» умеет `Map`. Получается связка «префиксные суммы + хеш-таблица» — одна из самых частых на собеседованиях.

### Решение

```js
/**
 * Количество непрерывных подмассивов с суммой k.
 * @param {number[]} nums — массив целых чисел (возможны отрицательные)
 * @param {number} k
 * @returns {number}
 */
function subarraySum(nums, k) {
  // счётчик: префиксная сумма → сколько раз она встречалась
  // Ключ 0 со значением 1 — это «пустой префикс».
  // Без него потерялись бы подмассивы, начинающиеся с индекса 0
  const counts = new Map([[0, 1]]);

  let running = 0;   // текущая префиксная сумма
  let total = 0;     // ответ

  for (const x of nums) {
    running += x;

    // Сколько раз встречалась сумма (running - k).
    // Столько подмассивов, заканчивающихся здесь, дают сумму k
    const needed = running - k;
    if (counts.has(needed)) {
      total += counts.get(needed);
    }

    // Регистрируем текущую префиксную сумму для будущих шагов.
    // ВАЖНО: после подсчёта, иначе при k = 0 элемент учтёт сам себя
    counts.set(running, (counts.get(running) || 0) + 1);
  }

  return total;
}
```

### Разбор

- **`new Map([[0, 1]])`** — конструктор `Map` принимает массив пар `[ключ, значение]`. Здесь сразу кладём «сумма 0 встречалась один раз».
- **`counts.get(needed)`** — количество, а не булев флаг: одна и та же префиксная сумма может встречаться много раз, и каждое вхождение даёт свой подмассив.
- **Порядок «сначала посчитать, потом записать»** — тот же принцип, что в Two Sum. При `k = 0` обратный порядок дал бы лишние совпадения.

### Сложность

Время **O(n)**, память **O(n)**.

:::note
Почему начальная пара `[0, 1]` так важна. Возьмём `nums = [3]`, `k = 3`. После первой итерации `running = 3`, `needed = 0`. Если в `Map` нет ключа 0, ответ будет 0 — а правильный ответ 1. Пустой префикс — полноценный участник, его нужно зарегистрировать заранее.

:::
## Задача 3. Индекс равновесия (pivot index)

**Условие.** Найти индекс, для которого сумма элементов слева равна сумме элементов справа. Сам элемент не учитывается ни в одной сумме. Вернуть самый левый подходящий индекс или −1.

Пример: `[1, 7, 3, 6, 5, 6]` → `3`, потому что `1+7+3 = 11` и `5+6 = 11`.

### Ход мысли

Явный массив префиксов строить не обязательно. Достаточно знать общую сумму и накапливать левую: правая сумма получается вычитанием.

### Решение

```js
/**
 * Индекс, где сумма слева равна сумме справа.
 * @param {number[]} nums
 * @returns {number} индекс или -1
 */
function pivotIndex(nums) {
  // reduce сворачивает массив в одно значение:
  // acc — накопленное, x — текущий элемент, 0 — стартовое значение
  const total = nums.reduce((acc, x) => acc + x, 0);

  let leftSum = 0;

  for (let i = 0; i < nums.length; i++) {
    // Сумма справа = всё минус левая часть минус текущий элемент
    const rightSum = total - leftSum - nums[i];

    if (leftSum === rightSum) return i;

    // Готовим leftSum для СЛЕДУЮЩЕЙ итерации — после сравнения
    leftSum += nums[i];
  }

  return -1;
}
```

### Разбор функций

- **`Array.prototype.reduce(fn, initial)`** — сворачивает массив в одно значение. `fn(acc, x)` возвращает новый аккумулятор. Стартовое значение `0` указывать обязательно: без него `reduce` на пустом массиве бросит исключение.
- **`total - leftSum - nums[i]`** — вычисление правой суммы без второго прохода.
- **Порядок обновления `leftSum`** — строго после сравнения: на индексе `i` элемент `nums[i]` не входит в левую сумму.

### Сложность

Время **O(n)**, память **O(1)**.

## Задача 4. Сумма прямоугольника в матрице

**Условие.** Дана матрица чисел. Много запросов «сумма прямоугольника с углами (r1, c1) и (r2, c2)».

### Ход мысли

Двумерное обобщение. `P[i][j]` — сумма прямоугольника от левого верхнего угла матрицы до клетки (i−1, j−1). Массив снова на единицу больше по каждой оси.

Формула суммы прямоугольника использует **включение-исключение**: берём большой прямоугольник, вычитаем полосу сверху и полосу слева, затем возвращаем обратно их пересечение — оно вычлось дважды.

```
P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1]
   всё до        минус          минус         плюс
 правого-низа   верх. полоса  лев. полоса   пересечение
```

### Решение

```js
class NumMatrix {
  /**
   * @param {number[][]} matrix — прямоугольная матрица чисел
   */
  constructor(matrix) {
    const rows = matrix.length;
    const cols = rows > 0 ? matrix[0].length : 0;

    // Матрица префиксов (rows+1) × (cols+1), нулевая строка и столбец — рамка нулей.
    // Array.from с функцией создаёт КАЖДУЮ строку отдельно.
    // new Array(n).fill(new Array(...)) создал бы одну общую строку — классическая ошибка
    this.prefix = Array.from({ length: rows + 1 }, () =>
      new Array(cols + 1).fill(0)
    );

    for (let i = 0; i < rows; i++) {
      for (let j = 0; j < cols; j++) {
        this.prefix[i + 1][j + 1] =
          matrix[i][j]
          + this.prefix[i][j + 1]      // прямоугольник выше
          + this.prefix[i + 1][j]      // прямоугольник левее
          - this.prefix[i][j];         // их пересечение учлось дважды — вычитаем
      }
    }
  }

  /**
   * Сумма прямоугольника с углами (row1, col1) и (row2, col2) включительно.
   */
  sumRegion(row1, col1, row2, col2) {
    return this.prefix[row2 + 1][col2 + 1]
         - this.prefix[row1][col2 + 1]
         - this.prefix[row2 + 1][col1]
         + this.prefix[row1][col1];
  }
}
```

### Разбор

- **`Array.from({ length: n }, () => ...)`** — создание матрицы. Объект `{ length: n }` — «массивоподобный»: `Array.from` понимает его как источник длины n. Вторая функция вызывается для каждой строки заново, поэтому строки независимы.
- **Включение-исключение** — принцип подсчёта, при котором пересечения, учтённые дважды, вычитаются один раз. Здесь встречается и при построении, и при запросе.

### Сложность

Построение **O(rows · cols)**, каждый запрос **O(1)**, память **O(rows · cols)**.

## Разностный массив: обратная задача

Префиксные суммы отвечают на запросы сумм к неизменяемому массиву. Обратная ситуация: много операций «прибавить `val` ко всем элементам отрезка `[l, r]`», а результат нужен один раз в конце.

**Разностный массив (difference array)** `D` устроен так: `D[i] = nums[i] - nums[i-1]`. Тогда прибавление `val` на отрезке `[l, r]` — это всего два изменения: `D[l] += val` и `D[r+1] -= val`. А исходный массив восстанавливается префиксными суммами `D`.

```js
/**
 * Применяет операции «прибавить val на отрезке» к массиву нулей.
 * @param {number} n — длина результирующего массива
 * @param {number[][]} updates — массив операций [start, end, val], границы включительные
 * @returns {number[]} итоговый массив
 */
function applyRangeUpdates(n, updates) {
  // Длина n+1, чтобы безопасно писать в diff[end + 1] при end === n - 1
  const diff = new Array(n + 1).fill(0);

  for (const [start, end, val] of updates) {
    diff[start] += val;      // с этой позиции прибавка началась
    diff[end + 1] -= val;    // с этой позиции она закончилась
  }

  // Восстанавливаем массив префиксными суммами разностного массива
  const result = new Array(n).fill(0);
  let running = 0;
  for (let i = 0; i < n; i++) {
    running += diff[i];
    result[i] = running;
  }

  return result;
}

applyRangeUpdates(5, [[1, 3, 2], [2, 4, 3]]);  // [0, 2, 5, 5, 3]
```

**Разбор.** `for (const [start, end, val] of updates)` — деструктуризация прямо в заголовке цикла: каждый элемент `updates` — массив из трёх чисел, который сразу раскладывается в три переменные.

Сложность: **O(n + q)** вместо наивного O(n · q), где q — число операций.

## Типичные ошибки

1. **Путаница в границах.** Запомните: сумма `[l..r]` = `P[r+1] - P[l]`. Если результат «съезжает» на один элемент — почти наверняка дело здесь.
2. **Не заведён нулевой префикс.** `Map([[0, 1]])` в задаче 2 и `P[0] = 0` в построении — без них теряются подмассивы от начала.
3. **Запись в `Map` до подсчёта** — даёт лишние совпадения при `k = 0`.
4. **Применение скользящего окна при отрицательных числах.** Признак того, что нужны префиксные суммы.
5. **Переполнение точности.** При больших значениях и длинном массиве сумма может превысить `Number.MAX_SAFE_INTEGER` (2⁵³−1). Стоит проговорить вслух.
6. **`fill` со ссылочным значением** при построении двумерных префиксов.

## Чеклист

- Много запросов суммы к неизменяемому массиву → префиксные суммы
- «Сколько подмассивов с суммой k» → префиксные суммы + `Map` счётчиков
- Есть отрицательные числа, речь про сумму подотрезка → префиксные суммы, не окно
- Прямоугольники в матрице → двумерные префиксы + включение-исключение
- Много операций «прибавить на отрезке», результат нужен в конце → разностный массив

## Задачи для тренировки

1. **Найти опорный индекс** (решена выше — напишите заново с нуля).
2. **Подмассив с суммой, делящейся на k** — используйте остатки как ключи `Map`.
3. **Максимальная длина подмассива с суммой k.**
4. **Сравнять единицы и нули** — самый длинный подмассив с равным числом нулей и единиц (замените нули на −1 и ищите нулевую сумму).
5. **Произведение всех элементов кроме себя** — та же идея префиксов и суффиксов, но для произведения и без деления.
