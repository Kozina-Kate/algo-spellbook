Пара индексов, которые двигаются по данным по определённому правилу. Убирает вложенный цикл и почти всегда даёт O(1) по дополнительной памяти.

**Маршрут главы:** перебираем пары простым способом → замечаем лишний вложенный цикл → доказываем, какую часть поиска можно отбросить → двигаем два индекса → сравниваем O(n²) и O(n). Полная схема — в памятке [«Как работать с алгоритмической главой»](../kak-rabotat-s-algoritmicheskoy-glavoy/).
:::

## Что это

**Два указателя (two pointers)** — техника, при которой по массиву или строке одновременно двигаются два индекса. Вместо перебора всех пар за O(n²) мы делаем один проход за O(n), потому что каждый указатель движется только в одну сторону и суммарно проходит не больше n шагов.

Слово «указатель» здесь не значит указатель на память, как в C. Это обычная числовая переменная-индекс.

## Три схемы

### Схема 1. Навстречу друг другу (opposite ends)

Один указатель в начале, другой в конце, движутся навстречу до встречи.

```
[ 1,  3,  5,  7,  9 ]
  ↑               ↑
 left           right
```

Применяется, когда массив **отсортирован** или когда нужно сравнивать симметричные позиции (палиндромы).

```js
let left = 0;
let right = arr.length - 1;
while (left < right) {
  // принимаем решение и двигаем один из указателей
  left++;   // или right--
}
```

### Схема 2. В одну сторону, с разной скоростью (fast & slow)

Оба идут слева направо, но быстрый убегает вперёд, а медленный отстаёт по своему условию.

Применяется для удаления дубликатов на месте, фильтрации на месте, поиска цикла в связном списке.

```js
let slow = 0;
for (let fast = 0; fast < arr.length; fast++) {
  if (/* элемент нужно оставить */) {
    arr[slow] = arr[fast];
    slow++;
  }
}
// slow — длина «очищенной» части
```

### Схема 3. По двум разным массивам

Указатель в каждом массиве, двигается тот, чей элемент меньше. Так сливают отсортированные последовательности.

```js
let i = 0, j = 0;
while (i < a.length && j < b.length) {
  if (a[i] < b[j]) i++;
  else j++;
}
```

## Когда применять

Признаки в условии:

- массив **отсортирован** (или его можно отсортировать), и нужна пара/тройка с заданным свойством
- «палиндром», «симметрия», «с обоих концов»
- «удалить/переместить элементы **на месте**, за O(1) памяти»
- «слить два отсортированных массива»
- «найти цикл в списке»

:::tip
Если массив отсортирован — почти всегда работает либо два указателя, либо [бинарный поиск](../binarnyj-poisk/). Отсортированность в условии никогда не бывает случайной.

:::
## Задача 1. Сумма двух в отсортированном массиве

**Условие.** Дан массив, отсортированный по возрастанию, и число `target`. Найти два элемента с суммой `target`. Разрешено O(1) дополнительной памяти.

Пример: `[2, 7, 11, 15]`, `target = 9` → индексы `[0, 1]`.

### Ход мысли

Через `Map` эта задача решается за O(n) времени и O(n) памяти ([Хеш-таблицы](../hesh-tablicy/)). Но здесь запрещена дополнительная память — значит, нужно использовать отсортированность.

Поставим указатели на концы. Текущая сумма — `arr[left] + arr[right]`.

- Сумма **больше** target → нужно уменьшить. Все элементы справа от `right` ещё больше, значит уменьшить можно только сдвинув `right` влево.
- Сумма **меньше** target → нужно увеличить → двигаем `left` вправо.
- Сумма **равна** → нашли.

**Почему мы ничего не теряем.** Когда мы сдвигаем `right` влево, мы отбрасываем все пары вида `(x, arr[right])` для всех `x` между `left` и `right`. Но любая такая пара имеет сумму **не меньше** `arr[left] + arr[right]`, которая уже больше target. Значит, ни одна из них не подходит, и отбросить их безопасно. Это и есть **инвариант** алгоритма — обоснование, которое стоит проговорить вслух.

### Решение

```js
/**
 * Ищет пару с заданной суммой в отсортированном массиве.
 * @param {number[]} numbers — массив, отсортированный по возрастанию
 * @param {number} target
 * @returns {number[]} пара индексов или пустой массив
 */
function twoSumSorted(numbers, target) {
  let left = 0;                      // указатель на начало
  let right = numbers.length - 1;    // указатель на конец

  // строго <, а не <=: элемент не должен образовывать пару сам с собой
  while (left < right) {
    const sum = numbers[left] + numbers[right];

    if (sum === target) {
      return [left, right];
    } else if (sum < target) {
      left++;    // нужна сумма побольше — сдвигаем левый вправо
    } else {
      right--;   // нужна сумма поменьше — сдвигаем правый влево
    }
  }

  return [];
}
```

### Разбор конструкций

- **`numbers.length - 1`** — индекс последнего элемента. Забыть `-1` — самая частая ошибка, приводящая к `undefined`.
- **`while (left < right)`** — цикл работает, пока указатели не встретились. Каждая итерация двигает ровно один указатель, значит итераций не больше n.
- **`left++` / `right--`** — инкремент и декремент на единицу.

### Сложность

Время **O(n)** — указатели суммарно проходят массив один раз. Память **O(1)** — только две переменные.

## Задача 2. Проверка палиндрома

**Условие.** Строка — палиндром, если читается одинаково слева направо и справа налево, при этом учитываются только буквы и цифры, регистр игнорируется.

Пример: `'A man, a plan, a canal: Panama'` → `true`.

### Ход мысли

Можно очистить строку, развернуть и сравнить — но это O(n) дополнительной памяти. С двумя указателями обойдёмся O(1): идём с концов навстречу, пропуская всё, что не буква и не цифра.

### Решение

```js
/**
 * Проверяет, является ли строка палиндромом
 * (с учётом только букв и цифр, без учёта регистра).
 * @param {string} s
 * @returns {boolean}
 */
function isPalindrome(s) {
  let left = 0;
  let right = s.length - 1;

  while (left < right) {
    // Пропускаем слева всё, что не буква и не цифра.
    // Проверка left < right внутри обязательна: строка может состоять
    // целиком из знаков препинания, и без неё указатель убежит за границу
    while (left < right && !isAlphanumeric(s[left])) {
      left++;
    }
    while (left < right && !isAlphanumeric(s[right])) {
      right--;
    }

    // Сравниваем, приведя к одному регистру
    if (s[left].toLowerCase() !== s[right].toLowerCase()) {
      return false;
    }

    left++;
    right--;
  }

  return true;   // дошли до середины, расхождений нет
}

/**
 * Буква или цифра? Вспомогательная функция.
 * @param {string} ch — ровно один символ
 * @returns {boolean}
 */
function isAlphanumeric(ch) {
  // Регулярное выражение: ^ начало, $ конец, [a-z0-9] один символ
  // из диапазона, i — без учёта регистра.
  // test() возвращает true, если строка подходит под шаблон
  return /^[a-z0-9]$/i.test(ch);
}
```

### Разбор функций

- **`String.prototype.toLowerCase()`** — новая строка в нижнем регистре. Строки неизменяемы, исходная не меняется.
- **`RegExp.prototype.test(str)`** — проверяет соответствие шаблону, возвращает `true`/`false`.
- **`/^[a-z0-9]$/i`** — литерал регулярного выражения. `^` и `$` фиксируют начало и конец, `[a-z0-9]` — один символ из набора, флаг `i` — регистронезависимо.
- **Вложенный `while` внутри внешнего `while`** — это **не** O(n²): каждый указатель за всё время выполнения движется только в одну сторону, суммарно не больше n шагов.

Альтернатива без регулярок, если интервьюер попросит:

```js
function isAlphanumericNoRegex(ch) {
  const code = ch.charCodeAt(0);
  return (code >= 48 && code <= 57)    // '0'–'9'
      || (code >= 97 && code <= 122)   // 'a'–'z'
      || (code >= 65 && code <= 90);   // 'A'–'Z'
}
```

### Сложность

Время **O(n)**, память **O(1)**.

## Задача 3. Удалить дубликаты из отсортированного массива на месте

**Условие.** В отсортированном массиве оставить каждое значение один раз, изменив массив **на месте**. Вернуть новую длину. Что находится за этой длиной — не важно.

Пример: `[1, 1, 2, 2, 3]` → длина `3`, массив начинается с `[1, 2, 3, ...]`.

### Ход мысли

Схема «быстрый и медленный». `fast` просматривает все элементы. `slow` указывает на позицию, куда нужно записать следующее уникальное значение.

Так как массив отсортирован, все одинаковые значения лежат подряд. Значит, элемент уникален (в смысле «первый в своей группе»), если он отличается от предыдущего записанного.

### Решение

```js
/**
 * Удаляет дубликаты из отсортированного массива на месте.
 * @param {number[]} nums — отсортированный по возрастанию массив
 * @returns {number} длина части массива без дубликатов
 */
function removeDuplicates(nums) {
  // Пустой массив — краевой случай, обязательно проверяем
  if (nums.length === 0) return 0;

  // Первый элемент всегда остаётся, поэтому slow начинается с 1:
  // это позиция, КУДА писать следующий уникальный элемент
  let slow = 1;

  for (let fast = 1; fast < nums.length; fast++) {
    // Сравниваем с последним записанным, то есть с nums[slow - 1]
    if (nums[fast] !== nums[slow - 1]) {
      nums[slow] = nums[fast];
      slow++;
    }
    // Если равны — просто пропускаем, fast едет дальше
  }

  return slow;
}
```

### Разбор

- **`nums[slow - 1]`** — последний записанный уникальный элемент. Сравнение именно с ним, а не с `nums[fast - 1]`: `fast - 1` может указывать на пропущенный дубликат.
- **Ранний выход `if (nums.length === 0)`** — без него `slow = 1` вернулся бы для пустого массива, что неверно.
- **`!==`** — строгое неравенство, без приведения типов. В алгоритмах всегда используйте `===`/`!==`.

### Сложность

Время **O(n)** — один проход. Память **O(1)** — меняем массив на месте.

## Задача 4. Переместить нули в конец

**Условие.** Переместить все нули в конец массива, сохранив относительный порядок ненулевых элементов. На месте.

Пример: `[0, 1, 0, 3, 12]` → `[1, 3, 12, 0, 0]`.

### Решение

```js
/**
 * Перемещает все нули в конец, сохраняя порядок остальных элементов.
 * @param {number[]} nums
 * @returns {number[]} тот же массив (изменённый на месте)
 */
function moveZeroes(nums) {
  let slow = 0;   // позиция для следующего ненулевого элемента

  // Фаза 1: сдвигаем все ненулевые элементы влево, сохраняя порядок
  for (let fast = 0; fast < nums.length; fast++) {
    if (nums[fast] !== 0) {
      nums[slow] = nums[fast];
      slow++;
    }
  }

  // Фаза 2: всё, что осталось с позиции slow до конца, заполняем нулями
  for (let i = slow; i < nums.length; i++) {
    nums[i] = 0;
  }

  return nums;
}
```

Вариант в один проход — через обмен:

```js
function moveZeroesSwap(nums) {
  let slow = 0;
  for (let fast = 0; fast < nums.length; fast++) {
    if (nums[fast] !== 0) {
      // Деструктурирующее присваивание — обмен значениями без временной переменной.
      // Справа создаётся пара [nums[fast], nums[slow]],
      // слева она раскладывается обратно в переменные
      [nums[slow], nums[fast]] = [nums[fast], nums[slow]];
      slow++;
    }
  }
  return nums;
}
```

Оба варианта — **O(n)** по времени, **O(1)** по памяти. Первый делает меньше записей, когда нулей много; второй короче. Назовите оба.

## Задача 5. Контейнер с наибольшим объёмом воды

**Условие.** Дан массив `height`, где `height[i]` — высота вертикальной линии в точке `i`. Выбрать две линии так, чтобы они вместе с осью X образовали контейнер максимального объёма.

Объём пары `(i, j)` = `min(height[i], height[j]) × (j - i)` — ширина умножить на высоту меньшей стенки.

Пример: `[1,8,6,2,5,4,8,3,7]` → `49`.

### Ход мысли

Наивно — перебрать все пары, O(n²).

Ставим указатели на концы: это максимальная возможная **ширина**. Дальше ширина может только уменьшаться, значит, чтобы объём вырос, должна вырасти высота.

Какой указатель двигать? **Тот, у которого стенка ниже.** Обоснование: объём ограничен меньшей стенкой. Если сдвинуть указатель с более высокой стенкой, ширина уменьшится, а высота останется ограничена той же низкой стенкой — объём гарантированно не вырастет. Значит, единственный шанс на улучшение — двигать низкую стенку.

Это рассуждение — ядро задачи. Именно его хочет услышать интервьюер.

### Решение

```js
/**
 * Максимальный объём воды между двумя линиями.
 * @param {number[]} height — высоты линий
 * @returns {number} максимальный объём
 */
function maxArea(height) {
  let left = 0;
  let right = height.length - 1;
  let best = 0;

  while (left < right) {
    // Высота контейнера ограничена МЕНЬШЕЙ из двух стенок
    const h = Math.min(height[left], height[right]);
    const width = right - left;

    // Math.max выбирает большее из двух — обновляем рекорд
    best = Math.max(best, h * width);

    // Двигаем указатель с меньшей высотой — только так высота может вырасти
    if (height[left] < height[right]) {
      left++;
    } else {
      right--;
    }
  }

  return best;
}
```

### Разбор функций

- **`Math.min(a, b)`** — меньшее из чисел.
- **`Math.max(a, b)`** — большее. Идиома `best = Math.max(best, candidate)` — стандартный способ вести текущий максимум.
- **`right - left`** — ширина в единицах индексов.

### Сложность

Время **O(n)**, память **O(1)**.

## Задача 6. Слияние двух отсортированных массивов

**Условие.** Даны два массива, отсортированных по возрастанию. Вернуть один отсортированный массив из всех элементов.

### Решение

```js
/**
 * Сливает два отсортированных массива в один отсортированный.
 * @param {number[]} a — отсортированный массив
 * @param {number[]} b — отсортированный массив
 * @returns {number[]} новый отсортированный массив
 */
function mergeSorted(a, b) {
  const result = [];
  let i = 0;   // указатель по a
  let j = 0;   // указатель по b

  // Пока в обоих массивах есть непросмотренные элементы —
  // берём меньший из текущих
  while (i < a.length && j < b.length) {
    if (a[i] <= b[j]) {
      result.push(a[i]);
      i++;
    } else {
      result.push(b[j]);
      j++;
    }
  }

  // Один из массивов кончился. Остаток второго уже отсортирован
  // и весь больше уже добавленного — дописываем как есть.
  // Ровно один из этих циклов реально что-то сделает
  while (i < a.length) { result.push(a[i]); i++; }
  while (j < b.length) { result.push(b[j]); j++; }

  return result;
}
```

### Разбор

- **`<=` вместо `<`** в сравнении — делает слияние **стабильным**: при равных значениях первым берётся элемент из `a`. Для чисел разницы не видно, но для объектов с ключом сортировки это важно.
- **Два добивающих цикла** — стандартная концовка слияния. Забыть их — частая ошибка: часть элементов просто потеряется.

### Сложность

Время **O(n + m)**, память **O(n + m)** на результат.

Эта функция — сердце сортировки слиянием, см. [Сортировки](../sortirovki-i-intervaly/).

## Задача 7. Сумма трёх (3Sum)

**Условие.** Найти все уникальные тройки элементов с нулевой суммой.

Пример: `[-1, 0, 1, 2, -1, -4]` → `[[-1, -1, 2], [-1, 0, 1]]`.

### Ход мысли

Классический приём: **зафиксировать один элемент и свести задачу к сумме двух**. Отсортируем массив. Для каждого `i` ищем в части справа от него пару с суммой `-nums[i]` — это уже решённая задача 1.

Главная сложность — не выдать дубликаты троек. После сортировки одинаковые значения стоят рядом, поэтому дубликаты пропускаются проверкой «текущий элемент равен предыдущему».

### Решение

```js
/**
 * Все уникальные тройки с нулевой суммой.
 * @param {number[]} nums
 * @returns {number[][]}
 */
function threeSum(nums) {
  // Сортируем — это даёт и работу двух указателей, и удобный пропуск дубликатов.
  // Компаратор (a, b) => a - b обязателен: без него сортировка была бы строковой
  nums.sort((a, b) => a - b);

  const result = [];

  // Фиксируем первый элемент тройки. Идём до length - 2,
  // потому что справа должно остаться минимум два элемента
  for (let i = 0; i < nums.length - 2; i++) {
    // Массив отсортирован: если текущий элемент положительный,
    // все следующие тоже положительные, нулевой суммы уже не будет
    if (nums[i] > 0) break;

    // Пропускаем дубликат первого элемента:
    // тройки с таким значением уже были собраны на предыдущей итерации
    if (i > 0 && nums[i] === nums[i - 1]) continue;

    let left = i + 1;
    let right = nums.length - 1;

    while (left < right) {
      const sum = nums[i] + nums[left] + nums[right];

      if (sum === 0) {
        result.push([nums[i], nums[left], nums[right]]);

        // Пропускаем дубликаты второго и третьего элементов
        while (left < right && nums[left] === nums[left + 1]) left++;
        while (left < right && nums[right] === nums[right - 1]) right--;

        // Сдвигаем оба: с текущей парой значений всё найдено
        left++;
        right--;
      } else if (sum < 0) {
        left++;    // сумма мала — берём элемент побольше
      } else {
        right--;   // сумма велика — берём элемент поменьше
      }
    }
  }

  return result;
}
```

### Разбор

- **`break`** — прекращает цикл полностью. **`continue`** — пропускает текущую итерацию, переходя к следующей.
- **`i > 0 && nums[i] === nums[i - 1]`** — сравнение с **предыдущим**, а не со следующим. Сравнение со следующим пропустило бы первое вхождение и сломало ответ.
- **`nums.length - 2`** — граница внешнего цикла: нужно место под ещё два элемента.

### Сложность

Время **O(n²)**: сортировка O(n log n) плюс внешний цикл n, внутри которого два указателя за O(n). Память — O(1) дополнительно, не считая результата (сортировка на месте).

## Типичные ошибки

1. **`while (left <= right)` вместо `left < right`** там, где элемент не должен образовывать пару с самим собой.
2. **Указатель уезжает за границу** во внутреннем `while` — всегда добавляйте условие `left < right` внутрь.
3. **Забыт добивающий цикл** при слиянии двух массивов.
4. **Забыта сортировка** перед применением схемы «навстречу». Техника опирается на порядок.
5. **Не обработаны дубликаты** в 3Sum — ответ содержит повторы.
6. **`sort()` без компаратора** — числа отсортируются как строки.
7. **Сравнение с `nums[fast - 1]` вместо `nums[slow - 1]`** в схеме fast/slow.

## Чеклист

- Массив отсортирован и ищем пару → указатели навстречу
- Нужна фильтрация/сдвиг на месте за O(1) памяти → fast и slow
- Палиндром, симметрия → навстречу
- Два отсортированных источника → по указателю в каждом
- Тройка/четвёрка с условием → зафиксировать элемент + два указателя внутри
