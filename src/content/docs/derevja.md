Дерево — связный список, у которого больше одной ссылки вперёд. Почти все задачи на деревья решаются одним из четырёх обходов, и главный навык здесь — увидеть, какой именно нужен.

## Термины

**Дерево** — структура из узлов, где каждый узел имеет одного родителя (кроме корня) и сколько угодно детей, а циклов нет.

**Бинарное дерево** — дерево, где у каждого узла не больше двух детей: левый и правый.

- **Корень (root)** — единственный узел без родителя, вход в дерево.
- **Лист (leaf)** — узел без детей.
- **Поддерево** — узел вместе со всеми его потомками. Ключевая идея: **любое поддерево само является деревом**, поэтому рекурсия так естественна для деревьев.
- **Глубина узла** — расстояние от корня до него.
- **Высота дерева** — максимальная глубина. У дерева из одного узла высота 0 (иногда считают 1 — уточняйте).
- **Уровень** — все узлы одной глубины.

**Сбалансированное дерево** — дерево, где высота ≈ log₂(n). **Вырожденное** — дерево, выродившееся в цепочку, высота n.

Почему это важно: сложность почти всех операций зависит от высоты. Для сбалансированного дерева O(log n), для вырожденного O(n).

```js
/**
 * Узел бинарного дерева.
 */
class TreeNode {
  constructor(val = 0, left = null, right = null) {
    this.val = val;
    this.left = left;
    this.right = right;
  }
}

//      1
//     / \
//    2   3
//   / \
//  4   5
const root = new TreeNode(1,
  new TreeNode(2, new TreeNode(4), new TreeNode(5)),
  new TreeNode(3)
);
```

## Обходы дерева

**Обход (traversal)** — систематическое посещение всех узлов. Есть два семейства.

### Обход в глубину (DFS, depth-first search)

Идём максимально глубоко, потом возвращаемся. Три варианта, отличающиеся моментом обработки узла:

- **Прямой (preorder)**: корень → левое → правое
- **Симметричный (inorder)**: левое → корень → правое
- **Обратный (postorder)**: левое → правое → корень

Для дерева выше:

- preorder: `1, 2, 4, 5, 3`
- inorder: `4, 2, 5, 1, 3`
- postorder: `4, 5, 2, 3, 1`

:::tip
**Как запомнить и как выбрать.** Название говорит, где обрабатывается **корень** относительно детей.

- **preorder** — когда нужно обработать узел **до** детей: копирование дерева, сериализация, построение путей сверху вниз.
- **inorder** — для **бинарного дерева поиска** даёт значения в отсортированном порядке. Это его главное применение.
- **postorder** — когда для обработки узла нужны **результаты от детей**: подсчёт высоты, суммы поддерева, удаление дерева.

Вопрос «какой обход брать?» сводится к вопросу «нужны ли мне ответы детей, чтобы обработать узел?». Нужны — postorder.

:::
```js
/**
 * Прямой обход (корень → левое → правое).
 * @param {TreeNode|null} root
 * @returns {number[]} значения в порядке обхода
 */
function preorder(root) {
  const result = [];

  function visit(node) {
    if (node === null) return;   // база рекурсии: пустое поддерево

    result.push(node.val);       // обрабатываем КОРЕНЬ
    visit(node.left);            // затем левое поддерево
    visit(node.right);           // затем правое
  }

  visit(root);
  return result;
}

/**
 * Симметричный обход (левое → корень → правое).
 */
function inorder(root) {
  const result = [];

  function visit(node) {
    if (node === null) return;
    visit(node.left);
    result.push(node.val);
    visit(node.right);
  }

  visit(root);
  return result;
}

/**
 * Обратный обход (левое → правое → корень).
 */
function postorder(root) {
  const result = [];

  function visit(node) {
    if (node === null) return;
    visit(node.left);
    visit(node.right);
    result.push(node.val);
  }

  visit(root);
  return result;
}
```

### Разбор структуры

- **Вложенная функция `visit`** видит `result` через замыкание — не нужно передавать аккумулятор параметром и не нужно склеивать массивы.
- **`if (node === null) return`** — база рекурсии. Без неё будет обращение к `null.left` и падение.
- **Три функции отличаются одной строкой** — позицией `result.push`. Это стоит подчеркнуть вслух: демонстрирует понимание, а не заучивание.

**Сложность.** Время **O(n)** — каждый узел посещается один раз. Память **O(h)** на стек рекурсии, где h — высота; для сбалансированного дерева O(log n), для вырожденного O(n).

### Обход в ширину (BFS, breadth-first search)

Посещаем узлы по уровням: сначала все на глубине 0, затем все на глубине 1, и так далее. Реализуется **очередью**.

```js
/**
 * Обход по уровням. Возвращает массив уровней.
 * @param {TreeNode|null} root
 * @returns {number[][]} массив, где каждый элемент — значения одного уровня
 */
function levelOrder(root) {
  if (root === null) return [];

  const result = [];
  const queue = [root];   // массив как очередь
  let head = 0;           // указатель головы вместо shift() — см. «Стек и очередь»

  while (head < queue.length) {
    // Фиксируем размер уровня ДО обработки:
    // внутри цикла в очередь добавятся дети, и длина изменится
    const levelSize = queue.length - head;
    const currentLevel = [];

    for (let i = 0; i < levelSize; i++) {
      const node = queue[head];
      head++;

      currentLevel.push(node.val);

      // Дети попадут в очередь и будут обработаны на следующем витке
      if (node.left !== null) queue.push(node.left);
      if (node.right !== null) queue.push(node.right);
    }

    result.push(currentLevel);
  }

  return result;
}
```

### Разбор

- **`levelSize`, зафиксированный до цикла** — ключевая деталь. Именно она позволяет разделить узлы по уровням. Без неё получится плоский список без границ уровней.
- **`head` вместо `shift()`** — `shift()` это O(n), см. [Стек и очередь](../stek-i-ochered/).
- **Очередь, а не стек** — определяет, что обход идёт вширь. Замена очереди на стек превращает BFS в DFS.

**Сложность.** Время **O(n)**, память **O(w)**, где w — максимальная ширина дерева. Для полного дерева это n/2, то есть O(n).

:::note
**Когда BFS, а когда DFS.**

BFS — когда важны уровни или нужен **кратчайший путь** в невзвешенном случае: «минимальная глубина», «правый вид дерева», «узлы на расстоянии k». BFS находит ближайший подходящий узел первым.

DFS — когда нужно исследовать пути целиком: «сумма по пути от корня до листа», «максимальная глубина», «есть ли путь с такой суммой». И DFS короче пишется.

:::
## Задача 1. Максимальная глубина

**Условие.** Найти высоту дерева — число узлов на самом длинном пути от корня до листа.

### Ход мысли

Классический **postorder**: чтобы узнать глубину узла, нужны глубины обоих поддеревьев. Значит, сначала считаем детей, потом узел.

Рекуррентное соотношение: `глубина(узел) = 1 + max(глубина(левый), глубина(правый))`.

### Решение

```js
/**
 * Максимальная глубина бинарного дерева.
 * @param {TreeNode|null} root
 * @returns {number} число узлов на самом длинном пути от корня до листа
 */
function maxDepth(root) {
  // База: пустое дерево имеет глубину 0
  if (root === null) return 0;

  // Рекурсивно получаем глубины поддеревьев
  const leftDepth = maxDepth(root.left);
  const rightDepth = maxDepth(root.right);

  // Текущий узел добавляет единицу к более глубокому из поддеревьев
  return 1 + Math.max(leftDepth, rightDepth);
}
```

Время **O(n)**, память **O(h)**.

Обратите внимание, насколько компактно выражается идея. Это типично для деревьев: правильно поставленная рекурсия делает решение трёхстрочным. Если решение раздувается — скорее всего, выбран не тот обход.

## Задача 2. Симметричное ли дерево

**Условие.** Проверить, является ли дерево зеркальным относительно своего центра.

### Ход мысли

Одного узла для проверки мало — симметрия это свойство **пары** узлов. Поэтому заводим вспомогательную функцию от двух аргументов.

Два поддерева зеркальны, если их корни равны, левое одного зеркально правому другого, и наоборот.

### Решение

```js
/**
 * Симметрично ли дерево относительно центра.
 * @param {TreeNode|null} root
 * @returns {boolean}
 */
function isSymmetric(root) {
  if (root === null) return true;

  /**
   * Зеркальны ли два поддерева.
   * @param {TreeNode|null} a
   * @param {TreeNode|null} b
   * @returns {boolean}
   */
  function isMirror(a, b) {
    // Оба пусты — зеркальны
    if (a === null && b === null) return true;
    // Ровно один пуст — структуры различаются
    if (a === null || b === null) return false;

    return a.val === b.val              // значения совпадают
      && isMirror(a.left, b.right)      // ВНЕШНИЕ стороны
      && isMirror(a.right, b.left);     // ВНУТРЕННИЕ стороны
  }

  return isMirror(root.left, root.right);
}
```

### Разбор

- **Порядок проверок на `null`** обязателен: сначала «оба пусты», затем «один пуст». Обратный порядок дал бы неверный результат.
- **Перекрёстные вызовы** `(a.left, b.right)` и `(a.right, b.left)` — суть зеркальности. Написать `(a.left, b.left)` — значит проверить равенство деревьев, а не симметрию.
- **`&&` с коротким замыканием** — если значения не совпали, рекурсивные вызовы не выполнятся.

Время **O(n)**, память **O(h)**.

## Бинарное дерево поиска

**Бинарное дерево поиска (BST, binary search tree)** — бинарное дерево со свойством: для каждого узла **все** значения в левом поддереве меньше значения узла, **все** в правом — больше.

```
      8
     / \
    3   10
   / \    \
  1   6    14
```

Главное следствие: **inorder-обход BST даёт отсортированную последовательность**. Из этого выводится половина задач на BST.

:::caution
Свойство BST относится ко **всему поддереву**, а не только к непосредственным детям. Частая ошибка — проверять только `node.left.val < node.val`. Такое дерево пройдёт проверку, хотя BST не является:

```
      5
     / \
    1   6
       / \
      3   7      ← 3 < 5, но находится в ПРАВОМ поддереве корня
```

:::
### Задача 3. Проверить, является ли дерево BST

### Ход мысли

Раз свойство глобальное, передаём вниз по рекурсии **допустимый диапазон** значений. Корень может быть любым: диапазон `(−∞, +∞)`. Уходя влево, сужаем верхнюю границу значением узла; уходя вправо — нижнюю.

### Решение

```js
/**
 * Является ли дерево корректным BST.
 * @param {TreeNode|null} root
 * @returns {boolean}
 */
function isValidBST(root) {
  /**
   * @param {TreeNode|null} node
   * @param {number} min — значения должны быть строго больше
   * @param {number} max — значения должны быть строго меньше
   */
  function validate(node, min, max) {
    if (node === null) return true;   // пустое поддерево валидно

    // Строгие неравенства: дубликаты в классическом BST не допускаются.
    // Если по условию допускаются — уточните, куда их класть
    if (node.val <= min || node.val >= max) return false;

    return validate(node.left, min, node.val)    // слева потолок — текущий узел
      && validate(node.right, node.val, max);    // справа пол — текущий узел
  }

  return validate(root, -Infinity, Infinity);
}
```

### Альтернатива через inorder

```js
function isValidBSTInorder(root) {
  let prev = -Infinity;
  let valid = true;

  function visit(node) {
    if (node === null || !valid) return;

    visit(node.left);

    // В корректном BST inorder даёт строго возрастающую последовательность
    if (node.val <= prev) {
      valid = false;
      return;
    }
    prev = node.val;

    visit(node.right);
  }

  visit(root);
  return valid;
}
```

Оба решения — O(n) времени, O(h) памяти. Назвать оба и объяснить связь между ними — хороший ответ.

### Задача 4. Поиск и вставка в BST

```js
/**
 * Поиск узла по значению.
 * @param {TreeNode|null} root
 * @param {number} val
 * @returns {TreeNode|null}
 */
function searchBST(root, val) {
  let node = root;

  // Итеративно — память O(1) вместо O(h)
  while (node !== null) {
    if (node.val === val) return node;
    // Свойство BST позволяет на каждом шаге отбросить половину дерева
    node = val < node.val ? node.left : node.right;
  }

  return null;
}

/**
 * Вставка значения в BST.
 * @param {TreeNode|null} root
 * @param {number} val
 * @returns {TreeNode} корень изменённого дерева
 */
function insertBST(root, val) {
  // Дошли до пустого места — здесь и создаём узел
  if (root === null) return new TreeNode(val);

  if (val < root.val) {
    // Результат рекурсивного вызова присваиваем обратно:
    // если поддерево было пустым, так подключится новый узел
    root.left = insertBST(root.left, val);
  } else if (val > root.val) {
    root.right = insertBST(root.right, val);
  }
  // val === root.val — дубликат, ничего не делаем

  return root;
}
```

**Сложность.** Время **O(h)**: O(log n) для сбалансированного дерева, O(n) для вырожденного. Это важная оговорка — именно поэтому в реальных системах используют самобалансирующиеся деревья (AVL, красно-чёрные), которые поддерживают высоту O(log n) автоматически.

### Задача 5. Наименьший общий предок в BST

**Условие.** Найти самый глубокий узел, являющийся предком обоих заданных узлов.

**Наименьший общий предок (LCA, lowest common ancestor)** — узел, от которого пути к двум заданным узлам расходятся.

### Ход мысли

В BST это решается элегантно. Если оба значения меньше текущего узла — оба узла в левом поддереве, идём влево. Оба больше — вправо. Если значения по разные стороны (или одно совпало с текущим) — текущий узел и есть точка расхождения.

### Решение

```js
/**
 * Наименьший общий предок двух узлов в BST.
 * @param {TreeNode} root
 * @param {TreeNode} p
 * @param {TreeNode} q
 * @returns {TreeNode|null}
 */
function lowestCommonAncestorBST(root, p, q) {
  let node = root;

  while (node !== null) {
    if (p.val < node.val && q.val < node.val) {
      node = node.left;      // оба слева
    } else if (p.val > node.val && q.val > node.val) {
      node = node.right;     // оба справа
    } else {
      return node;           // разошлись здесь — это и есть LCA
    }
  }

  return null;
}
```

Время **O(h)**, память **O(1)**.

**Для обычного дерева** (не BST) задача решается иначе — postorder-рекурсией:

```js
/**
 * LCA в произвольном бинарном дереве.
 */
function lowestCommonAncestor(root, p, q) {
  // База: дошли до конца либо нашли один из искомых узлов
  if (root === null || root === p || root === q) return root;

  const left = lowestCommonAncestor(root.left, p, q);
  const right = lowestCommonAncestor(root.right, p, q);

  // Нашлись в разных поддеревьях — текущий узел и есть LCA
  if (left !== null && right !== null) return root;

  // Иначе оба (или ни одного) в одном поддереве — возвращаем то, что нашли
  return left !== null ? left : right;
}
```

Время **O(n)**, память **O(h)**.

## Задача 6. Сумма пути от корня до листа

**Условие.** Есть ли путь от корня до листа с заданной суммой значений?

### Решение

```js
/**
 * Существует ли путь корень→лист с суммой targetSum.
 * @param {TreeNode|null} root
 * @param {number} targetSum
 * @returns {boolean}
 */
function hasPathSum(root, targetSum) {
  if (root === null) return false;

  // Лист — узел без детей. Проверка именно на лист принципиальна:
  // без неё «путь» мог бы закончиться в середине дерева
  if (root.left === null && root.right === null) {
    return root.val === targetSum;
  }

  // Идём вниз с уменьшенным остатком
  const remaining = targetSum - root.val;

  // Достаточно, чтобы путь нашёлся хотя бы в одном поддереве.
  // || с коротким замыканием не вызовет второй обход, если первый успешен
  return hasPathSum(root.left, remaining)
      || hasPathSum(root.right, remaining);
}
```

### Разбор

- **Определение листа** `left === null && right === null` — проверяйте именно так. Проверка `root === null` вместо этого дала бы неверный ответ на дереве-цепочке.
- **Вычитание вместо накопления** — идём вниз с остатком. Эквивалентно накоплению суммы, но короче.
- **Отрицательные значения** узлов не ломают решение, потому что мы не отсекаем ветви досрочно.

Время **O(n)**, память **O(h)**.

## Типичные ошибки

1. **Забыта база рекурсии** `if (node === null) return`.
2. **Проверка BST только по соседям** вместо диапазона.
3. **Не зафиксирован `levelSize`** в BFS — уровни слипаются.
4. **`shift()` в BFS** — скрытый O(n²).
5. **Путаница обходов.** Нужен результат детей → postorder. Нужен отсортированный порядок в BST → inorder.
6. **Неверное определение листа.**
7. **Рекурсия на вырожденном дереве** при n порядка 10⁵ — переполнение стека. Скажите об этом вслух.
8. **Присваивание результата рекурсии** забыто при вставке (`root.left = insert(...)`).

## Чеклист

- Нужны ответы от детей → postorder
- Нужен отсортированный порядок из BST → inorder
- Обработка сверху вниз, передача контекста → preorder
- Уровни, кратчайший путь, минимальная глубина → BFS
- Свойство пары узлов (симметрия, равенство) → вспомогательная функция от двух аргументов
- Глобальное свойство поддерева → передавайте диапазон/контекст вниз
- Сложность операций на дереве — O(h), обязательно оговорите разницу между сбалансированным и вырожденным

## Задачи для тренировки

1. **Инвертировать дерево** — поменять местами левых и правых детей везде.
2. **Одинаковы ли два дерева.**
3. **Минимальная глубина** — осторожно с узлом, у которого один ребёнок.
4. **Правый вид дерева** — последний узел каждого уровня (BFS).
5. **Диаметр дерева** — самый длинный путь между любыми двумя узлами.
6. **Сериализация и десериализация дерева.**
7. **Построить BST из отсортированного массива** так, чтобы дерево было сбалансированным.
8. **k-й наименьший элемент в BST** — inorder со счётчиком.
