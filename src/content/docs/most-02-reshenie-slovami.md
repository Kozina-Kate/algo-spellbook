## Берём маленький пример

```text
numbers = [3, 0, 1]
n = 3
```

По условию полный диапазон идёт от `0` до `n` включительно:

```text
0, 1, 2, 3
```

Сравниваем кандидатов с массивом:

| Кандидат | Есть в `[3, 0, 1]` | Действие |
| ---: | --- | --- |
| 0 | да | перейти дальше |
| 1 | да | перейти дальше |
| 2 | нет | вернуть 2 |

Мы только что выполнили алгоритм, ещё не написав ни одной строки JavaScript.

## Выделяем повторяющееся действие

В ручном решении повторяется один вопрос:

> Есть ли очередной кандидат в массиве?

Кандидаты меняются от `0` до `n`. Значит, понадобится цикл по диапазону. Проверка наличия на первом варианте может быть выполнена методом массива `includes`.

Сопоставим слова и конструкции:

| Решение словами | Конструкция JavaScript |
| --- | --- |
| начать с кандидата 0 | `let candidate = 0` |
| проверять до n включительно | `candidate <= numbers.length` |
| перейти к следующему числу | `candidate += 1` |
| есть ли число в массиве | `numbers.includes(candidate)` |
| если числа нет | `if (!...)` |
| отдать найденное число | `return candidate` |

## Пишем псевдокод

**Псевдокод** — точная последовательность действий без требований конкретного языка.

```text
для каждого кандидата от 0 до длины массива включительно:
    если кандидата нет во входном массиве:
        вернуть кандидата
```

Псевдокод полезен, только если достаточно точен. Фраза «найти пропущенное число» повторяет условие и не объясняет, какие действия выполнять.

## Проверяем алгоритм на другом примере

```text
numbers = [0, 1]
n = 2
кандидаты = 0, 1, 2
```

`0` найден, `1` найден, `2` не найден — возвращаем `2`. Это подтверждает, что цикл должен включать правую границу `n`.

Если написать условие `candidate < numbers.length`, значение `2` никогда не будет проверено. Так ручной пример обнаруживает будущую ошибку на единицу.

## Состояние алгоритма

**Состояние** — значения, которые могут быть разными на разных шагах.

В нашем первом алгоритме состояние минимально:

- входной массив `numbers` не меняется;
- `candidate` увеличивается после каждой проверки;
- функция завершается, как только найдено отсутствующее число.

Отдельная переменная `answer` не нужна: найденного кандидата можно сразу вернуть.

## Предскажите шаги

Для массива `[2, 3, 0]` заполните таблицу до момента возврата.

| Кандидат | Есть в массиве | Что дальше |
| ---: | --- | --- |
| 0 | ? | ? |
| 1 | ? | ? |
| 2 | ? | ? |
| 3 | ? | ? |

<details>
<summary>Ответ</summary>

`0` есть — продолжаем. `1` нет — возвращаем `1`. До кандидатов `2` и `3` алгоритм не дойдёт, потому что `return` завершит функцию.

</details>

## Самостоятельная практика

Для входа `[4, 2, 1, 0]` выполните четыре действия:

1. выпишите полный диапазон;
2. составьте таблицу кандидатов;
3. отметьте момент возврата;
4. перепишите алгоритм тремя строками псевдокода.

<details>
<summary>Решение</summary>

Полный диапазон: `0, 1, 2, 3, 4`. Первые три кандидата найдутся в массиве, `3` отсутствует, поэтому функция должна вернуть `3`. Псевдокод остаётся тем же: перебрать кандидатов, проверить наличие, вернуть первый отсутствующий.

</details>

## Типичные ошибки

- описать цель вместо последовательности действий;
- сразу использовать термин «хеш-таблица», не имея простого решения;
- забыть кандидата `n` на правой границе;
- добавить переменные, которые не отражают состояние алгоритма;
- проверять только пример, где пропущено число в середине.
