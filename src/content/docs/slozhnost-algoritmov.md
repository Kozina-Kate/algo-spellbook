## Зачем это нужно

Для алгоритма недостаточно сказать «работает быстро». Нужна сопоставимая оценка вида «O(n log n) по времени, O(n) по памяти».

Смысл понятия простой. Мы хотим сравнивать алгоритмы, не привязываясь к конкретному компьютеру. Замерять в секундах бесполезно: на вашем ноутбуке одно, на сервере другое. Поэтому считают **как растёт количество операций при росте размера входа**.

## Термины

**Размер входа (n)** — то, от чего зависит объём работы. Обычно длина массива или строки. Иногда несколько параметров: n строк и m столбцов в матрице.

**Элементарная операция** — действие, которое выполняется за фиксированное время независимо от n: сложение, сравнение, присваивание, чтение элемента массива по индексу. Мы считаем именно их.

**O-нотация (читается «о большое», big-O)** — способ записать скорость роста, отбросив всё несущественное. Формально: `f(n) = O(g(n))`, если начиная с некоторого n значение `f(n)` не превышает `C · g(n)` для какой-то константы C. Неформально: «растёт не быстрее, чем».

Два правила, из которых всё следует:

1. **Константы отбрасываются.** 3n операций и 100n операций — обе O(n). Потому что при удвоении n обе вырастут вдвое.
2. **Остаётся только старшее слагаемое.** n² + 5n + 100 — это O(n²). При больших n слагаемое n² полностью доминирует: при n = 1000 это 1 000 000 против 5100.

:::note
Почему отбрасывать константы — это не жульничество. O-нотация отвечает не на вопрос «сколько секунд», а на вопрос «что будет, если данных станет в 10 раз больше». Алгоритм за 100n при n = 10⁶ отработает; алгоритм за 0.001n² — нет. Константа важна на практике, но выбор алгоритма определяется порядком роста.

:::
**Сложность по времени (time complexity)** — как растёт число операций.

**Сложность по памяти (space complexity)** — как растёт объём **дополнительной** памяти, которую алгоритм заводит сам. Входные данные обычно не считают. Если алгоритм завёл один счётчик — O(1). Если скопировал массив — O(n).

**Худший случай (worst case)** — максимум работы по всем входам данного размера. По умолчанию на собеседовании называют именно его, если не оговорено иное.

**Средний случай (average case)** — усреднение по всем возможным входам. Пример: быстрая сортировка — O(n log n) в среднем, но O(n²) в худшем.

**Амортизированная сложность** — средняя стоимость одной операции в длинной последовательности операций. Пример ниже.

## Классы сложности — от быстрых к медленным

Ниже — сколько примерно операций для разных n. Это те цифры, которые стоит держать в голове.

| **Класс** | **Название** | **n = 10** | **n = 1000** | **n = 10⁶** |
| --- | --- | --- | --- | --- |
| O(1) | константная | 1 | 1 | 1 |
| O(log n) | логарифмическая | 3 | 10 | 20 |
| O(n) | линейная | 10 | 1 000 | 1 000 000 |
| O(n log n) | линейно-логарифмическая | 33 | 10 000 | 20 000 000 |
| O(n²) | квадратичная | 100 | 1 000 000 | 10¹² (не пройдёт) |
| O(2ⁿ) | экспоненциальная | 1024 | астрономия | — |
| O(n!) | факториальная | 3.6 млн | — | — |
### O(1) — константная

Время не зависит от размера входа.

```js
// Получить первый элемент массива.
// Движок знает адрес начала массива и смещение — читает напрямую,
// независимо от того, 10 элементов в массиве или 10 миллионов.
function getFirst(arr) {
  return arr[0];
}
```

### O(log n) — логарифмическая

На каждом шаге объём работы уменьшается в фиксированное число раз (обычно вдвое). Классика — бинарный поиск.

Почему log: чтобы из n прийти к 1, деля пополам, нужно log₂(n) шагов. Для миллиона это всего 20 шагов.

```js
// Сколько раз можно поделить n пополам, пока не дойдём до 1.
function countHalvings(n) {
  let steps = 0;
  while (n > 1) {   // тело цикла выполнится log2(n) раз
    n = Math.floor(n / 2);
    steps++;
  }
  return steps;
}
```

`Math.floor(x)` — округление вниз до целого: `Math.floor(2.7)` → `2`. Нужно, потому что в JS деление всегда даёт дробное число, а нам нужно целое количество элементов.

### O(n) — линейная

Один проход по данным. Удвоили вход — удвоилось время.

```js
// Сумма всех элементов массива: ровно n итераций.
function sum(arr) {
  let total = 0;
  for (let i = 0; i < arr.length; i++) {
    total += arr[i];
  }
  return total;
}
```

:::caution
Два последовательных цикла по n — это O(n) + O(n) = O(2n) = **O(n)**, а не O(n²). Квадрат возникает только от **вложенности**, когда внутренний цикл выполняется целиком на каждой итерации внешнего.

:::
### O(n log n) — линейно-логарифмическая

Типично для сортировок. Практически это «почти линейно»: для n = 10⁶ множитель log n равен всего 20.

```js
// sort в V8 — алгоритм TimSort, его сложность O(n log n).
function sortNumbers(arr) {
  return [...arr].sort((a, b) => a - b);
}
```

`[...arr]` — спред-оператор, создаёт поверхностную копию массива. Нужен, потому что `sort` меняет массив **на месте**, а портить входные данные без разрешения — плохая практика. Про компаратор `(a, b) => a - b` — ниже в разделе про ловушки.

### O(n²) — квадратичная

Вложенный цикл: для каждого элемента проходим по всем остальным.

```js
// Найти, есть ли в массиве два одинаковых элемента — наивно.
function hasDuplicateNaive(arr) {
  for (let i = 0; i < arr.length; i++) {        // n итераций
    for (let j = i + 1; j < arr.length; j++) {  // до n итераций внутри каждой
      if (arr[i] === arr[j]) return true;
    }
  }
  return false;
}
// Всего примерно n·(n-1)/2 сравнений = O(n²)
```

Ту же задачу можно решить за O(n) через `Set` — см. [Хеш-таблицы](../hesh-tablicy/). Именно этот переход от O(n²) к O(n) и есть суть половины задач на собеседованиях.

### O(2ⁿ) — экспоненциальная

Каждый новый элемент удваивает объём работы. Типично для полного перебора всех подмножеств и для наивной рекурсии без мемоизации.

```js
// Наивные числа Фибоначчи: каждый вызов порождает два новых.
function fib(n) {
  if (n <= 1) return n;
  return fib(n - 1) + fib(n - 2);
}
// fib(40) — около миллиарда вызовов, заметная пауза
// fib(50) — не дождётесь
```

Как это чинится — на странице [Динамическое программирование](../dinamicheskoe-programmirovanie/).

### O(n!) — факториальная

Перебор всех перестановок. Реалистично только для n ≤ 10.

## Как считать сложность: практические правила

**Правило 1. Последовательные блоки складываются, берётся максимум.**

```js
function f(arr) {
  arr.forEach(x => console.log(x));   // O(n)
  arr.sort((a, b) => a - b);          // O(n log n)
  return arr[0];                      // O(1)
}
// O(n) + O(n log n) + O(1) = O(n log n)
```

**Правило 2. Вложенные циклы умножаются.**

```js
// Матрица n×m: внешний цикл n раз, внутренний m раз
for (let i = 0; i < n; i++) {
  for (let j = 0; j < m; j++) { /* ... */ }
}
// O(n · m). Если матрица квадратная (m = n) — O(n²)
```

**Правило 3. Скрытые циклы внутри методов тоже считаются.** Это самая частая ошибка.

```js
// Выглядит как один цикл — на деле O(n²)
function countUnique(arr) {
  const seen = [];
  for (const x of arr) {          // n итераций
    if (!seen.includes(x)) {      // includes — это O(n) внутри!
      seen.push(x);
    }
  }
  return seen.length;
}
// O(n) × O(n) = O(n²)

// Правильно — O(n):
function countUniqueFast(arr) {
  return new Set(arr).size;       // Set.add и проверка — O(1) в среднем
}
```

`Array.prototype.includes(x)` — проверяет наличие элемента, сравнивая по очереди с каждым: O(n).
`new Set(arr)` — создаёт множество уникальных значений, проверка и добавление — O(1) в среднем.
`.size` — количество элементов множества (свойство, не метод, скобки не нужны).

**Правило 4. Рекурсия: количество вызовов × работа в одном вызове.**

```js
// Обход дерева: каждый узел посещается ровно один раз,
// в каждом делается O(1) работы → O(n), где n — число узлов
function countNodes(node) {
  if (node === null) return 0;
  return 1 + countNodes(node.left) + countNodes(node.right);
}
```

## Сложность по памяти

Считаем **дополнительную** память — ту, что алгоритм заводит сверх входа.

```js
// O(1) по памяти: сколько бы ни было элементов, переменных три
function maxValue(arr) {
  let max = -Infinity;
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] > max) max = arr[i];
  }
  return max;
}

// O(n) по памяти: новый массив пропорционален входу
function doubled(arr) {
  return arr.map(x => x * 2);
}
```

`-Infinity` — специальное числовое значение, меньшее любого числа. Удобная стартовая величина для поиска максимума: любой реальный элемент её перебьёт. Симметрично `Infinity` для поиска минимума.

`Array.prototype.map(fn)` — создаёт **новый** массив той же длины, применив `fn` к каждому элементу. Исходный не меняется.

:::caution
**Рекурсия тратит память, даже если не создаёт массивов.** Каждый незавершённый вызов лежит в стеке вызовов. Рекурсия глубиной n — это O(n) по памяти. Для сбалансированного дерева глубина O(log n), для вырожденного (цепочки) — O(n).

:::
## Амортизированная сложность на примере push

Массив в JS — динамический: под ним выделен блок памяти определённого размера. Когда место кончается, движок выделяет блок побольше (обычно вдвое) и копирует туда всё содержимое — это O(n).

Получается, что `push` иногда стоит O(n). Но такое случается редко: после удвоения ёмкости следующие n операций `push` будут дешёвыми. Если посчитать суммарную стоимость n операций `push` и поделить на n, получится константа. Это и называют **амортизированным O(1)**.

На собеседовании достаточно сказать: «push — амортизированное O(1)».

## Типичные ловушки в JS

**`sort()` без компаратора сортирует как строки.**

```js
[10, 9, 100, 1].sort();              // [1, 10, 100, 9] — строковое сравнение!
[10, 9, 100, 1].sort((a, b) => a - b); // [1, 9, 10, 100] — правильно
```

Компаратор — функция от двух элементов. Возвращает отрицательное число, если `a` должен стоять раньше `b`; положительное — если позже; ноль — если порядок не важен. `a - b` даёт возрастание, `b - a` — убывание.

**`shift()` и `unshift()` — это O(n).** Удаление из начала сдвигает все остальные элементы. Цикл с `shift()` внутри — скрытый O(n²).

```js
// Плохо: O(n²)
while (queue.length) {
  const item = queue.shift();
}

// Хорошо: O(n) — вместо удаления двигаем указатель
let head = 0;
while (head < queue.length) {
  const item = queue[head++];
}
```

`head++` — постфиксный инкремент: возвращает текущее значение, потом увеличивает. То есть берём `queue[head]`, а `head` становится больше на 1.

**Конкатенация строк в цикле.** Строки в JS неизменяемы, `s += x` создаёт новую строку. В худшем случае цикл даёт O(n²). Правильно — собирать в массив и склеить:

```js
const parts = [];
for (const x of items) parts.push(String(x));
const result = parts.join('');
```

`Array.prototype.join(sep)` — склеивает элементы массива в строку через разделитель `sep`. `join('')` — без разделителя.

**Спред и деструктуризация внутри цикла.** `[...arr]` — это O(n). Внутри цикла по n элементам получается O(n²).

## Чеклист: как назвать сложность своего кода

1. Найдите самый глубоко вложенный цикл — сколько итераций он даёт суммарно?
2. Проверьте каждый вызов метода: нет ли внутри скрытого прохода? (`includes`, `indexOf`, `slice`, `splice`, спред, `join`, `Object.keys`)
3. Если есть рекурсия — сколько всего вызовов и сколько работы в каждом?
4. Отдельно посчитайте память: какие структуры заводятся и какого они размера? Не забудьте про глубину рекурсии.
5. Сформулируйте вслух: «O(...) по времени, O(...) по памяти, потому что ...» — обязательно с «потому что».

## Задачи для тренировки

Определите сложность по времени и памяти, не подглядывая:

```js
// 1
function a(arr) {
  let s = 0;
  for (const x of arr) s += x;
  for (const x of arr) s -= x;
  return s;
}

// 2
function b(arr) {
  const res = [];
  for (let i = 0; i < arr.length; i++) {
    res.push(arr.slice(0, i));
  }
  return res;
}

// 3
function c(n) {
  let i = 1;
  while (i < n) i *= 2;
  return i;
}

// 4
function d(matrix) {
  for (const row of matrix) {
    row.sort((x, y) => x - y);
  }
  return matrix;
}
```

<details>
<summary>Ответы</summary>

**1.** Время O(n) — два последовательных цикла, складываются. Память O(1).

**2.** Время O(n²) — `slice(0, i)` копирует i элементов, суммарно 0+1+2+...+(n−1) = n(n−1)/2. Память O(n²) — суммарная длина всех сохранённых кусков. `Array.prototype.slice(start, end)` возвращает новый массив — копию участка от `start` включительно до `end` не включая.

**3.** Время O(log n) — `i` растёт как степень двойки, цикл выполнится log₂(n) раз. Память O(1).

**4.** Пусть матрица n строк по m элементов. Время O(n · m log m). Память O(log m) на стек сортировки (или O(m), в зависимости от реализации) — как дополнительная, не считая входа.


</details>
